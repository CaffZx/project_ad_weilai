# 定时分析机制说明

## 目的

本篇说明当前批量定时 Campaign 分析脚本的输入、API 调用、并发、重试、状态文件和退出码。

## 当前代码真源

- `batch_via_api.py`（位于 `AD_assistant_agent-v3.2` 仓库根目录）
- `batch_monitor.sh`
- `batch_night_monitor.sh`
- Campaign API：`ad-direction-agent/app/api/campaign.py`
- ERP 配置表读取：`t_advert_agent_decision_config`

## 脚本定位

`batch_via_api.py` 是通过 HTTP 调用本地服务的批量分析脚本。

它不直接调用内部 Python workflow，而是请求：

```text
POST http://127.0.0.1:8010/api/v1/agent/ad-direction/campaign/viewmodel
```

脚本位于仓库根目录，不在 `ad-direction-agent/scripts/` 下。部署或排障时不要按旧路径查找。

## ASIN 来源

脚本从 ERP 生产库 `t_advert_agent_decision_config` 读取需要分析的 ASIN 列表。

这意味着：

- 定时任务 ASIN 列表不来自 State 库。
- 配置表的可用性会影响批量任务启动。
- 连接信息在脚本中有专门配置，部署时要核对环境。

配置读取链路：

| 字段 | 来源 | 后端消费 |
| --- | --- | --- |
| ASIN 列表 | `t_advert_agent_decision_config.parent_asin` | batch 脚本循环 |
| 1-4 层策略配置 | `cfg_source=config` 触发后端读取 decision_config | `campaign.py:309` 附近加载 layer14 |
| `analysis_mode` | batch 请求固定 `SCHEDULED` | ERP decision 标记批次来源 |
| `write_erp` | batch 请求固定 true | `/campaign/viewmodel` 本身也强制落库 |
| `_userId` | batch 请求 `batch-cron` | 审计/操作上下文 |

## 请求体

典型请求体：

```json
{
  "asin": "B0...",
  "days": 7,
  "temp": 0.3,
  "analysis_mode": "SCHEDULED",
  "write_erp": true,
  "_userId": "batch-cron",
  "cfg_source": "config"
}
```

## 并发与重试

默认策略：

- 并发：5
- 重试：1
- 单 ASIN 超时：240 秒
- 重试延迟：30 秒

实际耗时还受 API 内部 Campaign 总超时、MCP 工具超时、LLM 超时和 semaphore 等配置影响。

## 状态文件

脚本会写状态 JSON：

```text
/opt/ad_agent_github_chenv31/logs/YYYYMMDD/batch_status.json
```

状态分类包括：

- `ok`
- `skipped`
- `failed`
- `data_unavailable`

`data_unavailable` 用于区分上游数据不可用和代码异常。

## 退出码

退出策略：

- 真失败存在时返回 1。
- `data_unavailable` 比例过高时返回 2。
- 全部成功或可接受跳过时返回 0。

监控系统应按退出码和状态文件同时判断，不要只看 stdout。

## 监控和自动重试

`batch_monitor.sh` / `batch_night_monitor.sh` 读取当天 `batch_status.json`：

- 如果运行数过少或成功率过低，触发全量重跑。
- 如果只有部分 ASIN 失败，拼出失败 ASIN 列表并调用 `batch_via_api.py --asins ...`。
- 重试日志写入 `batch_retry.log`。

这两个 shell 脚本依赖状态文件格式，不应随意改 `StatusWriter` 输出字段。

## 常见误区

- 批量脚本调用的是 `campaign/viewmodel`，不是 `campaign/analyze`。
- 单 ASIN 超时 240 秒不等于后端所有内部任务都只能跑 240 秒；请求层和内部 wait_for 是不同层级。
- `data_unavailable` 不是脚本崩溃。
- 定时任务写 ERP，因此会影响前端最新批次展示。

## 核心词离线判定任务

`batch_core_keyword.py` / `.sh` 是独立于 Campaign 批量分析的离线判定脚本。

| 项 | 值 |
|---|---|
| API URL | `http://127.0.0.1:8015/api/v1/agent/ad-direction/core-keyword/analyze` |
| ASIN 来源 | 同 Campaign：`t_advert_agent_decision_config`，读取三元组 `(parent_asin, parent_seller_sku, shop_id)` + `site_code` |
| 并发 | 5，单产品 HTTP timeout 420s |
| 调度 | cron 每周日 7:00 |
| 状态文件 | `batch_core_keyword_status_*.json` |

与 Campaign 批量分析的关键差异：
- 读的是**三元组**而非单一 `parent_asin`
- 调的是**独立 8015 端口**（`ad-core-keyword.service`），非 8010
- 7 天一次，非每日运行
