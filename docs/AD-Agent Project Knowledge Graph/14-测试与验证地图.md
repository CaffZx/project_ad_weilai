# 测试与验证地图

## 目的

本篇把现有测试文件映射到项目子系统，帮助开发者和开发 Agent 在改动后选择最小但有效的验证范围。

## 当前代码真源

- 测试目录：`ad-direction-agent/tests`
- 项目配置：`ad-direction-agent/pytest.ini` 或同级测试配置文件
- 业务代码：`ad-direction-agent/app`

## 推荐命令

在 `ad-direction-agent` 目录执行：

```powershell
python -m pytest tests -q
```

按子系统执行：

```powershell
python -m pytest tests/data tests/workflow -q
python -m pytest tests/persistence -q
python -m pytest tests/test_kb_slicing.py -q
python -m pytest tests/test_mcp_date_window.py tests/test_mcp_resolve_context.py -q
```

如果当前环境缺少外部服务，应优先运行不依赖真实 MCP/ERP 的单元测试，并在结果中说明跳过原因。

按风险选择验证：

| 改动类型 | 最小建议验证 |

## 常见误区

- 只跑全量测试失败后不定位子系统，会浪费大量时间。
- 修改 MCP 参数后只跑业务规则测试不够。
- 修改前端 viewmodel 后只跑后端测试不够，还应手动或浏览器验证 UI。
- 外部 MCP/ERP 不可用时，应明确说明验证覆盖缺口。

## 更新检查清单

- 新增测试文件后，同步加入本篇对应子系统。
- 新增关键链路但没有测试时，在对应专题文档中标出验证缺口。
- 修改测试目录结构后，同步更新推荐命令。
- 修改 CI 命令后，同步更新本篇。
