## ASINData

`ASINData` 是前置策略推荐链路的核心输入对象，父 ASIN 粒度。

它聚合：

- 产品基础信息：标题、类目、价格、库存等。
- 销售表现：销量、销售额、转化等。
- 评论与评分：评论数、评分、变化趋势。
- 广告数据：广告花费、订单、ACOS、CTR、CVR 等。
- 关键词：流量词、自然排名、广告关键词、核心词。
- 竞品：直接竞品、关键词竞品。
- 信号与配置：产品阶段、广告目的、策略选择、预算和 ACOS 目标。
- 数据质量：缺失字段、部分失败、趋势窗口。

`ASINData` 不是 Campaign 粒度对象。不要把单个活动、placement、search term 的决策字段塞回 `ASINData`。

字段来源和下游用途：

| 字段族 | 主要来源 | 关键归一化/装配 | 下游 |
| --- | --- | --- | --- |
| listing 基础信息 | `listing_basic_info_v2` | `mcp_adapter.py:310` 到 `:339` | 策略上下文、报告、Campaign overview |
| 库存 | `parent_listing_stock_summary` | `mcp_adapter.py:313`、`:438` | data gate、Campaign P10 placement 护栏、预算判断 |
| 广告汇总 | `ad_product_report` | `mcp_adapter.py:314`、`:353` 到 `:362` | Tactics/Execution/P3 data gate 与推荐 |
| 销售/利润 | `product_sales` | `mcp_adapter.py:328`、`:341` 到 `:365` | target ACOS、预算、Campaign overview |
| 关键词 | `ad_campaign_product_keyword_list` + `keyword_child_asins` | `mcp_adapter.py:246` 到 `:274`、`:374` 到 `:393` | tactics 目的推荐、自然排名、Campaign new |
| 竞品 | `direct_competitors` | `mcp_adapter.py:327`、`:418` 到 `:422` | 竞品诊断和可选新增词源 |
| 数据质量 | MCP 调用结果、异常、缺失字段 | `McpAdapter` / `DataAggregator` 汇总 | data gate、前端提示、`data_unavailable` 区分 |

## 四层工作流对象

`layers.py` 定义前置策略推荐的四层对象：

- Strategy：产品等级、产品阶段、季节阶段。
- Tactics：广告目的、目标关键词策略。
- Diagnosis：诊断 ASIN 当前经营和广告状态。
- Execution：推荐操作方向、执行选项和用户选择。

P3 推荐对象也在这一层附近：

- Target ACOS 推荐
- Budget 推荐
- Unified recommendation

这组对象服务“Campaign 分析之前”的策略配置与推荐，主要消费 `ASINData`。

## CampaignData

`CampaignData` 是 Campaign 分析链路的输入对象，活动粒度。

关键概念：

- `CampaignUnit`：一个活动单元，包含活动基础信息、效果、关键词、placement、search term 等。
- `CampaignPerf`：活动效果指标。
- `CampaignStrategyContext`：把前置策略配置转成 Campaign 分析可用的上下文。
- `campaign_key`：当前模型中以“活动名 × 子 ASIN”作为唯一语义。

`CampaignData` 和 `ASINData` 并列存在。Campaign 分析会借用 ASIN 级策略上下文，但不应该把 Campaign 明细强行归入 `ASINData`。

Campaign 粒度对象关系：

| 对象 | 粒度 | 关键字段 | 产出/消费 |
| --- | --- | --- | --- |
| `CampaignPerf` | campaign/sub ASIN/窗口 | spend、sales、orders、clicks、acos、cvr | CampaignUnit 的效果事实 |
| `CampaignUnit` | 活动单元 | campaign_id/name、match_type、current_bid/budget、perf、keyword、placements、search_terms | LLM batch、护栏、ERP mapper |
| `CampaignData` | 父 ASIN 一次拉取结果 | `campaigns: list[CampaignUnit]`、site/shop/sku、warnings/errors | Campaign 主流程 |
| `CampaignStrategyContext` | 父 ASIN 策略背景 | product stage、ad purposes、target ACOS、execution direction | Prompt 和预算回算 |
| `CampaignAdjustmentItem` | 一张建议卡的业务主项 | action、proposed_bid/budget、placement、negative_keywords、reason | card/pending/viewmodel/执行 |

## CampaignAnalysisResult

Campaign 输出核心对象包括：

- `CampaignAdjustmentItem`：活动级调整建议。
- `NewCampaignCandidate`：候选新建词或新建活动来源。
- `NewCampaignItem`：可落库/展示的新建活动建议。
- `CampaignStrategicOverview`：战略概览。
- `CampaignAnalysisResult`：最终综合结果。
- `CampaignDecision` 与 `CampaignConfirmRequest`：前端确认/拒绝时使用。

`CampaignAnalysisResult.data_unavailable` 很重要：它表示上游数据不可用，不等同于“业务判断无需调整”。

结果字段流向：

| 字段 | 生成位置 | 落库/展示 |
| --- | --- | --- |
| `adjustments` | existing campaign exact/broad 分流、投票、护栏后 | `mappers.py:357` 起生成 MODIFY/KEEP/灰卡等 card 与三类 pending |
| `new_campaigns` | `campaign_new.py` 双轮 LLM + 代码补齐 | `mappers.py:477` 起生成 CREATE card 与 pending |
| `strategic_overview` | `campaign.py:1239` `_run_overview()` | 写入 summary/viewmodel，前端作为总览 |
| `budget_summary` / reallocation | `campaign_budget_summary.py` / `campaign_budget_reallocation.py` | 前端预算区和 portfolio budget 执行入口 |
| `skipped_campaigns` | 预过滤、LLM 漏判、数据不足 | `mappers.py:523` 起生成灰卡或 warnings |
| `data_unavailable` | API / workflow 异常和数据不可用分支 | API/viewmodel 门禁，不应当作正常 no-op |

## 决策批次与快照

ERP 侧把一次分析写成一个 `decision_id` 批次。

批次通常包括：

- 主决策行：父 ASIN、日期窗口、是否最新、快照。
- 前置策略推荐：方向推荐、明细、目的得分、核心关键词等。
- Campaign 分析：summary、card、pending、reason group、special display。
- 执行状态：confirm_status、execute_status、execute_msg。

前端通常不直接消费原始 Python 对象，而是通过 API 读取 ERP 快照或 viewmodel。

## 常见误区

- `campaign_key` 不是数据库主键。它是业务唯一键或前端选择键，需要结合 `decision_id` 和 card/pending ID 理解。
- `CampaignAdjustmentItem.is_core` 当前不应被当成完整稳定规则入口。
- `data_unavailable=true` 不能被前端展示成普通“暂无建议”。
- 前置策略工作流和 Campaign 工作流都可能写 ERP，但它们的输出对象和展示区域不同。

## 更新检查清单

- 修改 `models/asin_data.py` 后，检查前置工作流和缓存文档。
- 修改 `models/layers.py` 后，检查策略工作流、前端和 ERP 映射。
- 修改 `models/campaign.py` 后，检查 Campaign 架构、MCP 调用链、前端 viewmodel 和执行链路。
- 修改 `campaign_key` 语义时，必须检查确认、拒绝、执行、reason group 和前端选择逻辑。
