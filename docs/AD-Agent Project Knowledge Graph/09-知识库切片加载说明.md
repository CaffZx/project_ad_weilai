## 目的

本篇说明项目如何按 preset 加载业务知识库切片。这里的“知识库”是业务规则素材，不是本目录的项目知识图谱。

## 核心机制

`kb_loader.py` 用 preset 描述“某个任务需要哪些知识库文件的哪些章节”。

加载流程：

1. 调用方指定 preset。
2. preset 展开为若干 `fid:sectionlist`。
3. loader 只读取被引用的文件。
4. 按章节切片提取内容。
5. 枚举值通过 `ENUM_MAP` 翻译成业务文本。
6. 缺失章节记录 warning。
7. 拼装成 LLM prompt 可消费文本。

Preset 的粒度原则：

- 一个 preset 对应一个 LLM 任务，不对应一个页面或一个后端模块。
- Campaign exact/broad/new/overview/budget 被拆成不同 preset，是为了减少 token、降低互相干扰。
- synthesis prompt 当前刻意不直接塞入完整 Campaign adjustment KB，避免 26K 级规则重复进入后处理阶段。

## 章节引用格式

典型格式是：

```text
fid:section1,section2,section3
```

其中：

- `fid` 指知识库文件标识。
- section list 指需要加载的章节。
- loader 根据章节标题或内部索引提取内容。

## 与 Prompt 的关系

知识库切片是 prompt 的证据和规则输入。

它不应包含：

- 当前运行时数据。
- MCP 工具返回原始 JSON。
- ERP 表结构。
- 项目架构说明。

这些内容应由代码、数据层或本项目知识图谱提供。

## 缺失章节处理

如果 preset 引用的章节不存在，loader 会记录 warning。

开发时不要忽略 warning。缺失业务规则可能导致 LLM 输出看似正常但依据不完整。

## 失败和降级边界

| 情况 | 行为 | 维护要求 |
| --- | --- | --- |
| preset 名不存在 | `build()` 返回空或记录异常风险 | 调用方应使用固定枚举式 preset，不要由前端传入 |
| 文件不存在 | preload warning | 新增/改名知识库文件后同步 PRESETS |
| 章节不存在 | build warning，缺少该片段 | 修改章节标题/编号后必须跑 `tests/test_kb_slicing.py` |
| enum 未翻译 | prompt 中保留原枚举或语义变弱 | 修改 `layers.py` 枚举后检查 `ENUM_MAP` |
| preset 过大 | LLM token 和延迟上升 | 优先按任务拆分，不要把全量 KB 塞给所有任务 |

## 常见误区

- 不要把本目录的项目知识图谱加入业务知识库切片。
- preset 越大不一定越好；过多无关业务规则会稀释 prompt。
- enum 翻译是 prompt 语义的一部分，修改枚举值时要检查 `ENUM_MAP`。
- 缺失章节 warning 不是纯日志噪音。

## 更新检查清单

- 新增业务知识库文件后，检查是否需要新增 fid。
- 新增 LLM 任务类型后，优先新增或复用 preset。
- 修改章节标题后，运行知识库切片测试。
- 修改 enum 后，检查 `ENUM_MAP` 和所有相关 prompt。
