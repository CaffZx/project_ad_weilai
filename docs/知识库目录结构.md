# 知识库目录结构

> **用途**: 统一管理广告决策知识，既方便人工按业务逻辑维护，也方便机器(RAG)按分类精准检索
> **维护规则**: 新增知识只往对应目录加文件，不改目录结构；修改索引在 `_index.yaml` 里改标签，不改目录名

---

## 一、总览

```
kb/
├── _index.yaml                    # ★ 总索引：每个文件的摘要+标签(机器和人共用入口)
│
├── structured/                    # 结构化参数(字典，代码直接读)
│   ├── strategy_params.yaml       #   标签组合→策略参数(ACOS上限/bid系数/预算系数)
│   ├── formulas.yaml              #   公式定义(bid调整/预算调整/否定词识别)
│   ├── guardrails.yaml            #   安全护栏(哪些操作绝对禁止)
│   └── scenarios.yaml             #   场景定义(8种场景+北极星指标+阈值)
│
├── unstructured/                  # 非结构化知识(经验集，RAG语义检索)
│   │
│   ├── 01-广告目标/                #   广告目的选型与组合
│   ├── 02-产品生命周期/            #   测试期/推进期/收割期/维持期/清货期
│   ├── 03-关键词管理/              #   选词/否定/拓词/排名监控
│   ├── 04-出价与预算/              #   Bid调整/预算分配/ACOS控制
│   ├── 05-广告位策略/              #   TOS/ROS/商品页面 位策略
│   ├── 06-竞品应对/                #   竞品监控/价格战/排名争夺
│   ├── 07-品类知识/                #   按品类：泳装/内衣/运动服...
│   ├── 08-季节性策略/              #   旺季/淡季/节日 特殊策略
│   ├── 09-库存与广告联动/          #   断货预警/清货策略/库存与出价
│   ├── 10-运营SOP/                 #   日常操作规范/检查清单
│   └── 11-历史案例/                #   优质分析案例(机器自动提取+人工精选)
│
└── vector_store/                  # ChromaDB 持久化(机器自动维护，不手动改)
    └── chroma.sqlite3
```

## 三、业务逻辑说明

### 3.1 为什么不按"杂项/通用"分类

如果出现一个文档既涉及出价又涉及竞品，**不建"综合"目录**。判断文档的主要价值落在哪，放在那里。在 `_index.yaml` 里多打几个 tags 就能覆盖次要主题。RAG 是按 tags 检索的，不是按目录检索的。

### 3.2 目录和 tags 的关系

```
目录 → 人工导航用，告诉你"去哪找"
tags → 机器检索用，告诉 ChromaDB"这篇讲的是什么"
```

一篇放在 `03-关键词管理/` 下的文档，可以同时打 `[否定词, 零转化, ACOS]` 三个 tags。当 Analyst 搜 "ACOS过高怎么处理" 时，这篇也能被检索到，虽然它不在 "04-出价与预算" 目录下。

### 3.3 文件命名规范

```
规则: {主题}_{子主题}.md
例子: 否定词策略.md / 拓词方法论.md / ACOS控制策略.md
反例: 文档1.md / 新建文件.md / 最终版_2.md
```

### 3.4 每个 Markdown 文件的 frontmatter

```yaml
---
title: "否定词投放策略"
category: "keyword_management"
tags: [否定词, 零转化, 高花费, 精准否定, 广泛否定]
applicable_stages: [测试期, 推进期, 收割利润期, 维持期]
last_reviewed_by: "张三"
last_reviewed_at: "2026-05-22"
version: 1
---

# 否定词投放策略

正文...
```

机器建索引时直接读 frontmatter，不需要人工再维护 `_index.yaml` 的对应条目（可自动生成）。

## 四、自动生成索引脚本

`_index.yaml` 不需要纯手写。从 Markdown frontmatter 自动生成：

```python
# kb/generate_index.py

def generate_index(unstructured_dir: str) -> dict:
    """遍历所有 .md 文件, 读 frontmatter, 生成 _index.yaml"""
    entries = []
    for md_file in sorted(Path(unstructured_dir).rglob("*.md")):
        fm = read_frontmatter(md_file)
        if fm:
            entries.append({
                "file": str(md_file.relative_to(unstructured_dir)),
                "title": fm.get("title", md_file.stem),
                "category": fm.get("category", "general"),
                "tags": fm.get("tags", []),
                "summary": fm.get("summary", ""),
                "applicable_stages": fm.get("applicable_stages", []),
            })

    with open(Path(unstructured_dir).parent / "_index.yaml", "w") as f:
        yaml.dump({"knowledge_files": entries}, f, allow_unicode=True, sort_keys=False)

    print(f"已生成索引: {len(entries)} 条")

def read_frontmatter(md_path: Path) -> dict | None:
    """读取 Markdown 文件的 YAML frontmatter"""
    text = md_path.read_text(encoding="utf-8")
    if text.startswith("---"):
        end = text.find("---", 3)
        if end > 0:
            return yaml.safe_load(text[3:end])
    return None
```

## 五、维护规范

| 操作 | 步骤 |
|------|------|
| **新增一篇知识** | 1) 在对应目录下新建 `.md` 文件, 填好 frontmatter 2) 运行 `python kb/generate_index.py` 更新 `_index.yaml` 3) 运行 `python kb/build_pipeline.py --incremental` 更新 ChromaDB |
| **修改一篇知识** | 1) 改 `.md` 文件内容 2) 更新 frontmatter 的 `last_reviewed_at` 3) 运行 `python kb/build_pipeline.py --incremental` |
