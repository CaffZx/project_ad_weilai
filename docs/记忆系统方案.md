# 广告决策 Agent 记忆系统 — 方案

> 版本：2026-06-16 · 面向：管理层 / 业务 / 技术
> 一句话：给"每天上班都失忆"的广告 Agent 配一套**经验记忆**，让它带着历史教训做今天的决策。

---

## 一、背景与目标

我们的广告 Agent 每晚为每个产品（父 ASIN）分析 40–70 个广告活动，给出"提价 / 降价 / 调预算 / 淘汰 / 维持"等建议。但它有一个根本短板：**它记不住自己做过什么。**

每晚都是"从零开始"，于是反复犯三类错：

| 问题 | 现象 |
|---|---|
| **重复调整** | 同一个活动连着两晚都被"降价控成本"，过度收缩 |
| **反向打架** | 前天刚提价冲排名，今天又降价控成本，自己跟自己拧 |
| **不会承接** | 上次的调整到底有没有用，它不知道，于是盲目加码或盲目放弃 |
| **目的脱节** | 在策略层定了"转化型"广告目的、为此调了一批活动，却从不回头确认——这段时间转化到底有没有起来，**策略有没有效，没人知道** |

**目标**：建立一套记忆系统，让 Agent 带着历史经验做决策。它的功能大致分两半，**复盘约占一半**：

**前一半——向前看：防错与积累（对应「操作记忆」）**
- 减少重复与反向的无效操作，让决策更连贯；
- 逐步积累成可复用的运营经验资产。

**后一半——向后看：复盘"广告目的"是否达成（对应「复盘记忆」，约一半功能为此而生）**
- Agent 在策略层为产品定了**广告目的**（引流型 / 转化型 / 排名型 / 盈利型），并据此做了一系列调整；但当前系统**从不回头确认成效**——
  *比如 14 天前 Agent 做出了某个动作，这段时间下来，对应的广告目的到底达成了没有？*
- 记忆系统要补上这条闭环：**写入时记下"当初为了什么目的、怎么算成功"，到期对照数据仓库的实际表现，判定广告目的是否达成，再把结论反馈给下一次决策**（机制见 4.5）。

> 第四节会用一个完整例子，演示这些错具体是怎么被解决的。

---

## 二、核心思路

广告决策依赖三种信息，各司其职、互不重叠：

| 系统 | 回答的问题 | 角色 |
|---|---|---|
| **知识库** | "应该怎么做" | 规则、SOP、阈值（已有） |
| **数据仓库** | "现在的事实数字是多少" | 花费、ACOS、订单、排名（已有） |
| **记忆系统**（本方案） | "过去这样做，结果怎样" | 历史决策 + 经验沉淀（新增） |

**关键设计：记忆不靠 Agent 额外生产，而是从"已经发生的历史"里自动提炼。** 现有系统在每次分析后，已经把"做了什么决定、依据什么、运营是否采纳、是否执行"完整记录在了决策数据库里。记忆系统只需一个独立程序，定期把这些历史**读出来、提炼成经验、存好**，在 Agent 下次决策前**喂回给它**。

好处：**不增加分析负担、不改动现有流程、可直接利用已有历史数据起步。**

---

## 三、总体实现方向

记忆系统说到底，最终的落点只有一个动作：

> **把[过去的经验]，以[自然语言 + 使用规则]的形式，注入到 Agent 的[具体决策环节]。**

围绕这个落点，整体方向定为六条：

1. **锁定两个注入点**：①「逐活动决策」（这个活动今天怎么调）和 ②「策略总览」（今天整体什么基调）。其余环节本期不动。
2. **内容全部从已有决策库派生**，不让 Agent 额外生产，也不改写入流程。
3. **离线派生、在线零额外 AI 调用**：经验提前整理好，决策时只是"读一段文字"，不增延迟、不增成本。
4. **以自然语言注入，并配套"使用规则"**：不把生硬的代码字段直接丢给 AI，而是渲染成人话，再用一条规则告诉 AI "看到这种经验该怎么办"。（这是 AI 能正确理解的关键，详见第四节。）
5. **按活动精确挂载**：每条经验挂到它对应的那个活动名下，避免张冠李戴。
6. **低侵入可回滚**：总开关默认关闭，关闭即与现状完全一致。

## 四、记忆如何真正进入决策（机制详解）

这一节回答两个核心问题：**逐活动的 AI 调用，怎么知道这个活动近期被怎么调过？把信息塞进提示词后，AI 又凭什么正确理解？**

### 4.1 端到端数据流（用一个真实例子走一遍）

以活动 **「SP-精准-fishnet × B0B7S3PWWB」** 为例：

**① 历史已沉淀（素材在决策库里）**
三天前的某晚分析后，这个活动产生过一条建议："ACOS 偏高 → 降价控成本"；运营在审核界面点了"采纳"。这些——动作、理由、采纳状态、时间——都已按**活动 ID** 记录在决策库的对应字段里。

**② 派生引擎离线整理成"一句话经验"**
派生引擎读出这条历史，把分散字段拼成一句**自然语言**，按活动 ID 归档：

```
活动ID: c-77a3...   →   "3天前已降价控成本（运营已采纳），目的是把 ACOS 压回目标内；尚未到复盘期。"
```

> 注意：句中的"目的/理由"**本来就是上一轮 AI 用自然语言写好的**（存在 `决策.理由` 字段里），不是代码硬造。代码只做两件小事：把动作类型（如 `降价`）翻成中文动词、把几段拼成一句话。

**③ 今晚再分析时，检索器按活动 ID 取出，挂到该活动名下**
今晚这个活动又进入分析批次。检索器用它的**活动 ID** 去记忆库查，命中那句经验，并把它**追加到"这个活动"在提示词里的那一段**——不是笼统放在开头，所以 AI 不会张冠李戴。

**④ AI 读到经验 + 一条"使用规则"，做出正确动作**
提示词里有一条常驻的"记忆使用规则"，教 AI 怎么用这句经验。于是 AI 据此**改为"维持观察"，而不是再降一次价**——重复调整被消除。

### 4.2 AI 实际看到的提示词长什么样（前后对照）

**改之前**（无记忆，AI 容易重复降价）：
```
【活动】SP-精准-fishnet × B0B7S3PWWB
  匹配类型: 精准
  近7天: 花费 $45 · ACOS 48% · 订单 3 · 转化率 2.1%
  当前出价: $0.55 · 当前预算: $8
```

**改之后**（多了一行"近期记忆"，且系统规则里多了"记忆使用规则"）：
```
【活动】SP-精准-fishnet × B0B7S3PWWB
  匹配类型: 精准
  近7天: 花费 $45 · ACOS 48% · 订单 3 · 转化率 2.1%
  当前出价: $0.55 · 当前预算: $8
  📋 近期记忆: 3天前已降价控成本（运营已采纳），目的是压回目标 ACOS；尚未到复盘期。
```
```
【记忆使用规则】（系统提示词中常驻）
- 若某活动"近期记忆"显示 7 天内已做过同方向调整、且尚未到复盘期
   → 本次默认"维持观察"，不要重复同方向动作。
- 若上次调整目的尚未验证（未复盘）→ 禁止做相反方向的调整。
- 记忆与当前数据冲突时，遵循"先复盘、再动手"。
```

### 4.3 为什么 AI 能"正确理解"——三个保证

直接把 `action_type=adjust_bid` 这种代码字段丢给 AI，它确实可能读不懂、或当成噪声。我们靠三点确保它读懂并照做：

| 保证 | 做法 |
|---|---|
| **① 不注入裸字段，注入完整人话** | 代码把结构化字段**渲染成一句完整中文**；其中"目的/理由"本就是自然语言。AI 面对的是"3天前已降价控成本…"，不是 `adjust_bid`。 |
| **② 精确挂载，关联无歧义** | 经验句挂在**该活动自己的段落**里，AI 不会把 A 活动的历史套到 B 活动上。 |
| **③ 配套使用规则，把"看到"变成"会用"** | 仅展示经验还不够——再加一条"记忆使用规则"，把经验**转成可执行指令**（同向冷却、禁止反向）。这是从"AI 看到了"到"AI 据此正确决策"的关键一步。 |

### 4.4 第二个注入点：策略总览

除了逐活动，**策略总览**（决定今日整体基调）也注入一段 ASIN 级简报。一期注入**本产品近期轨迹**：
```
本品近14天共调整 12 个活动（淘汰 3 / 降价 5 / 调预算 4），整体偏控成本。
```
让"今日总纲"带着记忆定调，再去框住每个活动的决策。
（跨产品的"群体经验"，如"推进期+转化目的下淘汰至捡漏组历史 45 次"，属**长期记忆**，二期再加入。）

### 4.5 短期记忆的闭环：不止"记得住"，还要"知道有没有用"

防重复 / 防反向只是记忆的下半场。记忆更核心的一个目标是**复盘**——一次调整在 **1/3/7 天**后，到底有没有达成当初的目的。这构成短期记忆的完整闭环：

```
写入：动作 + 目的 + 【成功标准】 + 【复盘窗口 1/3/7 天】
   ↓  （到第 1/3/7 天）
复盘：对照数据仓库的实际数据，判定  达成 / 部分达成 / 未达成
   ↓
回灌：把结论喂回下一次决策——
      达成 → 可加码 / 进入下一阶段；  未达成 → 换打法，不再重复同方向
```

复盘分两个层级：① **动作级**——本次调整的即时成功标准（1/3/7 天，如降价后 ACOS 是否压回目标内）；② **广告目的级**——这段时间下来（最长到约 14 天），当初在策略层定的广告目的（引流型 / 转化型 / 排名型 / 盈利型）是否真的达成。**后者正是记忆系统约一半价值的落点。**

**关键设计含义（之前漏了，现已补上）**：要能复盘，就必须在**写入记忆的当下**把"成功标准 + 复盘窗口"一起记下来——没记下目标，日后无从对账。因此 **"记录可复盘的目标"属于一期硬要求**；而"到期自动判定达成与否"需要等天数走完 + 回读数仓，落在二期开头。

> **为什么"判定"放二期不是偷懒**：一次调整必须等 1/3/7 天才谈得上复盘——记录是今晚写的，最快也要明天才有得判。所以"一期记录、二期初判定"恰好踩着数据自然成熟的节奏。成功标准取自知识库按"调整目的"定义的模板（如转化目的看 ACOS 与订单、排名目的看自然位变化），无需额外 AI。

## 五、系统架构与组件

```
   [决策数据库]  ← 已有：每次分析的决策 / 采纳 / 执行结果（素材）
        │  只读
        ▼
   【派生引擎】 独立运行、可定时
     读历史决策 → 提炼成"一句话经验"（自然语言）→ 按活动ID/场景归档
        │
        ▼
   【记忆库】（文件）  短期记忆：操作记忆 + 复盘记忆
        │  决策前按需读取
        ▼
   【检索器】 → 按活动ID/场景取出 → 拼成"记忆简报"
        │  注入（自然语言 + 使用规则）
        ▼
   广告 Agent：① 逐活动决策      ② 策略总览
```

| 组件 | 职责 | 通俗说明 |
|---|---|---|
| **决策数据库**（已有） | 记录每次分析的决策与结果 | 经验的"原始素材" |
| **派生引擎**（新增，独立程序） | 读历史 → 提炼经验 → 写记忆库 | 定期整理笔记的助理，单独运行 |
| **记忆库**（新增，文件） | 存放提炼好的经验 | 一个产品一个文件，轻量、可重建 |
| **检索器**（新增） | 决策前取相关记忆，拼成简报 | 把厚笔记浓缩成"今天该记住的几句话" |
| **注入**（新增，2 处） | 把简报 + 使用规则放进决策提示词 | 让 AI 决策时"眼里有历史、手里有规矩" |

**记忆分层**（短期记忆分两层；长期记忆延后）：

| 大类 | 子层 | 存什么 | 解决什么 | 分期 |
|---|---|---|---|:--:|
| **短期记忆** | **操作记忆**（工作日记） | 近 14 天每个活动调了什么、目的、是否采纳/执行 | 防重复 / 打架 / 不承接——像给 AI 一本随调随记的工作日记（模仿长上下文会话记忆的作用） | ✅ 一期 |
| **短期记忆** | **复盘记忆**（成效） | 每次调整的**成功标准、复盘窗口、复盘结论** | 复盘"本产品的动作一段时间后是否达成当时的广告目的" | ✅ 一期记录目标 / 二期判定 |
| **长期记忆** | 经验沉淀 | **跨产品场景经验聚合**（即原设想的"模式记忆"）+ 季节 / 生命周期 / 店铺规律 | 群体经验参考、长期资产 | 🔜 二期+ |

> 命名说明：短期第 2 层此前暂称"模式记忆"，因其复盘的是**本产品自身成效**（非跨案例"模式"），且易与"跨产品经验聚合"撞名，故定名 **复盘记忆**；跨产品聚合归入**长期记忆**。

## 六、它如何提升决策准确性

| 记忆带来的能力 | 没有记忆 | 有记忆之后 |
|---|---|---|
| **防重复调整** | 同活动连两晚降价，过度收缩 | 看到"3 天前已降、未到复盘"→ 维持观察 |
| **防反向误调** | 前天提价、今天降价，互相抵消 | "上次目的还没验证"→ 禁止反向，先等结果 |
| **承接上次目的（复盘）** | 不知上次有没有用，盲目加码 | 上次达成→可加码；没达成→换打法（一期记录目标+窗口，二期到期判定达成与否） |
| **群体经验参考**（二期·长期记忆） | 每个活动都从一堆指标重新分析 | "同类场景这么调过 45 次、采纳率 82%"→ 直接参考 |
| **风险升级**（二期） | 高风险调整被自动放行 | 历史连续失败 → 自动升级人工复核 |

**可量化验收指标**：① 运营对建议的接受/拒绝率 ② 决策受风控率

## 七、存什么、不存什么

**原则：记忆不是流水日志，存太多反成噪声。** 只存"有后果、可验证、对下次有用"的：

**✅ 存**：真实动作（提价/降价/扩词/否词/淘汰/调预算）且已通过审核的决策；同活动同方向**合并去重**，只留最近。

**❌ 不存**：维持现状的零动作；被驳回/被过滤的噪声（只留失效标记）；原始指标数字（花费/ACOS/出价——属数据仓库，**本期记忆不存具体数字**）；AI 中间推理过程。

> 一句话：**记忆存"意图与结论"，数据仓库存"事实数字"，知识库存"通用规则"——三者不重叠。**

## 八、关于 AI（LLM）的取舍

AI 用在哪、不用在哪，按**任务的失效模式**划线，而不是一刀切：

| 环节 | 是否用 AI | 理由 |
|---|---|---|
| **在线决策（逐活动 / 总览）** | **不用** | 这是 40–70 次/晚的热路径，加 AI 会拖慢、加成本、加失败面。记忆做成"读了就用"的简报，注入瞬时完成。 |
| **离线提炼短期记忆** | **默认代码模板（待拍板，见下）** | 短期记忆是"安全联锁"，价值在于精确还原"上次做了什么、哪个方向、是否采纳"；代码直读字段=零失真，且"目的/理由"本就是上一轮 AI 写好的自然语言，原样复用即可。 |
| **离线沉淀长期记忆** | **用 AI** | 跨案例归纳"什么有效"、做相似场景匹配——语义合成正是 AI 的强项，且离线、低频。 |

> 划线原则：**精确召回（短期）重在"不失真" → 代码；经验归纳（长期）重在"会泛化" → AI。** 不是排斥 AI，是让工具对口失效模式。

### 【待拍板】短期记忆用"代码模板"还是"离线 LLM"提炼

> 这是一个**需要拍板、但分歧成本极低（仅一个配置开关）**的点，如实列出。

- **争议点**：短期记忆的提炼引擎是**离线、不阻塞主进程**的，所以"延迟/成本"不构成反对用 AI 的理由——那短期记忆该用代码模板还是离线 LLM 提炼？
- **两个方案**：
  - **A. 代码模板（默认推荐）**：直读结构化字段拼成定长句子。优点：对"动作/方向"**零失真**（联锁安全）、可复现、零成本、上线快。
  - **B. 离线 LLM 提炼**：让 AI 把历史压成更齐整的一句话，并能把"多步历史"归纳成一句。风险：对安全字段（动作/方向）有**非零的改写或丢失风险**——而联锁一旦报错方向，比没有联锁更糟。
- **裁决依据**：**默认 A**（理由：安全联锁不容失真）；**若前置数据审计发现 `description` 字段普遍冗长杂乱、模板拼不出可读句子，则切到 B**。
- **工程兜底**：提炼器做成**可插拔双模式**（`模板 / 离线LLM` 由配置切换），无论最终拍板结果如何都**不返工**。

## 九、一期落地（成果 + 工期）

### 交付成果
1. **派生引擎**：从历史决策自动生成短期记忆（操作记忆 + 复盘记忆），可手动/定时运行；
2. **操作记忆（工作日记）上线**：近 14 天逐活动经验 → 注入逐活动决策 + 配套"记忆使用规则"，**实现防重复 / 防反向**；
3. **复盘记忆——记录可复盘的目标**：写入时**一并记下"成功标准 + 复盘窗口(1/3/7 天)"**，为复盘闭环打底（到期判定见二期）；
4. **策略总览注入本品近期轨迹**（操作记忆汇总）；
5. **总开关**：默认关闭时行为与现在**完全一致**，可灰度、可一键回滚。

### 工期
**核心开发，含前置验证、历史数据核对、联调、回归，测试，合计约 3-4个工作日。**

### 前置条件与依赖（需先确认）
- **数据就绪验证（约半天）**：用现有审计工具核对历史决策的关联键稳定性、字段填充率、采纳/执行数据的真实分布——确认"原料齐备"。
- **两项外部依赖**：① 广告活动 ID 跨次稳定（关联记忆的钥匙）；② 上游"运营确认 / 执行"闭环的使用成熟度——它决定一期记忆的丰富度。

> **诚实口径说明**：一期记忆只到"运营接受了、且成功执行了"这一层，**不等于"最终见效了"**——"广告目的有没有达成"需二期复盘判定。简报中会明确标注口径，避免误读。

## 十、二期计划（成果 + 工期）

### 交付成果
1. **复盘器（复盘记忆闭环的收尾）**：一期已在写入时记录"成功标准 + 复盘窗口"；二期到第 1/3/7 天**自动对照数据仓库实际数据，判定"达成 / 部分达成 / 未达成"并回灌下一次决策**，为复盘记忆填上"是否达成广告目的"的结论；
2. **沉淀器（引入 AI）→ 长期记忆**：把大量复盘结论按场景聚合成**跨产品群体经验**（如"推进期+转化目的淘汰成功率"，即原设想的"模式记忆"）+ 季节 / 生命周期 / 店铺规律，并支持"相似场景"智能匹配；
3. **ASIN 背景记忆**：沉淀竞品态势、退货/评分等持久风险背景；
4. **风险联动 + 定时调度**：历史失败模式自动提高审核等级；记忆生成接入定时任务。

### 工期
**约 1-1.5周。**

## 十一、风险与边界

| 风险 / 边界 | 说明与应对 |
|---|---|
| **关联键稳定性** | 记忆靠广告活动 ID 关联，依赖上游 ID 跨次稳定；一期前置验证先确认。 |
| **一期记忆丰富度受上游闭环影响** | 若运营确认/执行尚未充分使用，一期先从"我们提议过什么"起步，随闭环成熟自然增厚。 |
| **冷启动空窗** | 上线初期积累少，价值随运行逐步显现（约一两周）。 |
| **采纳 ≠ 成效** | 一期不做成效判定，简报标注口径；真成效待二期复盘。 |
| **可回滚** | 总开关默认关闭即回到现有行为，风险可控。 |

## 十二、一页总结

| 维度 | 结论 |
|---|---|
| **做什么** | 给广告 Agent 配"经验记忆"，决策前先看历史：减少重复/反向、**复盘上次有没有达成目标**、积累经验 |
| **怎么落地** | 独立程序从已有决策库派生经验 → 存文件 → 决策前**以自然语言+使用规则注入**两个关键环节 |
| **AI 怎么读懂** | 不给裸字段、给人话；经验精确挂到对应活动；配"使用规则"把经验变成可执行指令 |
| **改动多大** | 不改现有分析流程，开关默认关，可灰度可回滚 |
| **一期成果** | 短期记忆两层：操作记忆（工作日记·防重复/反向）+ 复盘记忆（记录可复盘目标），约 3–4 个工作日 |
| **二期成果** | 复盘判定（成效达成）+ 长期记忆（群体经验/季节规律）+ 背景记忆 + 风险联动，约 1–1.5 周 |
| **怎么衡量** | 运营接受/拒绝率、决策受风控率；二期加"成效达成率" |
| **待拍板** | 短期记忆提炼用「代码模板（默认）」还是「离线 LLM」——默认 A，按前置审计结果定，可插拔不返工（见第八节） |
