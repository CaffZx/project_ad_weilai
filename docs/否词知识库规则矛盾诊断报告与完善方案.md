# 否词知识库规则诊断与改造方案

> 记录时间：2026-08-07。诊断对象：KB31《广泛自动词组调整规则》§4、KB19《执行层数值规则》§8、KB17《问题诊断与动作优先级》§3、ontology/runtime_contract.yaml ONT-RUNTIME-004、ontology/actions.yaml add_negative_search_term。
> 触发现象：① 否词触发频率太少；② 否词被核心词/保护词阻断；③ 否词不正确——仅一次没点击的词 LLM 也否。

---

## 一、发现的问题

### 1. KB 根本没有数据驱动的否词规则

KB31 §4 四档表（L90-95）的"是否否词"列与"数据条件"列**完全解耦**：

| 档 | 数据条件（控制"降Bid"） | 是否否词（控制"否词"） |
|:-:|------|:--:|
| 1 | 点击<10 且 花费<无单门槛 → 不降Bid | **否**（数据不足，不否词） |
| 2 | 点击≥10 或 花费≥无单门槛 → 降Bid一档 | **否**（R1/R2 相关，不否词） |
| 3 | 点击≥20 或 花费≥强优化门槛 → 降Bid两档 | **否**（通常不否 R1） |
| 4 | 无数据门槛 | **是**（R3/R4 语义不相关） |

否词的触发条件**完全由相关性判定（R1-R4）驱动，与数据（花费、点击、订单）无关**。整个 KB 不存在一条"某搜索词 7 天花费 > $X 且 0 单 → 应当否词"的规则。`03号§7`（L385）的注释提到"效率驱动否词（05号§3 路径二）"，但 05 号早已删除，该概念在现行 KB 中无任何落地。

**结果**：否词 = 语义判定，而非数据判定。只要 LLM 判了 R1/R2 相关性，该词无论花费多高、表现多差，都不会被否词，只能降 Bid/降预算。

### 1.1 推论：R1/R2 词永远不会被否词

§4 四档表（用相关性标注还原）：

| 档 | 相关性 | 数据条件 | 动作 | 是否否词 |
|:-:|------|------|------|:-:|
| 1 | 任意 | 点击<10 且 花费<无单门槛 | 观察 | **否** |
| 2 | R1/R2 | 点击≥10 或 花费≥无单门槛，无订单 | 降 Bid 一档 | **否** |
| 3 | R1/R2 | 点击≥20 或 花费≥强优化门槛，仍无单 | 降 Bid 两档 + 降预算 | 通常**否** |
| 4 | R3/R4 | 无数据门槛 | 否词 | **是** |

档 1-3 全部"不否词"——一个 R1/R2 的词无论花费多高、表现多差，都只能降 Bid/降预算，永远不会被否词。"相关性优先于效率"的实际效果是"相关性豁免否词"：LLM 判了 R1/R2 之后，否词永久关闭。

KB17 §3.2 对 `KEYWORD_POOL_DIRTY` 说"① 先否词净化 ② 净化完成后再扩词"——但如果词池里的脏词被 LLM 标记为 R1/R2，按 §4 全部不能否词，"先否词净化"的第一步永远卡住。

### 2. KB 宏观"先否词"与微观"不否词"互相矛盾

KB 在不同地方给了 LLM 相反的信号：

**宏观层面——"遇到问题先否词"**：

| 位置 | 规则 |
|------|------|
| KB31 §13 L250 | "高花费无单且低相关 → **否词** → 降 Bid → 降预算" |
| KB31 §13 L254 | "停止投放前必须走完诊断路径：**先否词** → 仍无改善降 Bid" |
| KB17 §3.1 L122 | `KEYWORD_POOL_DIRTY`："① **先否词净化**" |
| KB17 §3.2 L139 | `KEYWORD_POOL_DIRTY`："① **先否词净化** ② 净化完成后再扩词" |
| KB17 §3.3 L150 | `HIGH_ACOS_NO_ORDER`："① **否词**（广泛）/ 降Bid（精准）" |

**微观层面——"逐词不否词"**：KB31 §4 四档表，档 1-3 全部"不否词"。

LLM 读到的整体印象是"遇到问题先否词"，但逐词决策时§4 表说"不能否"。**宏观规则和微观规则方向相反**——§4 表的"不否词"被 KB17 的"先否词净化"惯性覆盖。

**但更深层的问题是**：即使 LLM 严格遵循 §4 逐词判定为 R1/R2 不否词，KB 的宏观"先否词"也从未定义过**哪些客观数据条件可以推翻"不否词"**——因为否词条件从来不依赖数据。

### 3. ONT-RUNTIME-004 保护范围过大，但数据不可执行

`ontology/runtime_contract.yaml` ONT-RUNTIME-004（L203-210）：

```
描述: 高相关词、标题词、后台ST词和历史转化词禁止否定
forbidden_when:
  - high_relevance
  - title_term
  - backend_search_term
  - historical_converted_term
```

`evidence.yaml` add_negative_search_term（L166-169）：

```yaml
required:
  - search_term_report
```

**三层断裂**：
- ONT-RUNTIME-004 要求禁止否词的条件包括 `title_term`（标题词）、`backend_search_term`（后台 ST 词）、`historical_converted_term`（历史转化词）——但**代码从未把"这个词是不是标题词/ST 词/历史转化词"注入 prompt**，LLM 无法判断。
- `evidence.yaml` 要求否词必须基于 `search_term_report`——但 `search_term_report` 只是一个 MCP 工具返回，不代表数据充分性已验证。
- `actions.yaml` add_negative_search_term 的 `missing_report_policy: hard_block` 表示**缺少搜索词报告时硬阻断**——但当搜索词报告存在但词级数据不足时（点击 0、花费 0），没有阻断。

**结果**：ONT-RUNTIME-004 在 prompt 里是一个空头支票——LLM 不知道哪个词是后台 ST 词、哪个是历史转化词。保护逻辑只能在 LLM 的"自觉"上运行，代码完全无法校验。

### 4. 一次没点击的词也否——代码没有任何数据门槛

KB31 §4 档 1（L92）："活动上线 <3 天；或 7 天点击 <10 **且** 7 天花费 < 无单花费门槛" → "不做大幅调整" → "否"（不否词）。

`reasoner.py` L375 prompt 规则："词级样本不足按 7d「点击<10 且花费<max($15, 目标 CPA)」判定"。

`reasoner.py` 否词闸门（L2062-2096）：**只检查 match_type==NEGATIVE_EXACT 和 keyword 在搜索词索引中**，没有点击/花费/订单的数据门槛检查。

**根因**：prompt 告诉了 LLM"样本不足不否词"，但代码没有第二道防线。LLM 一旦输出 `negative_keywords`，闸门放行。代码层完全没有执行 KB19 §8 的四档判定。

### 5. KB30 已删除但 prompt 仍在引用

`reasoner.py` L375 prompt："先读 KB 30 §2（必需数据）确认数据可用，再按 KB 30 §3 判断相关性，最后走 KB 30 §5 准入规则和 KB 30 §6 精准/词组选择。"

v3.22 KB 重构时 `30-广泛广告否词与搜索词治理规则.md` 已删除，内容迁移至 KB31。LLM 注入的 KB preset 中 `campaign_adjustment_broad` 包含 `31`（KB31）但没有旧 `30`。prompt 文本中的 "KB 30" 引用是**死引用**，LLM 拿到的是 KB31 的内容但被叫成 KB30——这可能误导 LLM 去推理不存在的章节。

## 二、知识库现有局限

### 2.1 §4 四档法则缺少"效率否词"的独立通道

当前 §4 的否词 = 相关性判定（R3/R4）。但 `03号§7`（L385）有一条关键注释：

> **相关性驱动否词豁免**：R3/R4 否词（31号§4 档4）是语义判定不依赖表现数据，**不受本门约束**；
> 效率驱动否词（05号§3 路径二）仍受约束

"效率驱动否词"在 05 号 §3 被提及，但在 KB31 的 §4 表中**完全缺失**——既没有"效率驱动否词"的触发条件（高花费+高点击+无转化+即使 R1/R2 也可否），也没有对应的数据门槛。整个 KB31 只有"相关性否词"一条路。

KB22 §3.3："调整维度为 Budget → Bid → SearchTerm（否词/提词）"。SearchTerm 层的"否词"被排在最后——但 KB31 没有任何规则解释**什么时候该走 SearchTerm 否词而不是继续降 Bid**。

### 2.2 actions.yaml 的 forbidden_objects_or_scenes 未落地

`actions.yaml` add_negative_search_term（L142-145）：

```yaml
forbidden_objects_or_scenes:
  - listing_optimization_in_progress
  - test_period_insufficient_sample
  - brand_competitor_term_unreviewed
```

`test_period_insufficient_sample` 禁止在测试期样本不足时否词。但代码侧**没有任何 `forbidden_objects_or_scenes` 的校验**——这个 ontology 规则只在 `kb_loader.py` 的 `build_ontology_card()` 中注入 prompt，不执行代码校验。

### 2.3 KB17 `KEYWORD_POOL_DIRTY` 的"先否词净化"路径不可达

KB17 §3.1（L122）：`KEYWORD_POOL_DIRTY` → "① 先否词净化 ② 否词后重新评估是否继续 push_natural_rank"。

KB17 §3.2（L139）：`KEYWORD_POOL_DIRTY` → "① 先否词净化 ② 净化完成后再扩词"。

但 KB31 §4 表格中"否词"唯一触发条件是 R3/R4。如果词池里的是 R1/R2 的脏词（比如高 ACOS 但语义相关的广泛流量词），按 §4 全部不能否词。"先否词净化"的第一步永远执行不了，`KEYWORD_POOL_DIRTY` 的后两步也永远无法执行。

## 三、改造建议方案

### 3.1 KB 侧：补数据驱动否词规则（KB31 §4.1 新增）

现行 §4 的否词完全依赖相关性（R3/R4）。需要补一条**独立于相关性的数据驱动否词通道**：

```
### 4.1 数据驱动否词（独立于相关性）

以下条件同时满足时，**即使 R1/R2 也可以否词**（效率否词）：
- 7天花费 ≥ 强优化花费门槛（max($20, 目标CPA×2)）
- 7天订单 = 0
- 7天 CVR = 0%
- 7天点击 ≥ 20

→ add_negative_search_term（MANUAL_REVIEW），reason 写明"高花费完全无转化，即使语义相关也应否词以减少无效花费"
```

这条规则使得否词从纯语义判定扩展为"语义 + 效率"双通道。效率通道有严格的数据门槛（花费/点击/订单三重条件），且 MANUAL_REVIEW 人工确认。

### 3.2 KB 侧：§4 表改称"相关性否词"，与 §4.1 "数据驱动否词"并列

§4 标题从"相关性优先于效率：四档分支"改为"相关性否词：四档分支"。明确两种否词通道的优先级：相关性通道优先（R3/R4 → 立即否词，无数据门槛）；数据通道补位（R1/R2 + 高花费零转化 → MANUAL_REVIEW 否词）。

### 3.3 代码层：否词闸门加数据门槛（`reasoner.py`）

在现有"match_type 检查"和"搜索词索引检查"之后，加第三层——数据门槛：

```python
# 否词闸门 §3: 数据门槛
term_data = authoritative  # search_terms_by_cid 中已取到的词数据
metrics = term_data.get("metrics_7d", {})
clicks = int(metrics.get("clicks") or 0)
cost = float(metrics.get("cost") or 0)

# KB19 §8：样本不足 → 禁否词
threshold = max(15.0, float(target_cpa) if target_cpa else 15.0)
if clicks < 10 and cost < threshold:
    logger.warning("否词闸门 [%s]: keyword=%r 样本不足 → 丢弃", ...)
    continue

# R1/R2 有订单 → 禁否词（效率否词需要 0 订单）
orders = int(metrics.get("orders") or 0)
if orders > 0:
    logger.warning("否词闸门 [%s]: keyword=%r 有订单 → 丢弃", ...)
    continue
```

效果：LLM 即使少数学了"遇到问题先否词"，数据门槛也会拦截。

### 3.4 Prompt 侧：修复死引用

`reasoner.py` L375 的 "KB 30" → 改为 "KB 31"。

### 3.5 报告端到端示例

```
搜索词: "irrelevant dress"  | R4 | 7d clicks=15, cost=$25, orders=0
  → 档 4: R4 不相关 → 否词 ✅

搜索词: "fishnet stockings plus size"  | R1 | 7d clicks=0, cost=$0, orders=0
  → 档 1: 样本不足 → 代码拦截 ❌

搜索词: "cheap fishnet"  | R2 | 7d clicks=12, cost=$18, orders=0
  → 档 2: R1/R2 相关但无转化 → 不否词，降 Bid
  → 但如果 cost=$35(≥强优化门槛), clicks=25(≥20) → 可走效率否词(MANUAL_REVIEW)
```
