## 二、Part 6 新增功能 — 广告调整 MCP 真实执行接入

### 2.1 业务背景与目标

分析 → 落库 → 运营确认(confirm)后,**之前没有任何代码把 CONFIRMED 的调整真正执行到 Amazon**(`execute_status` 永远 PENDING,前端有「执行流待接入」占位)。本次接入广告调整 MCP `whp-advert-agent`(`http://192.168.2.31:5678/mcp`,6 工具),把这条链路接通:

```
运营在 tab5 勾选 → 「同意所选」(confirm,标 CONFIRMED)
              → 「执行已确认调整」(新增) → 后端调调整 MCP
              → 拿 taskId → 落 record + 回写 pending execute_status
              → 前端「调整记录」表展示
```

### 2.2 落地原则

- **两步制**:`confirm`(标 CONFIRMED,现状)与 `execute`(调 MCP)分离,可二次复核。
- **复用旧 4 张 `_record` 表**(advert/campaign/keyword/placement),不建新表。
- **唯一映射点** `advert_exec_mapper.py` — Agent action → MCP 工具的所有字段/枚举/命名映射只在这里。
- **dry-run 默认开** — 构造 payload + 落 advert_record(标 DRY_RUN),**不调 MCP**;上线前可全链路验证而不动真实广告。
- **总开关 `advert_mcp_enabled` 默认关** — 开箱不会动真实广告。
- **幂等** — 只取 `execute_status=PENDING` 的 pending 行,已执行项不再处理。
- **门禁** — 沿用 confirm 校验(`is_latest=1` 且无进行中 session)。

### 2.3 调整 MCP 6 工具总览(已实测连通)

| 工具 | 用途 | 必填(实测) |
|---|---|---|
| `agent_async_batch_update_advert` | 异步批量改已有 (bid/budget/placement/state) → 返回 taskId | `paramsVoList` |
| `agent_batch_update_advert_result` | 查异步结果 | `taskIds[]` |
| `agent_create_portfolio_campaign` | 新建组合(可选)+ 活动 | `shopId/parentAsin/parentSellerSku/createCampaignVo`,且**实测必须含 `productColor`+`productSize`**(schema 标可选) |
| `agent_create_negative_keywords` | 否定词/关键词 | `shopId/parentAsin/parentSellerSku/keywordType/campaignVoList` |
| `agent_query_portfolio_list` | 查组合列表(只读) | `shopId/parentAsin/parentSellerSku` |
| `agent_query_keyword_suggest_bid` | 查建议竞价(只读) | `shopId/parentAsin/parentSellerSku/keywordVoList`,且**`currentUserId` 实为必填**(schema 标可选,空则报「用户id不能为空」) |

### 2.4 Agent action → MCP 工具 → record 子表 映射

| action / 来源 | MCP 工具 | record 子表 |

placement 三套命名归一(mapper 唯一处理):pending `TOP_OF_SEARCH` ↔ MCP async 字段 `placementTopPercent` ↔ MCP create predicate `TOP` ↔ record `TOP_OF_SEARCH`。

## 五、过程中真库才暴露的真实缺陷(全部已修)

| # | 真实发现 | 修复 |
|---|---|---|
| 1 | **测试 ERP 库 sql_mode 严格** (`STRICT_TRANS_TABLES,ONLY_FULL_GROUP_BY,...`) | 印证 Part 3 步骤4「类型收窄缺陷」是真阻塞 |
| 2 | **改造后 `version` 列已删**(`advert_record`+`campaign_record` 等) | 5 个 record INSERT 移除 `version` 列 |
| 3 | **审计列 `create_by/editor_by`=int、`creator_id/editor_id`=bigint** | 加 `_audit_int()`:数字串→int、非数字串→NULL;`current_user_id`(varchar) 仍存 operator 串 |
| 4 | **MCP `currentUserId` 实为必填**(schema 标可选) | 客户端/mapper 全程带上;mapper 入参 `operator` 不能为空 |
| 5 | **MCP 返回 3 种信封形态**(原解析器漏 2 种) | `parse_result_envelope` 加固:任意 `*state` 取状态、任意 `*msg` 取消息;有 errorMsg 即失败 |
| 6 | **新建活动 `productColor/productSize` 实为必填**(schema 标可选) | 接入 create 路径时需从数仓 `dwd_whp_amazon_listing_general.product_color/product_size` 取(child 级精确值,如 `White`/`Medium`) |

// 未找到资源(无 state 字段)
