# 标签维度定义（dimensions.yaml）

> C01 / `amazon_ops.v2`：所有标签必须归属唯一 `OperatingUnitRef`，即
> `shop_id + site_code + parent_asin`。父 SKU 只用于外部接口映射，不参与唯一性。
> 缺少店铺或站点时可生成候选与数据缺口，不得保存配置或执行广告动作。

## 维度总览

共 **13 个**标签维度，用于给每个 ASIN 打标签，指导广告策略决策。

| 维度 | 类型 | 维护方 | 更新频率 | Agent权限 |
| --- | --- | --- | --- | --- |
| **经营模式** | 单选 | 运营手动 | 事件驱动 | **仅建议，不可自行变更** |
| 产品定位 | 单选 | 运营手动 | 长周期 | 仅建议 |
| 产品阶段 | 单选 | 运营手动 | 长周期 | 仅建议 |
| 淡旺季 | 单选 | 运营手动 | 长周期 | 仅建议 |
| 广告目的 | 单选或多选 | Agent建议+运营确认 | 长周期 | 可提议变更 |
| 关键词类型 | 单选或多选 | Agent建议+运营确认 | 长周期 | 可提议变更 |
| 广告方向 | 单选或多选 | Agent建议+运营确认 | 每日 | 可提议变更 |
| ACOS目标 | 数值 | Agent建议+运营手动 | 每日 | 仅建议 |
| 预算 | 数值 | Agent建议+运营手动 | 每日 | 仅建议 |
| 广告预算组合类型 | 单选 | Agent自动归类+运营可覆写 | 每次广告调整 | 可自动归类并提议 |
| 特殊场景 | 单选或多选 | 混合 | 事件驱动 | 可提议或遵循 |
| 广告位 | 单选或多选 | Agent建议+运营确认 | 每日或活动变更 | 可提议调整 |
| 市场竞争态势 | 衍生对象 | Agent从ERP数据衍生 | 每日 | 可衍生存储并提议 |

## 1. 产品定位

战略资源优先级，开发阶段即定，不因短期ACOS/销量波动自动变更。

| 级别 | 定义 |
| --- | --- |
| P0 | 战略级产品，全年核心主推或旺季爆款。准入条件：月订单≥3000 + BSR Top50 + 评≥4.0 + 退货率≤25% + 库存≥30天。 |
| P1 | 重点产品，市场已验证且有机会推成主力款。P2→P1需满足任意3条：日均订单≥50 / 环比≥20% / 自然单>30% / 核心词Top50 / 退货率≤30% |
| P2 | 常规产品，稳定出单、控制成本、保护利润（兜底类型） |
| P3 | 长尾产品，高毛利、小众或风格化，不追大词排名，ACOS通常≤30% |

**英文映射（English Mapping）**：用于代码/数据库中的产品定位标识。

| 中文名称 | English Key |
| --- | --- |
| 战略级产品 | P0_PRODUCT |
| 重点产品 | P1_PRODUCT |
| 常规产品 | P2_PRODUCT |
| 长尾产品 | P3_PRODUCT |

**p0_protection_rule**：P0 为战略级产品，不因淡季、旺季末期、测试期、短期 ACOS 或销量波动自动触发降级。即便进入淡季或旺季末期，仍须保持：核心词权重不变、自然流量保护、Conversion 低成本承接、Profit 控损、balance_maintain 平衡维持。仅在不可投放、库存断货、严重差评等硬阻断场景下，允许跳过常规广告动作。

## 2. 产品阶段

产品当前客观运营阶段。

| 阶段 | 说明 | 关键约束 |
| --- | --- | --- |
| testing | 验证品质、退换货、价格、Listing承接和词路 | 日预算≤$30，最多测60天 |
| pushing | 测试通过后放量、推排名、扩大有效词 | ACOS可+10pp容忍→有效上限50%，P0日预算≥$150，P1≥$100 |
| harvesting | 销量和结构稳定后提升广告效率和利润 | ACOS收紧至30% |
| maintaining | 数据健康，无需大动作 | 保排名、稳单量、稳利润 |
| liquidating | 清库存阶段 | AI可建议但必须人工确认，ACOS放宽至60%，日预算≤$80 |

## 3. 淡旺季

AI可建议但必须人工确认-类目/直接竞品市场环境，不能只按月份判断。

| 阶段 | 判定条件 |
| --- | --- |
| 淡季 | 类目搜索量<峰值40% + 竞品销量<峰值50% |
| 旺季前期 | 类目搜索量环比>15%/2周 + CPC周环比>5% + ≥3竞品BSR爬升 |
| 旺季 | 类目搜索量达峰值±15% + ≥3竞品BSR飙升 |
| 旺季末期 | 类目搜索量降>20% + ≥2竞品降价清库存 |

## 4. 广告目的

当前广告目标。

| 目的 | 说明 | 倾向的广告方向 |
| --- | --- | --- |
| traffic | 引流 | expand_keywords |
| conversion | 转化 | expand_keywords, push_natural_rank, balance_maintain |
| ranking | 冲排名 | push_natural_rank |
| profit | 利润 | optimize_acos, balance_maintain |

切换冷却：≥7天，30天内≤2次。

约束：`ad_purpose` 只能是 `traffic / conversion / ranking / profit`；`balance_maintain` 只能作为 `ad_direction`，不得写成 `ad_purpose=maintain` 或 `ad_purpose=balance_maintain`。

> **Ontology 引用**：广告目的的合法枚举、与广告方向的映射关系，详见 [20-亚马逊广告ontology补充 §6 广告目的与广告方向 Ontology](20-亚马逊广告ontology补充.md#6-广告目的与广告方向-ontology)。

## 5. 关键词类型

关键词或 Target 的策略类别，用于出价、扩词、否词和预算分配。
注意：关键词类型不是匹配方式，不能与 `match_type` 混用。

| 类型 | 出价系数 | 说明 |
| --- | --- | --- |
| generic（大词/泛词） | 0.5 | 低成本曝光筛词，允许阶段性偏高 ACOS，但必须换来曝光、点击、搜索词样本或有效词根 |
| long_tail（长尾词） | 0.8 | 3-6 单词，精准意图高转化，ACOS 严格监控，是整体 ACOS 锚定点 |
| competitor（竞品词） | 0.8 | 直接竞品反查得出的关键词，初始中低 Bid 测试 |
| brand（品牌词） | 0.3 | 借品牌流量做平替转化，小比例补充策略 |
| custom（自定义词） | 0.5 | 运营经验词/节日词/趋势词 |

## 6. 广告方向

每日执行方向。

| 方向 | 说明 |
| --- | --- |
| push_natural_rank（推自然位） | 自然位上升+ACOS可控+花费稳定+CVR不降 |
| expand_keywords（新增扩词） | 三信号：预算花不完/现有词效果差/单量想更大 |
| optimize_acos（优化ACOS） | 按层级排查：整体→组合→活动→关键词→搜索词 |
| balance_maintain（平衡维持） | 有意识不作为，所有指标正常时默认 |

> **Ontology 引用**：广告方向的合法枚举、与广告目的的映射关系，详见 [20-亚马逊广告ontology补充 §6 广告目的与广告方向 Ontology](20-亚马逊广告ontology补充.md#6-广告目的与广告方向-ontology)。

## 7. 特殊场景

覆盖日常策略的特殊场景。优先级规则：特殊场景 > 硬护栏 > 库存 > 退货/评价 > 产品阶段 > 淡旺季 > 广告目的 > 竞品 > 广告方向 > 产品定位。

| 场景 | 维护方 | 核心规则 |
| --- | --- | --- |
| promotion（活动促销） | 运营手动 | ACOS容忍度+0.15，预算+0.15，库存<30天时阻断 |
| inventory_low（库存不足） | Agent建议+运营确认 | Ranking降级为核心词保护或Conversion承接，执行方向可切到balance_maintain，出价系数0.7，预算最多降50% |
| bad_reviews（差评） | Agent建议+运营确认 | Ranking降级为Conversion |
| listing_optimization（页面优化） | 运营手动 | 强制balance_maintain观察7天，最大出价调整0.05，不新增否定词 |
| urgent_liquidation（紧急清仓） | 运营手动 | 暂停 ACOS 约束判断，不代表暂停广告投放；预算模式激进，需HIGH_RISK_REVIEW |

## 8. 广告位

Amazon SP广告位加价策略。详见广告位规则。

| 位置 | 适用说明 |
| --- | --- |
| top_of_search（搜索结果顶部） | P0/P1推进期/maintaining可用，单次≤30%，>20%需高级审批 |
| product_pages（商品页面） | 截流/清仓首选，单次≤10% |

## 9. 广告预算组合类型

父 ASIN 下每个 Campaign 归属的 AdBudgetGroup 类型，用于三层预算控制（ParentASIN → AdBudgetGroup → Campaign）。Agent 每次广告调整时自动归类，运营可覆写。

| English Key | 组合名称 | 允许的 campaign_type | 核心目的 |
| --- | --- | --- | --- |
| `exact_core_group` | 精准主力组 | `exact_keyword` | 承接通过连续三日验证的单关键词精准活动 |
| `exact_testing_group` | 精准测试组 | `exact_keyword` | 验证尚未通过连续三日门槛的单关键词精准活动；支持 `protected_testing` 保护标记 |
| `auto_broad_group` | 广泛自动组 | `broad_keyword` / `phrase_keyword` / `auto_discovery` | 用低 Bid 获取探索流量和有效搜索词；表现好时允许获得预算 |
| `auto_broad_group` + `subtype=product_targeting` | **商品定投子桶** | `product_targeting` | 竞品截流、类目拓展、防守自家页面。允许广告位调整（PP 优先，`ONT-010`，按子桶放开）；不套三日验证；退出走 `paused_campaign`；预算计入广泛自动组，组内**先于**广泛/词组/自动被压缩 |
| `low_bid_retention_group` | 低价捡漏组 | `exact_keyword` | 仅承接退出后的精准活动；组合预算 $1、Target Bid `min(current_bid, 0.20)` |

组合身份由匹配类型与验证状态决定，不由活动预算金额决定。旧名称仅作为历史输入兼容，不作为 Agent 输出。

## 13. 经营模式

父 ASIN 当前的**经营意图**，由运营手动录入或确认。**Agent 只引用，不自行变更。**

| English Key | 中文 | 广告权限 | 核心含义 |
| --- | --- | --- | --- |
| `immediate_exit` | 立即退出 | `STOP` | 不再经营。确定性路径：精准迁低价捡漏组，广泛/词组/自动/商品定投 `paused_campaign`，禁止新建 |
| `controlled_clearance` | 控制清货 | `CLEARANCE_ONLY` | 控成本收缩，允许有限清货动作。可选人工字段 `clearance_deadline` |
| `limited_repair` | 有限修复 | `NORMAL` + 目标 ACOS 约束 | 在父 ASIN 预算与目标 ACOS 内修复；阶段 ACOS 正加值归零 |
| `stable_operation` | 稳定经营 | `NORMAL` | 保持盈利对象稳定，避免不必要扩量 |
| `active_promotion` | 积极推进 | `NORMAL` | ACOS 良好且在预算内时不机械限流；可设人工 `max_exact_push_share` |
| `profit_harvest` | 获取利润 | `NORMAL` | 以利润和现金回收为第一目标，优先低成本流量；阶段 ACOS 正加值归零 |

**枚举名硬规则**：积极推进的 English Key 是 `active_promotion`，**不是** `active_push`。
照 `active_push` 实现会走到 `except ValueError` 分支并**静默降级为 `NORMAL`**——
经营模式静默失效；正确实现是未知枚举值强制 `MANUAL_REVIEW`。

### 13.1 经营模式与产品阶段的区别（最容易混淆的一处）

| | 经营模式 | 产品阶段 |
| --- | --- | --- |
| 性质 | 经营**意图**（人的决定） | 客观**状态**（产品所处生命周期） |
| 谁决定 | 运营手动录入 | 运营手动维护，Agent 可建议 |
| 决定什么 | **方向与权限**：允许哪些动作、是否允许新建、预算倾向给哪个组合 | **幅度**：Bid/预算幅度系数、ACOS 容忍加值 |
| 变更频率 | 事件驱动（决定退出、决定清货） | 长周期 |

**两者不争夺同一个决定权**，所以 6 模式 × 5 阶段的 30 种组合中有 29 种可确定性推导，
不需要枚举仲裁表。唯一真冲突在 ACOS 容忍加值（模式想收缩、阶段给了正加值），
消解规则见 `09号§3`。

### 13.2 优先级

经营模式在冲突裁决链中**位于产品阶段之前**（`09号§1`）：
「这个品阶段上还在 pushing，但我决定立即退出」必须能表达，反之无意义。

但经营模式**不置顶**——安全护栏、库存阻断、退货评价风控仍优先于经营意图。
理由：`controlled_clearance` / `active_promotion` 若置顶，就能覆盖「库存 <7 天阻断增长动作」
这类硬阻断，这是危险的。`immediate_exit` 的硬路径在代码中前置执行，不依赖裁决链。
