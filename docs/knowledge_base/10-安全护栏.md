# 安全护栏（safety_guardrails.yaml）

定义 Agent 的安全边界、数据降级策略、幂等规则。

## 1. 硬护栏（Hard Blocks）

### 1.1 不直接执行

Agent 不得直接调用 Amazon API 执行广告更改。所有可执行输出使用 PROPOSED 状态，需要 ERP 审核。

### 1.2 缺少必需数据

任何动作都至少需要以下数据，缺失则 BLOCKED： - ASIN标签 - 知识库版本 - 父ASIN库存 - 广告指标

### 1.3 库存数据缺失

库存数据不可降级用于增长型动作。阻断以下操作：提价、加预算、加广告位、扩词

### 1.4 单次最大出价变化

- 超出阈值上限 → 需 HIGH_RISK_REVIEW

- 超出绝对上限 → BLOCKED

### 1.5 单次最大预算变化

- 超出阈值上限 → 需 HIGH_RISK_REVIEW

- 超出绝对上限 → BLOCKED

### 1.6 停投类动作处理

Agent **可以**输出退出类动作，但必须使用正确的动作码，且必须人工确认。

| 活动类型 | 退出动作 | 去向 | 审核等级 |
| --- | --- | --- | --- |
| 单关键词 EXACT | `eliminate_to_low_bid_pool` | 低价捡漏组：预算 $1、Bid `min(current_bid, 0.20)` | HIGH_RISK_REVIEW |
| 多关键词 EXACT | `eliminate_to_low_bid_pool` | 低价捡漏组（确定性迁入） | HIGH_RISK_REVIEW |
| BROAD / PHRASE / AUTO | `paused_campaign` | 暂停关停。**不得**进低价捡漏组（`ONT-016`） | HIGH_RISK_REVIEW |
| PRODUCT_TARGETING | `paused_campaign` | 暂停关停。**不得**进低价捡漏组 | HIGH_RISK_REVIEW |

**硬规则**：

- 退出动作是 `paused_campaign`（LLM 语境动作码，出 LLM 翻译为后端 `paused`）。
- 退出动作必须人工确认，审核等级 `HIGH_RISK_REVIEW` 且**不可降级**。
- 退出动作必须走完对应的诊断路径才能提出：精准类按 `21号§3`，广泛类按 `21号§3` 的广泛分支
  （高点击无单 → 先否词 → 降 Bid/预算 → 仍无改善才评估关闭）。
- 退出动作触发预算回算义务（`GROUP-BUDGET-001/002`），未回算则 `GROUP-002` 阻断输出。

### 1.7 禁止无限预算

Agent 不得输出无限预算，包括紧急清仓场景。替代方案：clearance_aggressive_mode_with_senior_approval

### 1.8 对象级非法动作阻断

- `SearchTerm` 禁止直接执行 Bid / Budget / Placement 动作（`ONT-001`）
- `broad_keyword / phrase_keyword / auto_discovery` 禁止输出 Placement 调整（`ONT-002`）
- `exact_keyword` 禁止输出否词动作（`ONT-015`）；**阻断时必须给出 `recommended_next_step`**
  （降 Bid 观察 / 暂停该 Target / 迁入低价捡漏组，见 `22号§2.4`），不得只 block 不给替代路径
- `product_targeting` **允许** Placement 调整（PP 优先，`ONT-010`）。它归属 `auto_broad_group` 的 `product_targeting` 子桶——
  **权限判据必须同时看组合与子桶**：只看组合会把它误判为「广泛自动组 → 禁止广告位」
- 低价捡漏组只允许 `exact_keyword`（`ONT-016`）
- 未在 `30号§1` 注册的 `action_code` → BLOCKED（`reason_code = ACTION_NOT_REGISTERED`）
- `action_code` 与 `physical_action_code` / `scope` / `campaign_type` 不匹配 → BLOCKED（`30号§7`）
- 若动作对象与 Ontology 允许对象不一致 → BLOCKED

### 1.9 组合预算超限阻断

Campaign 预算调整后必须按三层逐级回算（`GROUP-BUDGET-001/002`），超限则阻断：

| 超限场景 | 判断标准 | 处理 |
| --- | --- | --- |
| 组合预算超限 | Campaign 预算调整后，所属 `AdBudgetGroup` 的 `proposed_group_budget` 超出组合预算上限 | BLOCKED |
| 父 ASIN 总预算超限 | 所有组合预算汇总后 `proposed_total_group_budget > parent_target_daily_budget`，且本轮 `net_required_increase > parent_allowed_net_increase` | BLOCKED |
| **超配跨越 2 倍**（本轮动作造成） | 调整前 活动预算总和 ≤ 组合预算 × 2.0，调整后 > 2.0 | **BLOCKED**（`GROUP-010`）。Agent 自己造成的必须拦 |
| **存量已超 2 倍** | 调整前 活动预算总和已 > 组合预算 × 2.0 | **MANUAL_REVIEW**，且本轮**只允许输出降预算动作**（`GROUP-010`） |

超配的目的是避免预算花不完（Campaign 日预算是上限，多数活动实际花费低于日预算），
健康比例分层见 `23号§4.3`。

### 1.10 账户级断路器

在「本轮提案生成之后、输出之前」评估聚合统计，任一触发
→ 本轮降级为 no-op 或全量 MANUAL_REVIEW + 报警：

| 断路器 | 触发 | 级别 |
| --- | --- | --- |
| CB-01 数据事故 | 昨日有花费（≥ 03号§13 阈值）但全账户 0 订单 → 疑似归因/报表中断 | NO_OP |
| CB-02 净预算变化 | 本轮净预算变化超父预算总和的上限比例 | NO_OP |
| CB-03 提案量突增 | 本轮提案数超近 7 轮均值的倍数上限 | REVIEW_ALL |
| CB-04 未成熟批量收缩 | 降级类动作占比超限 **且** 窗口平均成熟度低于下限 | NO_OP |
| CB-05 批量退出 | 单轮淘汰/关闭类动作超每店铺上限（首次接入例外走 03号§7.2） | NO_OP |

NO_OP = 本轮全部动作降级为观察 + 报警 + 人工确认后重跑。断路器是机械防线，
不做业务推理；它的触发含义是「这轮的形态异常到不该无人放行」。阈值见 `03号§13`。

### 1.11 对账冻结

日级两方对账（ERP ↔ Agent 期望值）检测到**外部修改**
（运营手改 / 亚马逊自动规则）时，该对象转入「人工接管中」：Agent 跳过它并输出 flag，
直到运营显式解冻（操作人入审计日志）。每次写回前执行 CAS 校验（当前值 == 上次读值），
失败即放弃写入并转对账队列（复合动作整批放弃）。
**机器不得覆盖人的操作** —— 违反一次，运营就会永远绕过系统。

### 1.12 顺序纪律：先机械护栏，后取消人工点击

既定路线是「人工审核作为前期风控，随数据积累逐步取消人工点击」。**任何取消人工点击的
决定，前置条件是 §1.10 断路器、§1.11 对账、ONT-022 成熟度门三者已上线并稳定运行。**
顺序反了，放权后的第一个数据事故日就是第一次生产事故——而且发生在没人点确认的那一天。
本版内取消任何动作类别的人工点击须人工决策并记录。

## 2. 软护栏（Soft Guardrails）

| 场景 | 条件 | 处理方式 |
| --- | --- | --- |
| 低置信度 | confidence < 0.70 | 升级为 MANUAL_REVIEW |
| 高风险 | risk_score > 0.70 | 调整幅度减半；如果仍超标则需 HIGH_RISK_REVIEW |
| 同一方向连续调整 | 同一目标同一方向≥3天 | 建议进入观察期或要求 MANUAL_REVIEW |

## 3. 数据降级策略

当某些数据不可用时，定义如何处理：

| 数据源 | 不可用状态 | 能否降级 | 降级行为 |
| --- | --- | --- | --- |
| 广告指标 | DATA_UNAVAILABLE | ✅ 可以 | 仅用旧记忆做摘要，不生成增长型动作 |
| 关键词表现 | DATA_PARTIAL | ❌ | 阻断推自然位动作 |
| 库存状态 | HARD_BLOCK | ❌ | 阻断提价、加预算、加广告位、扩词 |
| 广告位指标 | DATA_PARTIAL | ❌ | 阻断广告位加价 |
| 竞品洞察 | DATA_PARTIAL | ✅ 可以 | 跳过竞品修正，审核等级升一级 |
| 评价和退货 | DATA_PARTIAL | ❌ | 阻断TOS加价和激进扩词 |
| 组合预算数据 | DATA_UNAVAILABLE | ❌ | 阻断 Campaign 预算变更输出；仅允许 balance_maintain_no_action 和诊断建议 |
| 父 ASIN 目标预算 | DATA_UNAVAILABLE | ❌ | 所有预算动作升级为 MANUAL_REVIEW；Agent 不得自行假设 parent_target_daily_budget |

## 4. 幂等性

确保同一条建议不会重复执行。

| 规则 | 内容 |
| --- | --- |
| 键格式 | {父ASIN}::{对象ID}::{动作类型}::{日期YYYYMMDD} |
| 适用动作 | 提价、降价、预算变更、转低价捡漏、加否定词、加关键词、广告位调整 |

执行期不能只依赖“读取 `execute_status=PENDING`”。在任何广告写调用前，必须在同一
数据库事务内把本计划全部源 pending 原子认领为 `CLAIMED`；任一行认领失败则整批回滚
并拒绝下发。CREATE 的全部源 pending 必须参与认领，禁止以缺少 `pending_id` 的操作
绕过。异步提交后写 `SUBMITTED`，并把 ERP `taskId` 写入 `execute_msg`。
超过配置时限仍停留在 `CLAIMED` 的记录由巡检自动隔离为 `EXECUTION_UNCERTAIN`
并触发技术告警；该状态禁止自动重试，必须先与 ERP 请求日志或当前广告值对账。
组合预算执行没有 Campaign pending，必须使用 Agent 自有状态表持久化 decision、请求、
结构化 taskIds 和状态；成功响应缺 taskId、传输异常均进入 `EXECUTION_UNCERTAIN`。
同一 decision 的同一规范化组合预算请求必须使用唯一幂等键做数据库 CAS，禁止双击或
HTTP 重试重复下发。新建活动、否词和组合预算的网络异常都不能证明 ERP 未接单，
因此不得写成确定 `FAILED` 或自动重试。

## 5. 护栏覆盖矩阵（guardrail_coverage_matrix）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| guardrail_name | string | 护栏名称 |
| trigger_condition | string | 触发条件表达式 |
| coverage_type | hard_block / downgrade / review_only | 覆盖类型：hard_block=直接阻断；downgrade=降级执行但保留核心策略；review_only=保留提案并升级审核 |
| blocked_actions | list | 阻断动作列表（仅 coverage_type=hard_block 时有效） |
| downgraded_actions | list | 降级后动作列表（coverage_type≠hard_block 时必填，须说明幅度/比例/方向变化） |
| must_preserve_strategy | string | 必须保留的核心广告目的与策略方向（coverage_type≠hard_block 时必填，不得为空） |
| original_core_strategy_tags | list | SOP或触发规则原始命中的核心策略标签 |
| final_core_strategy_tags | list | 护栏裁决后的最终核心策略标签；coverage_type≠hard_block 时必须包含 original_core_strategy_tags |
| forbidden_replacement | list | 禁止替换关系，如 Traffic不得被Profit替代，Conversion不得被Profit替代；"维持"不是合法广告目的或核心策略标签 |
| downgrade_reason | string | 降级原因，须说明是预算、出价、扩词、广告位或Ranking强度降级 |
| hard_block_reason | string | 硬阻断原因，仅 coverage_type=hard_block 时必填 |
| review_level | enum | 审核等级 |

### 5.1 护栏覆盖矩阵样例

| guardrail_name | trigger_condition | coverage_type | original_core_strategy_tags | final_core_strategy_tags | blocked_actions | downgraded_actions | forbidden_replacement | must_preserve_strategy | review_level |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 起步期Traffic风险降级 | testing + 旺季前期/旺季 + SOP命中Traffic + ACOS/利润风险 | downgrade | Traffic, Conversion | Traffic, Conversion | 激进扩词、无限预算 | Traffic降级为低预算诊断型Traffic | Traffic不得替换为Profit | 保留Traffic测词路径和Conversion验证 | MANUAL_REVIEW |
| 推进期利润风控 | pushing + 旺季前期/旺季 + SOP命中Conversion/Ranking + ACOS或利润风险 | downgrade | Conversion, Ranking | Conversion, Ranking, Profit | 激进Ranking、TOS加价 | Ranking降级为少数强词保守推进；执行方向可降级为balance_maintain | Conversion/Ranking不得被Traffic/Profit替代 | 保留推进期核心承接和自然位保护 | MANUAL_REVIEW |
| 旺季末期尾部承接 | pushing/harvesting + 旺季末期 + 近7日订单>0 | downgrade | Conversion, Profit | Conversion, Profit | 大规模Traffic、激进Ranking | Traffic/Ranking逐步降预算；执行方向=balance_maintain | Conversion不得被Profit替代 | 保留尾部高效词和自然流量保护词 | MANUAL_REVIEW |

## 6. 库存不足策略（inventory_low_policy）

| 项目 | 内容 |
| --- | --- |
| 阻断动作 | 加预算、TOS加价、激进扩词、激进Ranking |
| 保留动作 | 高效Long-tail词、核心词保护、低成本Conversion承接、balance_maintain方向 |
| 清货期例外 | 按清货规则处理，不得输出无限预算 |

## 7. 退货与评价风险策略（review_return_risk_policy）

| 项目 | 内容 |
| --- | --- |
| 触发条件 | 30天退货率≥30% 或 评分<3.8 |
| coverage_type | downgrade；仅当评分<3.5且退货率≥40%，或广告资格异常时升级为hard_block |
| 阻断动作 | 增长型Traffic、TOS加价、激进提价、激进Ranking |
| 允许动作 | 低预算诊断型Traffic/Conversion、精准词承接、Long-tail承接、核心自然位保护词 |
| 必须保留策略 | 若SOP已命中Conversion/Ranking则必须保留；退货风险仅可降低执行强度 |
| 禁止行为 | 不得将推进期SOP主策略改写为Traffic+Profit；不得因退货率≥30%删除Conversion、Ranking |
| 输出要求 | 须写明"退货风险触发：增长型动作被阻断，SOP核心策略保留并降级执行" |

## 8. Ontology 补充引用

> 本文件 §1.8「对象级非法动作阻断」与 [20-亚马逊广告ontology补充 §9 推理与校验规则](20-亚马逊广告ontology补充.md#9-推理与校验规则) 对齐，应将以下 ontology 规则作为硬校验：
> - **ONT-001**：SearchTerm 禁止直接 Bid / Budget / Placement 动作
> - **ONT-002**：broad_keyword / phrase_keyword / auto_discovery 禁止 Placement 调整
> - **ONT-003**：缺 organic_rank_signal 时阻断 push_natural_rank
> - **ONT-004**：缺 inventory_status 时阻断所有增长型动作
> - **ONT-005**：缺 placement_report 时仅阻断 placement_adjustment
> - **ONT-013**：eliminate_to_low_bid_pool 目标组必须为 low_bid_retention_group
> - **ONT-014**：low_bid_retention_group 固定预算 $1、Bid $0.20
>
> 若动作对象与 Ontology 允许对象不一致 → `ontology_validation_status = blocked`，写入 `ontology_rule_refs`。
