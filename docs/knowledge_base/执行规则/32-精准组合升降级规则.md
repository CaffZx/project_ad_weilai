# 精准组合升降级规则（exact_portfolio_transition_rules.yaml）

> **适用范围**：`exact_core_group`（精准主力组）与 `exact_testing_group`（精准测试组）之间的
> 升组、降级，以及从这两组进入 `low_bid_retention_group`（低价捡漏组）的条件。
>
> **本文与 23号 的分工**：`23号§3.5/§3.6/§3.7` 定义了升组条件与三级回落的**定性框架**；
> 本文把 `§3.7` 的三级回落**量化为可判定的布尔式**，并补 23号 没有的两件事：
> ① 高优先级关键词保护的否决规则；② 精准测试组内两类活动（降级来的 / 原生新建的）的不同退出条件。
>
> **来源**：运营《精准主力组与精准测试组组合定义》，经 v3.4.0 评审修订后落地。修订项见 §7。

---

## 1. 精准主力组（`exact_core_group`）

### 1.1 含义与职责

精准主力组**只允许已完成稳定验证的单关键词精准活动进入**。核心任务：

- 推动关键词自然位提升，获取更高的自然流量；
- 承接已验证有效的精准关键词；
- 保护与产品标题、后台 Search Term、核心卖点或自然位相关的关键词。

精准主力组允许使用高于精准测试组和广泛自动组的预算与 Bid（`23号§8.1`）。

**组合身份由验证状态决定，不由预算金额决定**（`budget_groups.yaml` identity_rule）。
加预算不能替代验证 —— 这是 v3.3.0 明确纠正过的常见错误，本文继承。

### 1.2 准入条件（三条，全部满足）

以 `23号§3.5` 为唯一权威。**只有两条**：

| # | 条件 | 口径 |
| :-: | --- | --- |
| ① | 连续 3 个**完整站点自然日**，每日花费均达到门槛 | 门槛按 `03号§10`：固定 `$5.00`，每日均须严格大于（v3.4.3 已撤回 C-08） |
| ② | 3 日**汇总** ACOS < 目标 ACOS | 汇总口径，**不是**日 ACOS 平均值 |
| ③ | 近 7 天自然排名相较前一个 7 天周期提升 | 自然位上升是精准主力组的必要准入条件 |

**三日必须连续且均为已结束的完整站点自然日**（`app/domain/advertising.py::evaluate_exact_main_validation`）。

> 自然位条件按两个完整 7 天窗口比较：近 7 天自然排名必须较前一个 7 天周期提升。
> 自然位数据缺失或窗口不完整时，不得自动升组，转 `MANUAL_REVIEW`。

### 1.3 升组时的优先级排序

当多个精准测试活动同时满足 §1.2 但可分配预算不足以全部升组时，按 `23号§3.5` 的四级优先级：

| 优先级 | 判断标准 |
| :-: | --- |
| 1 | `natural_traffic_priority_score` 最高（`23号§3.1A`） |
| 2 | 分数接近时，当前自然位更接近第 1 页 / Top20 的词 |
| 3 | 再优先词更精准 / 相关性更强（R1 优于 R2） |
| 4 | 最后比较 ACOS、订单数、CVR |

**不得平均加预算**（`GROUP-BUDGET-006`）—— 平均分配会稀释推词预算，削弱自然位推进效果。
未升组的活动继续留在精准测试组小预算观察。

## 2. 精准主力组的三级回落

对应 `23号§3.7` 的定性三级，本节量化。**判定顺序：轻度 → 中度 → 严重，命中即止。**

所有 ACOS 比较均以目标 ACOS 倍数为基准：目标 ACOS×1.5 对应轻度回落，目标 ACOS×2 对应中度回落。

### 2.1 前置：高优先级关键词保护否决（先判这一条）

若关键词经确认属于以下任一类型，**直接跳过 §2.3 与 §2.4，最多只能执行 §2.2 的处理**：

- 产品标题相关词
- 后台 Search Term 相关词
- 产品核心卖点相关词
- `29号` 判定 `is_core_keyword = true`

**保护词的处理方式（v3.4.2 修订：从「绝对禁止降级」改为「分级从严」）：**

- **可以降级，但门槛比普通词更严，且按产品阶段分级**（见 §2.1A）；
- 优先动作仍是降 Bid / 降预算（P0 核心词额外受 `15号§1.3` 的单次降幅 ≤5%
  且禁连续两次下调约束），降级是**从严门槛都满足后**才允许的后续动作；
- 继续作为相关性关键词低强度观察；
- 重点排查 Listing、价格、库存、评价与转化承接（`14号§15` 页面承接排查清单）；
- **不得因单轮短期无订单、单日 ACOS 超标或自然排名波动直接淘汰**
  —— 必须走 §2.1A 的连续观察期。

> **为什么 v3.4.2 改口径**：v3.4.0 把这四类词从「不被否词」（`ONT-RUNTIME-004`）
> 扩大为「不得降级、不得进低价捡漏组」，是过度保护，产生两个后果：
> ① 与「立即退出时全部精准迁入低价捡漏组」直接相撞（代码实际按立即退出执行，
> 于是这条保护规则形同不存在，属于典型的「写了但不生效」）；
> ② 一个标题词只要一直不转化，就会永久占用主力组预算而无退出通道。
> 修订后的口径是**保护它不被草率降级，而不是保证它永不降级**。
> 立即退出/控制清货等收缩类经营模式按 `09号` 裁决链决定方向，覆盖本节保护
> （模式决定方向、阶段决定力度），保护词随同退出，但退出动作单独列出可审计清单。

### 2.1A 保护词降级的从严门槛（按产品阶段分级）

普通词满足 §2.2/§2.3 的回落触发式即可降级；保护词必须**同时**满足以下三条：

| 条件 | 普通词 | 保护词（从严） |
| --- | --- | --- |
| 连续观察期 | 2 个 3 日评估周期 | **按下表分级** |
| 期间已执行的温和动作 | 无要求 | **必须已完成 ≥1 轮降 Bid/降预算且无改善** |
| 页面承接排查 | 不要求 | **必须已完成 `14号§15` 排查且排除 Listing/价格/库存/评价因素** |

**分级观察期（按产品阶段，均为成熟窗口径见 `03号§12.2`）：**

| 产品阶段 | 保护词降级观察期 | 依据 | 状态 |
| --- | --- | --- | --- |
| `testing` 测试期 | 4 个 3 日周期（12 天） | 测试期本就在验证词效，最需要给时间 | ⚠️ 需确认 |
| `pushing` 推进期 | 4 个 3 日周期（12 天） | 推进期广告要托底自然位，保护词退出代价最大 | ⚠️ 需确认 |
| `maintaining` 维持期 | 3 个 3 日周期（9 天） | — | ⚠️ 需确认 |
| `harvesting` 收割利润期 | 2 个 3 日周期（6 天） | 以利润为先，从严让位于效率 | ⚠️ 需确认 |
| `liquidating` 清货期 | 不适用 | 清货类模式按 `09号` 覆盖本节，直接执行退出 | ✅ 已确认 |

**审核等级**：保护词的降级动作一律 `MANUAL_REVIEW`（即使门槛全部满足），
并在动作里输出命中的保护类型与已完成的从严条件清单，供审核人复核。

> 观察期数值全部 `needs_review`：分级方向（推进期最长、收割期最短）是按
> 「广告托底自然位的经营价值」排的，但具体天数没有经营验证依据，
> 需要运营按实际数据拍板，或在决策日志积累后按 `01号` 阈值状态机升级为 `confirmed`。

### 2.2 轻度回落 → 留在精准主力组

**触发式：**

```text
轻度回落 = 【3日汇总 ACOS > 目标 ACOS】
        AND 【3日汇总 ACOS ≤ 目标 ACOS × 1.5】
        AND 【近 7 天有订单 > 0】
```

**处理：**

- 保留在精准主力组；
- 降低 Bid 或预算（幅度按 `19号§3/§4` × `15号§1.2/§2` 系数）；
- 继续观察 7–14 天；
- **不得直接降级或淘汰。**

**保留判断的加权因子**：若该词自然位在上升（`page_uplift_score > 0`），即使 ACOS 已接近容忍上限，
也优先保留并维持 Bid（`GROUP-BUDGET-006`：ACOS 是成本约束而非第一优先级）。

### 2.3 中度回落 → 降级至精准测试组

> **v3.4.0 关键修订**：运营原稿此段是自然语言堆叠，AND/OR 不可解析（至少三种读法）。
> 已重写为显式布尔式。

**触发式：**

```text
中度回落 = 【ACOS 条件】
        AND （【转化条件】 OR 【订单衰减条件】）
        AND 【自然位条件】
        AND NOT 【§2.1 保护否决】

  【ACOS 条件】     连续 2 个 3 日评估周期，3 日汇总 ACOS 均 > 目标 ACOS × 1.5 且 ≤ 目标 ACOS × 2
  【转化条件】     近 7 天点击 ≥ 10 且 近 7 天订单 = 0
  【订单衰减条件】 近 7 天订单 < 前一个 7 天周期订单 × 80%
  【自然位条件】   近 7 天自然排名下降 OR 连续 7 天无自然位改善
                   （organic_rank 缺失时本条视为不满足 → 不降级，转 MANUAL_REVIEW）
```

**处理：**

- 执行 `demote_to_exact_testing`（`30号§3.2` 的复合动作：`move_portfolio` + `adjust_budget` + `adjust_bid`）；
- 降低预算和 Bid；
- 写入 `demoted_at` = 本次降级日期（§2.4 的观察窗起算点）；
- 重新完成 §1.2 的连续三日验证才能回到主力组 —— **不能用恢复预算代替验证**（`23号§3.7`）；
- **降级不等于淘汰。**

**必须同步做预算回算**（`21号§5A`、`GROUP-BUDGET-001/002`）：降预算释放的金额计入
`other_campaign_budget_decrease`，回算组合预算与父 ASIN 总预算，否则 `GROUP-002` 阻断输出。

### 2.4 严重回落 → 转入低价捡漏组

**只能从精准测试组进入**，主力组不可一步跨到低价捡漏组（必须先经 §2.3 降级）。

精准测试组内有两类活动，观察窗起算点不同：

| 类型 | 来源 | 观察窗起算 |
| --- | --- | --- |
| **降级型** | 从精准主力组 §2.3 降级而来 | `demoted_at` 起算，≥7 天 |
| **原生型** | 从广泛/自动/词组提词直接新建（`23号§3.4`、`31号§10`），从未在主力组待过 | `campaign_created_at` 起算，≥14 天（长尾/低流量可延至 21 天） |

> **v3.4.0 关键修订**：运营原稿的前置是「活动降级至精准测试组后…降级后继续观察至少 7 天」，
> 只覆盖降级型。原生型没有「降级日」，按原稿字面**永远无法退出**，再叠加原稿
> 「不得因数据暂时不足直接转入低价捡漏组」，等于给精准测试组开了一个永不退出的口子，
> 会持续累积僵尸活动并常年占用预算。本节区分两类来源解决此问题。

**触发式（两类共用）：**

```text
严重回落 = 【观察窗已满】（降级型 ≥7天 / 原生型 ≥14天，长尾 ≤21天）
        AND 【近 7 天点击 ≥ 10 OR 近 7 天花费 ≥ 无单花费门槛（03号§7 目标CPA口径）】
        AND 【近 7 天订单 = 0】
        AND 【近 7 天自然排名持续下降 OR 无自然位价值】
        AND 【已完成 21号§3 精准类诊断路径且仍无改善】
              （降广告位加价 → 观察3天 → 降基础 Bid → 仍无改善）
        AND NOT 【§2.1 保护否决】
```

**处理（`eliminate_to_low_bid_pool`，`30号§3.1` 复合动作）：**

| 参数 | 执行值 |
| --- | --- |
| 组合 | `low_bid_retention_group` |
| 活动日预算 | `$1.00`（`ONT-014` 锁定） |
| Target 基础 Bid | **`min(current_bid, 0.20)`** |
| 三个广告位加价 | 全部清零 0% |
| 审核等级 | `HIGH_RISK_REVIEW`（不可降级） |

> **`min(current_bid, 0.20)` 的必要性（C-10）**：v3.3.0 的 `ONT-014` / `GROUP-004A` 写死
> 「`proposed_bid != 0.20` 即 block」。遇到本来 Bid = $0.15 的词，转组时会被**强行抬到 $0.20**，
> 等于给一个正在淘汰的词加价 33%。这是运营稿抓到的真实漏洞，本版采纳并已同步修改
> `ONT-014`、`GROUP-004A`、`03号§8`、`15号§1.4`、`21号§4`。

**保留观察，不立即删除。** 进入低价捡漏组 ≥14 天后按 `21号§7` 复评是否重新启用
（`reactivate_budget_only` / `reactivate_with_calibrated_bid`）。

## 3. 精准测试组（`exact_testing_group`）

### 3.1 含义与职责

精准测试组是**新关键词的验证池**，承担从广泛自动组、自动广告、词组广告或搜索词报告跑出的
有效词的精准验证。核心任务：

- 验证新关键词是否具备真实转化能力；
- 验证关键词是否能稳定承接花费；
- 验证关键词 ACOS 是否达到经营目标；
- 筛选具备长期经营价值的关键词升入精准主力组。

**精准测试组不是精准主力组的低预算版本，而是独立的验证阶段。**
（与 `budget_groups.identity_rule` 一致：预算金额不改变组合身份。）

### 3.2 准入条件

以 `23号§3.4` 为唯一权威（三通道，见 `31号§10`）。本节只列结构性约束：

| # | 条件 |
| :-: | --- |
| ① | 活动必须建立为**单关键词精准活动**（多关键词 EXACT 按 `ROUTE-002` 直接进低价捡漏组） |
| ② | 关键词来源为 `28号§1` 的来源码：`SRC_CONVERTED` / `SRC_AUTO_CLICKED` / `SRC_BROAD_DERIVED` / `SRC_AUTO_BROAD_TERM` |
| ③ | 满足 `23号§3.4` 三通道之一：订单通道 / 词根通道 / CVR 通道（CVR 通道强制 `HIGH_RISK_REVIEW`） |
| ④ | 相关性达 R1（`28号§2`）；候选词必须存在于本轮输入数据（`28号§1` 词保真） |
| ⑤ | 无对应精准活动或同词根精准承接活动 |

> **v3.4.0 修订**：运营原稿 §二.2 用「有订单、**或** ACOS≤目标、**或** 与标题ST强相关」的或关系，
> 比 `23号§3.4` 宽松得多，且与运营自己的另一份文档（doc1 §六 写「订单≥3 **且** ACOS≤目标」）
> 互相冲突。已统一为引用 `23号§3.4` 的三通道，其中「与标题ST强相关」的意图由
> `31号§11` 的保护型精准测试承接（那才是它的正确位置：相关但数据未达标 → 保护观察）。

### 3.3 退出规则

| 方向 | 条件 | 动作 |
| --- | --- | --- |
| 向上：升入精准主力组 | 满足 §1.2 两条 | `promote_to_exact_core` |
| 向下：转入低价捡漏组 | 满足 §2.4 | `eliminate_to_low_bid_pool` |
| 留在原组 | 未达升组条件且未达 §2.4 | 继续小预算观察 |

**数据不足时不得判失败**：暂时没有足够花费、点击或订单数据的活动，保持小预算观察，
不得过早判定为无效（`18号§4` 样本不足条款）。但这条**不构成永久豁免** ——
原生型活动的 §2.4 观察窗从创建日起算，满窗且走完诊断后仍可退出。
