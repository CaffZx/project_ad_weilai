# 广告执行调整流程（ad_execution_flow.yaml）

串联触发规则、动作规则、广告位规则、安全护栏、风险评分、输出规范，定义 Agent 完整的执行判断顺序。

> v3.3.0经营模式硬规则：当 `operating_mode=immediate_exit` 时不进入LLM博弈判断；
> 单关键词/多关键词精准活动统一迁入低价捡漏组，广泛/词组/自动活动关闭，
> 禁止新建活动。所有动作仍须人工确认并经过ERP护栏。

---

## 1. 广告活动类型判定规则

**Agent 在判断新增、淘汰、调整之前，必须先判断广告活动类型。** 不同类型的可调整项不同。

### 类型分类表

| 广告活动类型 | 归类规则 | 可调整项 | 禁止调整项 | 核心运营目的 |
|-------------|---------|---------|-----------|------------|
| 精准广告 | EXACT（精准匹配）关键词广告 | Campaign Budget、Target Bid、Placement（头部/其他/商品）、`eliminate_to_low_bid_pool`、关闭 Target | **禁止否词**（`ONT-015`，阻断时须给 `recommended_next_step`）；不能盲目扩泛词 | 承接已验证词、推自然位、稳定转化、控制ACOS |
| 广泛广告 | BROAD / PHRASE / AUTO | Budget、Base Bid、Search Term 否词、提取有效词、补新广泛测试方向、**`stop_campaign`** | 不做 Placement 调整；**不得挪入低价捡漏组**（`ONT-016`） | 打开词池、获取搜索词、筛选有效词根、补充流量入口 |
| 商品定投广告 | PRODUCT_TARGETING（商品/类目投放） | Budget、Target Bid、Placement（**PP 优先**，`ONT-010`）、`stop_campaign` | 不套三日验证；**不得挪入低价捡漏组** | 竞品截流、类目拓展、防守自家页面（`08号`） |

> Phrase（词组匹配）默认归入广泛广告策略处理，不做广告位调整。

### 类型判定字段

| 判断字段 | 精准广告取值 | 广泛广告取值 | Agent 动作 |
|---------|------------|------------|----------|
| match_type | EXACT | BROAD / PHRASE | 先按 match_type 判定 campaign_type；AUTO 不属于 match_type |
| campaign_type | exact_keyword | broad_keyword / phrase_keyword / auto_discovery | 输出时必须带上 campaign_type；自动广告用 auto_discovery 表达 |
| placement_adjustment | 允许 | 不允许 | 广泛/词组广告该字段填写 N/A |
| negative_search_term | **禁止**（`ONT-015` hard_block）。阻断时必须输出 `recommended_next_step`：降 Bid 观察 / 暂停该 Target / 迁入低价捡漏组（v3.4.2 口径，见 `22号§2.4`） | 必须作为常规优化动作 | 广泛广告每轮都要读取搜索词报告 |
| keyword_extraction | 从精准表现中提炼主推词或保护词 | 从搜索词报告提取精准词、长尾词、词根 | 广泛跑出好词后转精准承接 |

## 2. 13 步 AI 广告调整总流程

### 核心原则

- AI 不能直接从"ACOS高"跳到"降 Bid"或"淘汰广告活动"。必须先判断整体问题，然后分广告类型诊断。
- 精准广告：做 Budget、Bid，允许读取并调整 Placement，可输出头部/商品/其他的当前值和建议值。
- 广泛广告/词组广告：不做 Placement 调整，只做 Budget、Bid、Search Term 否词、提词、挪组和低价捡漏组观察。
- 如果关键词承担 Ranking（冲排名）任务，即使 ACOS 短期偏高，也不能直接降 Bid 或移入低价捡漏组。
- 输出必须让运营能看懂：为什么调、调哪里、调多少、看几天、什么结果算有效、什么结果需要回调或进入低价捡漏组。

### 流程步骤

| 步骤 | Agent 需要做什么 | 输出结果 |
|------|----------------|---------|
| Step 1 | 读取标签快照（tag_snapshot）：产品定位、产品阶段、淡旺季、广告目的、广告方向、关键词类型、特殊场景 | 确认当前产品的策略背景 |
| Step 2 | 检查数据质量（data_quality）：确认库存、广告指标、关键词数据、广告位数据、竞品数据是否完整 | 关键数据缺失则进入 BLOCKED |
| Step 3 | 运行安全护栏（guardrails）：先判断库存不足、高退货、低评分、缺广告位数据等风险 | 阻断不安全的增长动作 |
| Step 4 | 判断广告目的（ad_purpose）：Traffic / Conversion / Ranking / Profit | 得到当前广告大方向 |
| Step 5 | 判断广告方向（ad_direction）：expand_keywords / push_natural_rank / optimize_acos / balance_maintain | 确定今天主要动作类型 |
| Step 6 | 判断广告活动类型（campaign_type）：精准广告 或 广泛广告（参见本文 §1） | 决定后续是否允许广告位调整 |
| Step 7 | 分层诊断（layered_diagnosis）：ASIN整体 → 广告组合 → Campaign → Ad Group → Keyword/Target → Search Term；仅精准广告继续读取 Placement | 找出问题具体在哪一层 |
| Step 8 | 判断投放效果（performance_evaluation）：有效 / 低效 / 样本不足 / 异常 / 护栏阻断（参见本文 §3） | 决定是否新增、淘汰或调整 |
| Step 9 | 生成建议（generate_proposal）：组合成三类运营建议——新增广告活动 / 淘汰广告活动 / 调整广告活动（参见本文 §4、§5、§6） | 输出运营可理解的动作表 |
| Step 10 | 运行 Ontology 合法性校验（ontology_validation）：检查 object_class、campaign_type、action_type 是否匹配，校验证据源是否充分。校验依据：[20-亚马逊广告ontology补充 §3 广告对象](20-亚马逊广告ontology补充.md#3-sponsored-products-广告对象-ontology) + [§7 动作合法性](20-亚马逊广告ontology补充.md#7-动作合法性-ontology) + [§9 推理与校验规则](20-亚马逊广告ontology补充.md#9-推理与校验规则) | 阻断非法动作并写入 ontology_rule_refs |
| Step 11 | 运行组合预算回算（budget_group_reallocation）：按 ParentASIN / AdBudgetGroup / Campaign 三层回算预算 | 输出 portfolio_budget_summary 和 budget_groups |
| Step 12 | 计算风险评分（risk_score）：根据动作幅度、库存、退货、评分、数据质量、竞品压力计算风险分 | 确定审核等级 |
| Step 13 | 输出 ERP 格式（output_schema）：每条建议必须包含当前值、建议值、变化幅度、证据、KB参数、预期影响、风险原因、审核等级 | 给 ERP 审核和执行 |

## 3. 数据读取时间规则

| 时间窗口 | 读取数据 | 用途 | 是否可直接决策 |
|---------|---------|------|--------------|
| 近1天 | 花费、订单、ACOS、预算利用率、异常点击 | 判断是否有单日异常、预算是否突然花满或花不出去 | 不能单独淘汰，只能轻微调整或标记异常 |
| 近3天 | ACOS趋势、CVR趋势、预算利用率、点击质量、订单趋势 | 判断趋势是否成立 | 可作为小幅调 Budget 或 Bid 的依据 |
| 近7天 | Campaign有效性、Keyword有效性、Search Term沉淀、精准广告 Placement 效果、Organic Rank 变化 | 判断活动是否保留、放量、降级、淘汰、新增承接 | **主要决策窗口** |
| 调整后第1天 | 花费、订单、ACOS、曝光、点击 | 判断调整后是否跑出流量 | 只判断是否起量 |
| 调整后第3天 | ACOS、CVR、预算利用率、点击、订单 | 判断调整是否初步有效 | 可做二次微调 |
| 调整后第7天 | 自然排名、自然订单、有效词数、广泛广告否词后搜索词质量 | 判断是否推动自然流量或改善词池质量 | 决定继续、加码或回调 |

## 4. 投放效果评估规则

### 有效广告活动判断

| 判断类型 | 触发信号 | Agent 动作 |
|---------|---------|----------|
| 转化有效 | 近7天有订单，ACOS ≤ 目标 ACOS | 保留，优先加 Budget，Bid 不轻易下调 |
| 预算有效 | 预算利用率 ≥ 70%，ACOS ≤ 目标 ACOS，库存天数 ≥ `03号§5` 健康线 | 可触发 campaign_budget_increase |
| 排名有效 | 自然排名上升，ACOS ≤ 目标ACOS倍数阈值，CVR 不下降 | 精准/商品定投可进入 Ranking 或广告位加价；广泛类只保留预算/Bid，不做广告位调整 |
| 词池有效 | 广泛广告跑出有效 Search Term 或有效词根 | 提取新增 Exact 或 Long-tail 承接 |
| 广告位有效 | 精准或商品定投中某广告位有订单且 ACOS ≤ 目标 ACOS | 对该 Placement 保留或加价（TOS 上限按 `03号§6.2` 定位分档）；广泛类不适用 |
| 自然流量有效 | 自然单或自然排名上升 | 不轻易降 Bid 或移入低价捡漏组 |

### 低效广告活动判断

| 判断类型 | 触发信号 | 优先动作 |
|---------|---------|---------|
| ACOS 低效 | 3天 Keyword ACOS > **目标ACOS倍数阈值**（`15号§4`），且 7天订单 = 0 或订单不足 | bid_down_for_acos |
| 搜索词低效 | 广泛/词组/自动广告中，**先判相关性**（`31号§4`）：明显不相关（R3/R4）→ 否词；相关但无转化 → 降 Bid 观察，不否词 | 按 `31号§4` 四档分支 |
| 活动整体低效 | 连续3天 ACOS > **目标ACOS倍数阈值**，或低转化、低相关 | campaign_budget_decrease；精准类严重时 `eliminate_to_low_bid_pool`（`32号§2.4`），广泛/商品定投类走 `stop_campaign` |
| 广告位低效 | 仅精准广告，近3天某广告位花费 ≥ $5、点击 > 7次、无订单 | 先降该广告位加价；若无广告位加价则降 Bid，不直接淘汰 Campaign |
| 不相关流量 | 搜索词明显不相关 | 广泛/词组/自动广告可在保护标题词、后台ST词、高相关词和历史转化词后否词；精准广告不否词，只能降 Target Bid 或关闭 |

### 样本不足不能直接判差

| 情况 | Agent 处理 |
|------|----------|
| 新 Campaign 不足3天 | 不退出、不移组，只看曝光、点击、花费是否跑出 |
| 曝光少、点击少、花费少 | 优先判断 Bid 是否过低、关键词搜索量是否太小 |
| Long-tail 点击少 | 观察周期可延长到 7–14 天 |
| 测试期样本不足 | 不直接否词，不直接淘汰 |
| 缺 Organic Rank 数据 | 不能做 Ranking，只能转 Conversion；若不适合转化动作，则执行 balance_maintain 方向观察 |
| 缺 Placement 数据 | 仅阻断精准广告 placement_adjustment；不影响广泛/词组广告的预算、Bid、否词判断 |

## 5. 新增广告活动输出规范

### 触发场景

| 触发场景 | 判断逻辑 |
|---------|---------|
| Traffic 或 expand_keywords | 需要打开流量入口，补充曝光和搜索词样本 |
| 预算利用率低 | 现有词池无法消耗预算，需要新增 Keyword 或 Campaign |
| 订单未达目标但 ACOS 可控 | 需要新增有效词承接订单 |
| BROAD/PHRASE/AUTO 跑出有效 Search Term | 需要新建 EXACT 或 Long-tail 承接 |
| 有效词根明确 | 围绕有效词根扩展同类词 |
| 竞品反查有高相关词 | 可新增竞品词 |
| 淘汰低效活动后 | 必须判断是否补新活动，避免流量盘缩小 |
| 旺季前期或旺季 | 提前新增 Generic、Long-tail、Competitor、Custom 词池 |

### 新增活动必须输出的字段

| 字段 | 中文解释 | 填写要求 |
|------|---------|---------|
| proposal_type | 建议类型 | 固定填写：新增广告活动 |
| action_type | 动作类型 | create_campaign / create_ad_group |
| campaign_name | 广告活动名称 | 命名规则：词+类型+ASIN，方便 ERP 创建 |
| campaign_type | 广告活动类型 | 必须先判断：EXACT=精准广告；BROAD/PHRASE/AUTO=广泛广告 |
| keywords_or_targets | 关键词或投放对象 | 必须列出具体词或 ASIN |
| match_type | 匹配方式 | EXACT / BROAD / PHRASE，PHRASE 默认按广泛广告策略处理 |
| proposed_daily_budget | 建议日预算 | 必须给具体金额（参见 `16-新增活动规则.md §2`） |
| proposed_base_bid | 建议基础竞价 | 必须给具体数值（参见 `16-新增活动规则.md §3`） |
| primary_placement | 主投广告位 | 仅精准广告必填（头部/其他/商品）；广泛/词组广告填 N/A |
| placement_adjustment | 广告位加价 | 仅精准广告可输出；广泛/词组广告禁止输出 |
| negative_strategy | 否词策略 | 新增广泛/词组广告必须设置后续否词观察规则 |
| reason | 新增理由 | 必须说明来源：搜索词/有效词根/竞品/历史有效词/节日趋势词等 |
| evidence | 证据链 | 来源、相关性、预期匹配方式、建议 Bid 理由 |
| review_level | 审核等级 | 默认 MANUAL_REVIEW；低风险历史有效词可 AUTO_APPROVED |

### 新增活动广告位策略（首次布局规则）

| 新增活动类型 | 广告类型归类 | 广告位规则 | 运营备注 |
|------------|------------|---------|---------|
| `match_type=BROAD`（广泛匹配扩词活动） | 广泛广告 | 不做 Placement 调整；primary_placement=N/A | 低成本拿搜索词样本，重点看预算、Bid、搜索词质量和否词 |
| `match_type=PHRASE`（词组匹配活动） | 广泛广告 | 不做 Placement 调整；primary_placement=N/A | 归入广泛广告，比 BROAD 更收窄但仍不做广告位调整 |
| Auto（自动测词） | 广泛广告 | 不做 Placement 调整；primary_placement=N/A | 先看系统匹配和 Search Term 质量，后续提取精准词 |
| Long-tail（长尾词）Exact 投放 | 精准广告 | 首次扩词布局暂不推荐广告位调整 | 长尾词相关性高，先跑 Bid/预算数据 |
| Exact（精准出单词） | 精准广告 | 首次扩词布局暂不推荐广告位调整 | 词已验证有效，先稳定 Bid 和预算 |
| Ranking Keyword（冲排名词） | 精准广告 | 首次扩词布局暂不推荐广告位调整 | 用于推动自然排名，先跑基础数据再加广告位 |
| Competitor（竞品词） | 精准承接 | 首次扩词布局暂不推荐广告位调整 | 对比型流量，先观察转化 |
| Brand（品牌平替词） | 精准低价截流 | 首次扩词布局暂不推荐广告位调整 | 低成本借品牌流量，不抢广告位 |

## 6. 淘汰广告活动输出规范

### 淘汰判断规则

| 条件 | 是否进入淘汰 | 说明 |
|------|------------|------|
| 7天 CVR=0 + 7天花费 ≥ `03号§7.3` 淘汰花费门槛 + 对自然排名无支持 | **仅 EXACT** 可进低价捡漏组 | 低预算低 Bid 捡漏。广泛/商品定投走 `stop_campaign` |
| 精准广告 Placement 花费高无单 | 不直接淘汰活动 | 先降该广告位加价；活动整体低效再考虑低价捡漏组 |
| 广泛/词组/自动高点击无单 | 先判相关性（`31号§4`）→ 不相关则否词 → 降 Bid/预算 → 仍无改善才 `stop_campaign` | 必须走搜索词治理，不能跳过否词直接退出 |
| 新活动不足3天 | 不能淘汰 | 样本不足 |
| 核心词自然位上升 | 不能淘汰 | 可能承担 Ranking 任务 |
| Listing 优化中 | 不做大动作 | 按 balance_maintain 方向观察 |

### 淘汰建议必须输出的字段

| 字段 | 中文解释 | 填写要求 |
|------|---------|---------|
| proposal_type | 建议类型 | 固定填写：淘汰广告活动 |
| action_code / physical_action_code | 动作码 | 按 `30号§1` 成对输出。EXACT 用 `eliminate_to_low_bid_pool`；广泛/商品定投用 `stop_campaign`。**均不使用 `pause_campaign`** |
| campaign_name | 需要淘汰的活动 | 必须明确 |
| portfolio_or_group | 所属广告组合 | 必须明确，方便后台定位 |
| target_low_bid_retention_group | 目标低价捡漏组 | 必须给出低价捡漏组名称；若没有则建议新建低价捡漏组 |
| proposed_daily_budget | 淘汰后预算 | 默认 $1；以后台可执行最低值为准 |
| proposed_base_bid | 淘汰后 Bid | **`min(current_bid, 0.20)`**，必须给出计算过程（`03号§8.1`） |
| lookback_window | 判断时间窗口 | 近7天 |
| current_spend_7d | 近7天花费 | 必须给出 |
| current_orders_7d | 近7天订单 | 必须给出 |
| current_cvr_7d | 近7天转化率 | 必须给出 |
| organic_rank_support | 自然位支持 | 必须判断：是 / 否 / 缺数据 |
| eliminate_reason | 淘汰理由 | 高花费无单、7天CVR=0、不相关、无自然位支持、无词池沉淀 |
| replacement_campaign | 替代活动 | 是否已有替代活动，避免流量盘被砍空 |
| need_new_campaign | 是否需要补新活动 | 若淘汰后词池变窄，应同步建议新增 |
| review_level | 审核等级 | 默认 HIGH_RISK_REVIEW |

## 7. 调整广告活动输出规范

### 精准广告调整规则

| 调整层级 | 适用场景 | 建议动作 | 审核逻辑 |
|---------|---------|---------|---------|
| Budget | 预算利用率 ≥ 70% + ACOS ≤ 目标 ACOS + 库存天数 ≥ `03号§5` 健康线 | campaign_budget_increase | 默认 MANUAL_REVIEW；增幅>30% 为 HIGH_RISK_REVIEW |
| Budget | 3天 ACOS > **目标ACOS倍数阈值**（`15号§4`） | campaign_budget_decrease | 默认 AUTO_APPROVED；主力精准活动需 MANUAL_REVIEW |
| Bid | ranking_opportunity 触发 | bid_up_for_ranking | 提价 ≤10% 可 AUTO_APPROVED；>20% 需 HIGH_RISK_REVIEW |
| Bid | 3天 Keyword ACOS > **目标ACOS倍数阈值** 且 7天订单 = 0 或订单不足 | bid_down_for_acos | 核心词降 Bid 必须 MANUAL_REVIEW；P0 核心词降幅 ≤5%（`15号§1.3`） |
| Placement | TOS 有单且 ACOS ≤ 目标 ACOS；自然位推进词 | 保持或提高头部加价（上限按 `03号§6.2` 定位分档） | 仅精准与商品定投可执行 |
| Placement | TOS/PP 花费高但无单 | 降低对应广告位加价，不一定降基础 Bid | 先调广告位，不直接淘汰活动 |
| Placement | 库存不足、高退货、低评分、缺广告位数据 | 阻断头部/商品加价 | BLOCKED 或 MANUAL_REVIEW |

### 广泛广告/词组广告调整规则

| 调整层级 | 适用场景 | 建议动作 | 审核逻辑 |
|---------|---------|---------|---------|
| Budget | 预算花不出去，曝光/点击不足 | **按 `19号§4.1` 三步**：① 瓶颈判断（`23号§4.3`）② `28号§5` 四档填补 ③ 仍无法消化才降预算 | 不可因预算低直接开广告位加价；组合层瓶颈时不得调活动层 |
| Budget | 预算花完但 ACOS 高、搜索词质量差 | 降低预算或把预算转给有效词/精准承接 | 非主力广泛可 AUTO_APPROVED；主力广泛 MANUAL_REVIEW |
| Bid | 曝光不足但词高度相关 | 小幅提高 Bid，观察1–3天 | 提 Bid 幅度建议 ≤15% |
| Bid | 点击多无单或搜索词质量差 | 按 `31号§4` 四档分支降 Bid；**不得转低价捡漏组**（`ONT-016`），需要退出时 `stop_campaign` | 降 Bid 前必须先判相关性、检查是否应先否词 |
| Search Term | 明显不相关词 | add_negative | 广泛/词组广告必做 |
| Search Term | 高点击无单词 | 先判断相关性（`31号§4`）；R3/R4 否词，R1/R2 降 Bid 或观察 | 点击 ≥10 预警；≥20 强优化（与 `19号§8`、`22号§3.3` 一致） |
| Search Term | 有订单、有 CVR、有词根价值 | 提取为 Exact 或 Long-tail 承接 | 提词后原广泛保留测词功能 |
| Placement | 任何广泛/词组广告场景 | 不做广告位调整 | placement 字段填写 N/A |
