# 淘汰广告活动规则（eliminate_campaign_rules.yaml）

定义 Agent 何时建议将广告活动移入淘汰组、执行值是什么、输出哪些字段。

---

## 0. 核心定义

**淘汰 ≠ 暂停 ≠ 关停。**

淘汰广告活动的本质是将低效活动移入淘汰组（Elimination Pool），用极低预算和极低 Bid 继续捡漏观察，避免直接断流。

- 活动在亚马逊后台保持**启用**状态
- Agent **不使用 `pause`（暂停）作为常规运营动作**，统一替换为 `eliminate_to_low_bid_pool`
- 淘汰后执行值固定（见 §3），不可由 Agent 自行修改

---

## 1. 淘汰触发条件（满足任一可触发淘汰建议）

| 条件码 | 触发条件 | 说明 |
|--------|---------|------|
| `NO_CVR_HIGH_SPEND` | 7天 CVR = 0 + 7天花费 > $15 + 对自然排名无支持 | 花费无产出，且对排名无贡献 |
| `ACOS_UNRECOVERABLE` | 连续3天 ACOS > 目标 × 1.5 + 活动整体低转化 + 降预算已执行但无改善 | 连续低效且已无优化空间 |
| `KEYWORD_UPGRADED` | 该词已从广泛/自动升级为精准活动，且精准活动连续7天有订单 | 原探索活动被精准版覆盖，失去价值 |
| `IRRELEVANT_NO_IMPROVEMENT` | 广泛/词组广告否词执行后，搜索词质量仍持续差（7天否词数 > 5 且仍无有效词沉淀） | 词池质量差且无法改善 |

---

## 2. 淘汰保护条件（以下情形禁止触发淘汰）

| 保护条件 | 说明 |
|---------|------|
| 活动上线 < 3天 | 样本不足，只能观察，不能淘汰 |
| 核心词自然位连续上升 | 活动可能承担 Ranking 任务，不能淘汰 |
| Listing 优化中 | 按 Maintain 观察，不做大动作 |
| 该词被运营标记为 Custom 核心词 | Custom 优先级最高，需运营手动决策 |

---

## 3. 淘汰前必须走的诊断步骤（不能跳过直接淘汰）

**精准广告的诊断路径：**
```
广告位花费高无单？
  → 是 → 先降该广告位加价，观察3天
           仍无改善 → 降基础 Bid
           仍无改善 → 再评估是否淘汰整体活动
  → 否 → 直接评估淘汰条件
```

**广泛/词组/自动广告的诊断路径：**
```
高点击无单？
  → 是 → 先执行否词（add_negative）
           否词后仍无改善 → 降 Bid / 降预算
           降 Bid/预算后仍无改善 → 评估淘汰
  → 否 → 直接评估淘汰条件
```

> **原则**：广泛/词组广告必须走搜索词治理流程，不能跳过否词直接淘汰。

---

## 4. 淘汰执行值（固定值，Agent 不可修改）

| 参数 | 执行值 | 备注 |
|------|--------|------|
| 广告活动日预算 | **$1.00** | 以后台可执行最低值为准，通常为 $1 |
| 关键词基础 Bid | **$0.20** | 以后台可执行最低值/类目特殊值为准 |
| 广告位：头部（TOS） | **0%** | 仅对精准广告有意义，广泛/自动执行但无实际影响 |
| 广告位：其他（RoS） | **0%** | 同上 |
| 广告位：商品（PP） | **0%** | 同上 |

---

## 5. 淘汰后联动动作（必须判断）

淘汰活动后，Agent **必须同步判断**是否需要补新活动，防止流量盘缩小：

| 判断项 | 处理 |
|--------|------|
| 该词是否仍有流量价值？ | 是 → 同步建议新增精准/长尾承接（触发 `FILL_AFTER_ELIMINATION`） |
| 淘汰后词池是否明显变窄？ | 是 → `need_new_campaign = true`，并给出新增建议 |
| 已有替代活动覆盖该词？ | 是 → `replacement_campaign` 填写替代活动名称，无需新增 |

---

## 6. 淘汰广告活动必须输出的字段

| 字段 | 中文说明 | 填写要求 |
|------|---------|---------|
| `proposal_type` | 建议类型 | 固定填写：**淘汰广告活动** |
| `action_type` | 动作类型 | 固定填写：`eliminate_to_low_bid_pool`（不使用 `pause`） |
| `campaign_name` | 需要淘汰的活动名称 | 必须明确 |
| `campaign_type` | 广告活动类型 | `exact_keyword` / `broad_keyword` / `phrase_keyword` / `auto_discovery` |
| `portfolio_or_group` | 所属广告组合/Portfolio | 必须明确，方便后台定位 |
| `target_elimination_group` | 移入哪个淘汰组合 | 必须给出淘汰组名称；若无则建议新建淘汰组 |
| `proposed_daily_budget` | 淘汰后预算 | 固定 **$1.00**（以后台最低可执行值为准） |
| `proposed_base_bid` | 淘汰后 Bid | 固定 **$0.20**（以后台最低可执行值为准） |
| `placement_cleared` | 广告位是否清零 | 精准广告：三个位置均清为 **0%**；广泛/自动：填 `N/A` |
| `lookback_window` | 判断时间窗口 | 固定：**近7天**（淘汰优先使用7天数据） |
| `current_spend_7d` | 近7天花费 | 必须给出具体金额 |
| `current_orders_7d` | 近7天订单数 | 必须给出 |
| `current_cvr_7d` | 近7天转化率 | 必须给出 |
| `organic_rank_support` | 是否支撑自然排名 | 必须判断：**是 / 否 / 缺数据** |
| `diagnosis_steps_taken` | 已执行的诊断步骤 | 必须说明淘汰前走了哪些诊断（如：已降广告位→已降Bid→仍无改善） |
| `eliminate_reason` | 淘汰理由 | 必须逐条列出命中的条件码 + 数据证据 |
| `replacement_campaign` | 是否已有替代活动 | 填写替代活动名称，或 `无` |
| `need_new_campaign` | 是否需要补新活动 | `true` / `false`，true 时同步输出新增建议 |
| `review_level` | 审核等级 | 固定 **`SENIOR_APPROVAL`** |

---

## 7. 淘汰后重新启用判断（≥14天后复评）

活动进入淘汰组 **≥ 14天**后，Agent 必须对该词进行一次复评，判断是否具备重新启用条件。

> **核心原则**：重新启用优先采用**原位恢复**（调整现有活动的预算/Bid），不默认走新增活动流程。

### 复评触发时机

| 条件 | 说明 |
|------|------|
| 距淘汰日期 ≥ 14天 | 固定复评窗口，Agent 按淘汰记录日期自动触发 |

---

### 情况一：偶然出单，数据不充分 → 仅恢复预算

**触发条件**：近 30 天该词在淘汰池中有出单（orders_30d ≥ 1）

**处理逻辑**：
- 该词在极低 Bid（$0.20）+ 极低预算（$1.00）的环境下仍能偶尔出单，说明词有基础信号
- 样本量不足，不具备提高 Bid 的依据
- 仅将预算从 $1.00 恢复至 $3.00，用更多曝光机会换取数据，Bid 维持 $0.20 不变
- 触发场景码：`REACTIVATE_BUDGET_ONLY`

**执行值**：

| 参数 | 执行值 |
|------|--------|
| 日预算 | **$3.00**（从 $1.00 提升） |
| 基础 Bid | **$0.20**（维持不变） |

**必须输出的字段**：

| 字段 | 填写要求 |
|------|---------|
| `proposal_type` | 固定：**重新启用广告活动** |
| `action_type` | `reactivate_budget_only` |
| `original_campaign_name` | 原淘汰活动名称 |
| `elimination_date` | 淘汰日期 |
| `days_in_elimination` | 已在淘汰组天数 |
| `orders_30d` | 近30天订单数（触发依据，填写具体数值） |
| `proposed_daily_budget` | **$3.00** |
| `proposed_base_bid` | **$0.20**（不变，注明"数据不足，维持淘汰池 Bid"） |
| `review_level` | **AUTO_BATCHABLE** |

---

### 情况二：历史高花费但转化差 → 恢复预算 + 重新定价

**触发条件**：近 30 天该词在淘汰池中无出单（orders_30d = 0）且淘汰前历史花费较高

**处理逻辑**：
- 该词历史上花费较多但表现差，问题可能在于出价锚点不准（过高或过低），不一定是词本身无价值
- 用该产品精准广告的真实成交均价重新定价，比建议竞价更贴近账户实际市场水平
- 触发场景码：`REACTIVATE_WITH_CALIBRATED_BID`

**Bid 取值规则**：

```
proposed_bid = min(0.5, 产品精准广告近30天均CPC)
```

| 参数 | 执行值 |
|------|--------|
| 日预算 | **$3.00**（从 $1.00 提升） |
| 基础 Bid | **min(0.5, 产品精准广告近30天均CPC)**，必须给出计算过程 |

> 数据来源：该父ASIN下所有精准广告活动，取近30天**有出单关键词**的平均CPC；若无有出单数据，取近30天所有精准广告关键词的均CPC。

**必须输出的字段**：

| 字段 | 填写要求 |
|------|---------|
| `proposal_type` | 固定：**重新启用广告活动** |
| `action_type` | `reactivate_with_calibrated_bid` |
| `original_campaign_name` | 原淘汰活动名称 |
| `elimination_date` | 淘汰日期 |
| `days_in_elimination` | 已在淘汰组天数 |
| `orders_30d` | 0（触发本情况的依据） |
| `avg_exact_cpc_used` | 计算所用的均CPC值，注明数据来源（有出单词/全部精准词） |
| `proposed_daily_budget` | **$3.00** |
| `proposed_base_bid` | min(0.5, 均CPC值)，必须给出计算过程 |
| `review_level` | **MANUAL_REVIEW** |

---

## 8. 输出示例

```yaml
proposal_type: 淘汰广告活动
action_type: eliminate_to_low_bid_pool
campaign_name: "casual_dress_broad_B0XXXXXXXX"
campaign_type: broad_keyword
portfolio_or_group: "女装主力组合-US"
target_elimination_group: "淘汰捡漏组-2026Q2"
proposed_daily_budget: 1.0
proposed_base_bid: 0.20
placement_cleared: N/A              # 广泛广告不涉及广告位
lookback_window: "近7天"
current_spend_7d: 18.5
current_orders_7d: 0
current_cvr_7d: 0%
organic_rank_support: 否
diagnosis_steps_taken:
  - "已执行否词3个，否词后仍无有效搜索词沉淀"
  - "已降 Bid 10%，花费减少但仍无订单"
eliminate_reason:
  - condition_code: "NO_CVR_HIGH_SPEND"
    evidence: "7天花费$18.5，订单0，CVR=0，无自然位支持"
  - condition_code: "IRRELEVANT_NO_IMPROVEMENT"
    evidence: "7天否词5个，仍无有效词根沉淀"
replacement_campaign: 无
need_new_campaign: true             # 同步触发新增建议
review_level: SENIOR_APPROVAL
```
