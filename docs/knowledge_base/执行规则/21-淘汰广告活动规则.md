# 淘汰广告活动规则（eliminate_campaign_rules.yaml）

定义 Agent 何时建议将**精准广告活动**移入低价捡漏组、执行值是什么、输出哪些字段。

> **边界**：低价捡漏组只允许 `exact_keyword`。
> BROAD / PHRASE / AUTO 表现差时执行否词、降预算、降 Bid，需要退出时走 **`paused_campaign`**
> （`30号§1` #13）；`product_targeting` 同样走 `paused_campaign`。
> 两者均**不得**迁入低价捡漏组（`ONT-016`）。
>
> 完整的三级回落判定（轻度/中度/严重）见 **`32-精准组合升降级规则.md§2`**。本文提供淘汰动作的
> 触发条件、保护条件、诊断路径、执行值与输出字段。

---

## 0. 核心定义

**淘汰 ≠ 暂停。**

淘汰广告活动的本质是将低效活动移入低价捡漏组（low_bid_retention_group），用极低预算和极低 Bid 继续捡漏观察，避免直接断流。

- 活动在亚马逊后台保持**启用**状态
- 对精准活动，Agent **不使用 `paused_campaign` 替代低价捡漏**，统一使用 `eliminate_to_low_bid_pool`
- 对广泛、词组、自动、商品定投活动，退出动作是 **`paused_campaign`**（不是 `eliminate_to_low_bid_pool`）。语义见 `30号§2`
- 淘汰后执行值固定（见 §3），不可由 Agent 自行修改

---

## 1. 淘汰触发条件（满足任一可触发淘汰建议）

| 条件码 | 触发条件 | 说明 |
|--------|---------|------|
| `NO_CVR_HIGH_SPEND` | 7天 CVR = 0 + 7天花费 ≥ `03号§7.3` 的**淘汰花费门槛**（目标 CPA 口径）+ 对自然排名无支持 | 花费无产出，且对排名无贡献 |
| `ACOS_UNRECOVERABLE` | 连续3天 ACOS > **目标ACOS倍数阈值**（`15号§4`）+ 活动整体低转化 + 降预算已执行但无改善 | 连续低效且已无优化空间 |
| `MULTI_KEYWORD_EXACT` | 精准活动包含多个有效关键词 | 按负责人确认规则迁入低价捡漏组 |

---

## 2. 淘汰保护条件（以下情形禁止触发淘汰）

| 保护条件 | 说明 |
|---------|------|
| 活动上线 < 3天 | 样本不足，只能观察，不能淘汰 |
| product_stage=testing 且 活动上线 < 14天 | 测试期样本保护，不进入淘汰评估。**但 testing 已超期（`03号§2`）时本保护失效**（`17号§1.2` `STAGE_EXPIRED_TESTING`） |
| **原生测试活动上线 < 14天** | 从广泛提词直接新建、从未在主力组待过的活动，观察窗从创建日起算，长尾可延至 21 天（`32号§2.4`） |
| **高优先级保护词** | 标题词 / 后台 ST 词 / 核心卖点词 / `29号` `is_core_keyword=true` → **不得转入低价捡漏组**，最多降 Bid 与降预算（`32号§2.1`） |
| 核心词自然位连续上升 | 活动可能承担 Ranking 任务，不能淘汰 |
| Listing 优化中 | 按 balance_maintain 方向观察，不做大动作 |
| 该词被运营标记为 Custom 核心词 | Custom 优先级最高，需运营手动决策 |

---

## 3. 淘汰前必须走的诊断步骤（不能跳过直接淘汰）

**精准广告的诊断路径：**
```
广告位花费高无单？
  → 是 → 先降该广告位加价，观察3天
           仍无改善 → 降基础 Bid
           仍无改善 → 再评估是否淘汰整体活动
  → 否 → 直接评估淘汰条件
```

**广泛/词组/自动广告的停止投放前诊断路径（不属于低价捡漏）：**
```
高点击无单？
  → 是 → 先执行否词（add_negative）
           否词后仍无改善 → 降 Bid / 降预算
           降 Bid/预算后仍无改善 → 评估停止投放
  → 否 → 继续按目标ACOS和经营模式判断
```

> **原则**：广泛/词组广告必须先保护高度相关词，再走搜索词治理流程；
> 无改善时可以关闭，但不能进入低价捡漏组。

## 4. 淘汰执行值（固定值，Agent 不可修改）

| 参数 | 执行值 | 备注 |
|------|--------|------|
| 广告活动日预算 | **$1.00** | `ONT-014` 锁定，不可被任何动作覆盖 |
| 关键词基础 Bid | **`min(current_bid, 0.20)`** | **当前 Bid 已低于 $0.20 时保持不变，不得抬高**。见 `03号§8.1`、`ONT-014`、`GROUP-004A` |
| 广告位：头部（TOS） | **0%** | 仅精准活动执行 |
| 广告位：其他（RoS） | **0%** | 仅精准活动执行 |
| 广告位：商品（PP） | **0%** | 仅精准活动执行 |

## 5. 淘汰后联动动作（必须判断）

淘汰活动后，Agent **必须同步判断**是否需要补新活动，防止流量盘缩小：

| 判断项 | 处理 |
|--------|------|
| 该词是否仍有流量价值？ | 是 → 同步建议新增精准/长尾承接（触发 `FILL_AFTER_ELIMINATION`） |
| 淘汰后词池是否明显变窄？ | 是 → `need_new_campaign = true`，并给出新增建议 |
| 已有替代活动覆盖该词？ | 是 → `replacement_campaign` 填写替代活动名称，无需新增 |

---

## 5A. 淘汰释放预算回算（组合层 + 父 ASIN 层）

淘汰活动的预算从原值降至 $1，释放的差额必须回算到组合预算和父 ASIN 总预算，避免出现"活动层预算降了但整体预算没回收"的黑洞。

> 来源：[23-广告组合与预算分配规则.md](23-广告组合与预算分配规则.md) §5 / §8.4；校验规则：GROUP-BUDGET-003 / GROUP-002。

### 5A.1 释放预算计算

```text
eliminated_campaign_release = sum(current_daily_budget - 1
                                  for campaigns moved_to low_bid_retention_group)
```

示例：某精准测试活动当前预算 $8，本轮转淘汰 → `proposed_daily_budget = $1`，释放金额 = $8 - $1 = **$7**。

### 5A.2 释放预算的归属

| 规则 | 说明 |
| --- | --- |
| 释放来源 | **Campaign 活动层**，不以 low_bid_retention_group 组合预算作为释放来源（GROUP-BUDGET-003） |
| 低价捡漏组组合层 | `group_delta = 0`，不出现组合层负预算；低价捡漏组组合预算固定 $1 不变 |
| 释放流向 | 只能分配给 **exact_core_group / exact_testing_group / auto_broad_group**，不得回流 low_bid_retention_group（GROUP-BUDGET-005） |

### 5A.3 回算到父 ASIN 可用预算

```text
released_budget = eliminated_campaign_release + other_campaign_budget_decrease
available_reallocation_budget = released_budget + parent_allowed_net_increase
```

> `eliminated_campaign_release` 计入本轮 `released_budget`，与`other_campaign_budget_decrease`共同抵扣本轮 `requested_increase`。转入淘汰的活动 **不得再计入原组合的负向 `group_requested_delta`**，避免同一笔释放被重复计算。

### 5A.4 输出字段补充

淘汰建议输出时，须额外包含预算回算字段：

| 字段 | 填写要求 |
| --- | --- |
| `released_at_campaign_level` | 本轮转淘汰在活动层释放的金额（= `current_daily_budget - $1`） |
| `group_type_before_elimination` | 淘汰前所属组合（`exact_core_group` / `exact_testing_group`） |
| `low_bid_retention_group_delta` | 固定填 `0`（低价捡漏组组合层不变） |
| `released_budget_flows_to` | 释放预算可分配去向：exact_core_group / exact_testing_group / auto_broad_group |

## 6. 淘汰广告活动必须输出的字段

| 字段 | 中文说明 | 填写要求 |
|------|---------|---------|
| `proposal_type` | 建议类型 | 固定填写：**淘汰广告活动** |
| `action_code` / `physical_action_code` | 动作码 | 按 `30号§1` 成对输出：`eliminate_to_low_bid_pool` → `move_portfolio` + `adjust_budget` + `adjust_bid`（复合，展开规则见 `30号§3.1`）。**不使用 `paused_campaign`** |
| `campaign_name` | 需要淘汰的活动名称 | 必须明确 |
| `campaign_type` | 广告活动类型 | 固定为 `exact_keyword`；其他类型不允许执行本动作 |
| `portfolio_or_group` | 所属广告组合/Portfolio | 必须明确，方便后台定位 |
| `target_low_bid_retention_group` | 移入哪个低价捡漏组 | 必须给出低价捡漏组名称；若无则建议新建低价捡漏组 |
| `proposed_daily_budget` | 淘汰后预算 | 固定 **$1.00**（以后台最低可执行值为准） |
| `proposed_base_bid` | 淘汰后 Bid | **`min(current_bid, 0.20)`**，必须给出计算过程 |
| `placement_cleared` | 广告位是否清零 | 精准广告三个位置均清为 **0%** |
| `lookback_window` | 判断时间窗口 | 近7天（淘汰优先使用7天数据）；长尾/低流量可延至近14天（`18号§3`） |
| `current_spend_7d` | 近7天花费 | 必须给出具体金额 |
| `current_orders_7d` | 近7天订单数 | 必须给出 |
| `current_cvr_7d` | 近7天转化率 | 必须给出 |
| `organic_rank_support` | 是否支撑自然排名 | 必须判断：**是 / 否 / 缺数据** |
| `diagnosis_steps_taken` | 已执行的诊断步骤 | 必须说明淘汰前走了哪些诊断（如：已降广告位→已降Bid→仍无改善） |
| `eliminate_reason` | 淘汰理由 | 必须逐条列出命中的条件码 + 数据证据 |
| `replacement_campaign` | 是否已有替代活动 | 填写替代活动名称，或 `无` |
| `need_new_campaign` | 是否需要补新活动 | `true` / `false`，true 时同步输出新增建议 |
| `testing_origin` | 测试组来源 | `demoted`（降级型）/ `native`（原生型），决定观察窗起算点（`32号§2.4`） |
| `demoted_at` / `campaign_created_at` | 起算日期 | 按 `testing_origin` 必填对应字段 |
| `protection_verdict` | 保护判定 | `not_protected` / `protected_by_title` / `protected_by_backend_st` / `protected_by_selling_point` / `protected_by_core_keyword`（`32号§2.1`） |
| `review_level` | 审核等级 | 固定 **`HIGH_RISK_REVIEW`**，不可降级 |

## 7. 淘汰后重新启用判断（≥14天后复评）

活动进入低价捡漏组 **≥ 14天**后，Agent 必须对该词进行一次复评，判断是否具备重新启用条件。

> **核心原则**：重新启用优先采用**原位恢复**（调整现有活动的预算/Bid），不默认走新增活动流程。

### 复评触发时机

| 条件 | 说明 |
|------|------|
| 距淘汰日期 ≥ 14天 | 固定复评窗口，Agent 按淘汰记录日期自动触发 |

---

### 情况一：偶然出单，数据不充分 → 仅恢复预算

**触发条件**：近 30 天该词在低价捡漏组中有出单（orders_30d ≥ 1）

**处理逻辑**：
- 该词在低价捡漏 Bid = `min(current_bid, $0.20)` + 极低预算（$1.00）的环境下仍能偶尔出单，说明词有基础信号
- 样本量不足，不具备提高 Bid 的依据
- 仅将预算从 $1.00 恢复至 $3.00，用更多曝光机会换取数据，Bid 不得高于进入低价组时的 `min(current_bid, $0.20)`
- 触发场景码：`REACTIVATE_BUDGET_ONLY`

**执行值**：

| 参数 | 执行值 |
|------|--------|
| 日预算 | **$3.00**（从 $1.00 提升） |
| 基础 Bid | **`min(current_bid, $0.20)`**（维持不变） |

**必须输出的字段**：

| 字段 | 填写要求 |
|------|---------|
| `proposal_type` | 固定：**重新启用广告活动** |
| `action_type` | `reactivate_budget_only` |
| `original_campaign_name` | 原淘汰活动名称 |
| `elimination_date` | 淘汰日期 |
| `days_in_elimination` | 已在低价捡漏组天数 |
| `orders_30d` | 近30天订单数（触发依据，填写具体数值） |
| `proposed_daily_budget` | **$3.00** |
| `proposed_base_bid` | **$0.20**（不变，注明"数据不足，维持低价捡漏组 Bid"） |
| `review_level` | **AUTO_APPROVED** |

---

### 情况二：历史高花费但转化差 → 恢复预算 + 重新定价

**触发条件**：近 30 天该词在低价捡漏组中无出单（orders_30d = 0）且淘汰前历史花费较高

**处理逻辑**：
- 该词历史上花费较多但表现差，问题可能在于出价锚点不准（过高或过低），不一定是词本身无价值
- 用该产品精准广告的真实成交均价重新定价，比建议竞价更贴近账户实际市场水平
- 触发场景码：`REACTIVATE_WITH_CALIBRATED_BID`

**Bid 取值规则**：

```
proposed_bid = min(0.5, 产品精准广告近30天均CPC)
```

| 参数 | 执行值 |
|------|--------|
| 日预算 | **$3.00**（从 $1.00 提升） |
| 基础 Bid | **min(0.5, 产品精准广告近30天均CPC)**，必须给出计算过程 |

> 数据来源：该父ASIN下所有精准广告活动，取近30天**有出单关键词**的平均CPC；若无有出单数据，取近30天所有精准广告关键词的均CPC。

**必须输出的字段**：

| 字段 | 填写要求 |
|------|---------|
| `proposal_type` | 固定：**重新启用广告活动** |
| `action_type` | `reactivate_with_calibrated_bid` |
| `original_campaign_name` | 原淘汰活动名称 |
| `elimination_date` | 淘汰日期 |
| `days_in_elimination` | 已在低价捡漏组天数 |
| `orders_30d` | 0（触发本情况的依据） |
| `avg_exact_cpc_used` | 计算所用的均CPC值，注明数据来源（有出单词/全部精准词） |
| `proposed_daily_budget` | **$3.00** |
| `proposed_base_bid` | min(0.5, 均CPC值)，必须给出计算过程 |
| `review_level` | **MANUAL_REVIEW** |

```yaml
proposal_type: 淘汰广告活动

campaign_name: "casual_dress_exact_B0XXXXXXXX"
campaign_type: exact_keyword
portfolio_or_group: "女装主力组合-US"
target_low_bid_retention_group: "低价捡漏组-2026Q2"
proposed_daily_budget: 1.0
proposed_base_bid: 0.20            # = min(current_bid 0.35, 0.20)
placement_cleared: true
lookback_window: "近7天"

current_orders_7d: 0
current_cvr_7d: 0%
organic_rank_support: 否

```
