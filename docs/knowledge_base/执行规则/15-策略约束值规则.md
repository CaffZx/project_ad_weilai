# 策略约束值规则（strategy_constraint_values.yaml）

定义 Agent 在执行广告调整时，Bid、预算、广告位、ACOS 容忍度的具体约束数值。

> **本文与17号的分工**
> `17-问题诊断与动作优先级.md` 决定"做什么动作"，本文提供"这个动作的具体数值边界是多少"。
> 17号输出有序动作列表后，Agent 必须查本文取得约束值，才能生成具体提案。

---

## 0. 使用方式

```
17号输出：action = "bid_up_for_ranking"，target = "主推词"
  ↓
查本文 §1：初始Bid = CPC × 0.8（long_tail）× 1.2（pushing）= $0.72
查本文 §1.2：调整幅度 = 19号大涨10% × pushing系数1.2 × 旺季系数1.2 = 14%
查本文 §1.4：确认不超过$3.00硬上限
  ↓
生成提案：当前Bid $0.85，建议Bid $0.85 × 1.14 = $0.97，取整$0.95
```

## 1. Bid 约束值

### 1.1 初始 Bid 公式

用于**新建活动**或**重置 Bid** 时计算起始出价：

```
初始 Bid = 品类参考 CPC × 关键词类型系数 × 产品阶段系数
```

品类参考 CPC 由 ERP 提供，Agent 只引用不覆盖。

**关键词类型系数**

| 关键词类型 | 系数 | 说明 |
|----------|------|------|
| generic（大词） | 0.5 | 低成本筛词，不追高排名 |
| long_tail（长尾词） | 0.8 | 精准高转化，主力出价档位 |
| competitor（竞品词） | 0.8 | 中低价测试竞品流量 |
| brand（品牌词） | 0.3 | 借品牌流量，出价保守 |
| custom（自定义词） | 0.5 | 运营经验词，保守起步 |

**产品阶段系数**

| 产品阶段 | 系数 | 说明 |
|---------|------|------|
| testing | 0.8 | 控成本验证，不激进 |
| pushing | 1.2 | 放量期，允许偏高出价 |
| harvesting | 1.0 | 效率优先，回归标准 |
| maintaining | 1.0 | 稳定期，标准出价 |
| liquidating | 0.5 | 清仓期，大幅压低出价 |

> 初始 Bid 不乘淡旺季系数，淡旺季系数只用于调整幅度修正（见§1.2）。

---

### 1.2 Bid 调整幅度修正系数

`19-执行层数值规则.md` 定义基础幅度（大涨+10%、小涨+5%等），本文提供修正系数：

```
实际调整幅度 = 19号基础幅度 × 产品阶段系数 × 淡旺季系数
```

**产品阶段系数**

| 产品阶段 | 系数 |
|---------|------|
| testing | 0.5 |
| pushing | 1.2 |
| harvesting | 1.0 |
| maintaining | 0.7 |
| liquidating | 0.5 |

**淡旺季系数**

| 淡旺季 | 系数 |
|-------|------|
| 淡季 | 0.8 |
| 旺季前期 | 1.1 |
| 旺季 | 1.2 |
| 旺季末期 | 0.9 |

> 示例：19号基础大涨 +10%，pushing × 1.2，旺季 × 1.2 → 实际幅度 = **+14%**

---

### 1.3 Bid 保护规则

以下情况下，Bid 不得下调：

| 保护场景 | 规则 |
|---------|------|
| 关键词承担 Ranking 任务 | 禁止降 Bid，直到 day_7 复盘结论为 not_achieved 且 ACOS > 目标ACOS倍数阈值 |
| P0 核心词 | 每次降幅 ≤ 5%，不得连续两次降同一关键词 |
| 活动上线 < 3天 | 禁止降 Bid（样本不足） |
| 淡旺季 = 旺季且广告目的 = ranking | 禁止降主推词 Bid |

---

### 1.4 Bid 硬上下限

| 限制项 | 值 | 来源 |
|-------|---|------|
| Bid 硬上限（全站） | $3.00 | `03号§8.2` |
| **Bid 硬下限（全站）** | **$0.02**（US 站点最低可执行值） | `03号§8.1` |
| **低价捡漏组固定 Bid** | **`min(current_bid, 0.20)`** —— 业务选择，**不是**全站下限 | `03号§8.1`、`ONT-014` |
| 活动日预算上限 | $200 | `03-阈值参数.md §8` |
| ASIN 总日预算上限 | $1,000 | `03-阈值参数.md §8` |
| 广告位加价上限 | 900% | 亚马逊平台限制 |

> 若变更 Bid 后广告位加价比例超过 900%，需自动截断至 900%。
> 变更 Bid 时须同步计算并展示加价后的 CPC 预估值。

## 2. 预算约束值

### 2.1 存量活动预算范围表

按**产品定位 × 产品阶段**查表，单位：美元/天。

|  | testing | pushing | harvesting | maintaining | liquidating |
|--|---------|---------|------------|-------------|-------------|
| **P0** | $20–40 | $80–200 | $50–100 | $40–80 | $10–20 |
| **P1** | $15–25 | $40–80 | $25–50 | $20–40 | $8–15 |
| **P2** | $8–15 | $15–30 | $12–20 | $10–18 | $5–10 |
| **P3** | $5–10 | $10–20 | $8–15 | $8–12 | $5–10 |

> 新建活动初始预算见 `16-新增活动规则.md §2`，本表适用于存量活动的预算范围约束。

### 2.2 淡旺季预算系数

在上表基础上乘以淡旺季系数：

| 淡旺季 | 系数 |
|-------|------|
| 淡季 | × 0.8 |
| 旺季前期 | × 1.2 |
| 旺季 | × 1.5 |
| 旺季末期 | × **0.9** |

> **v3.4.0 统一（C-24）**：与 `03号§3` 和 `17号§5.3` 共用同一套系数。
> v3.3.0 存在两套（幅度 0.7/0.85 vs 范围 0.8/1.0），且 `17号§5.3` 自标了待确认。已统一。

> 示例：P1 + pushing 预算范围 $40–80，旺季 × 1.5 → 有效范围 **$60–120/天**
>
> 注意：本节淡旺季预算系数用于修正**预算范围**，即判断当前预算是否处于合理区间；不用于计算本次预算调整幅度。本次预算调整幅度按 `17-问题诊断与动作优先级.md §5.3` 的预算系数计算。

### 2.3 预算特殊规则

| 规则 | 约束 |
|------|------|
| liquidating 阶段 | 预算绝对上限 $80/天，覆盖上表所有值 |
| 活动近期花费 > $20 | 涨幅翻倍（小涨 +$1 → +$2，大涨 +$2 → +$4） |
| 预算硬上限（单活动） | $200/天（来自 `03-阈值参数.md §8`） |
| 预算硬上限（ASIN总计） | $1,000/天（来自 `03-阈值参数.md §8`） |
| 预算硬下限 | $1/天（低价捡漏组最低值） |

## 3. 广告位约束值

**本节适用 `exact_keyword` 与 `product_targeting`。**
`broad_keyword / phrase_keyword / auto_discovery` 禁止输出任何广告位建议，该字段填 `N/A`。

> v3.4.3：`product_targeting`（商品/类目定投）归属 `auto_broad_group` + `subtype=product_targeting`（`02号§9`），
> 允许广告位调整且 **PP 优先于 TOS/RoS**（`ONT-010`）。

### 3.1 主投广告位选择矩阵

| 广告目的 | 产品阶段 | 推荐主投位 | 初始加价范围 |
|---------|---------|---------|-----------|
| ranking | pushing | 头部（TOS） | +10%–+20% |
| ranking | harvesting | 头部（TOS） | +10% |
| conversion | pushing | 头部（TOS） | +10% |
| conversion | harvesting / maintaining | 头部（TOS） | +5%–+10% |
| conversion | testing | 其他（RoS） | 0% |
| traffic | 任意 | 其他（RoS） | 0% |
| profit | 任意 | 其他（RoS）或不加价 | 0% |
| 竞品截流 | 任意 | 商品页（PP） | +10% |
| liquidating | 任意 | 商品页（PP） | +5%–+10% |

### 3.1A TOS 加价上限按产品定位分档（v3.4.0 新增，G3）

| 产品定位 | TOS 加价上限 |
|---------|------------|
| P0 / P1 | 30% |
| P2 | 15% |
| P3 | 10% |

数值来源：`03号§6.2`。PP 与 RoS 不按定位分档（上限见 `03号§6.1`）。

> v3.3.0 有三处冲突答案：`07号§1` 写「仅 P0/P1 可用」、本节矩阵不分定位、
> `17号§5.1` 写「P3 上限 10%」。已统一为 `03号§6.2` 四档表：**P2/P3 可用但上限更低**。

### 3.2 广告位加价阻断条件

| 阻断场景 | 影响范围 |
|---------|---------|
| 库存天数 < 15天 | 阻断 TOS 加价 |
| 高退货率 ≥ 30% | 阻断 TOS 加价 |
| 评分 < 3.8 | 阻断 TOS 加价 |
| 产品阶段 = testing | TOS 加价上限 10%，不新增 |
| 广告目的 = profit | 禁止新增 TOS 加价 |
| 淡季 | TOS 加价上限 10%，不新增 PP 加价 |
| 缺少广告位数据 | 阻断所有广告位调整，原因码 PLACEMENT_DATA_MISSING |

## 4. ACOS 容忍度矩阵

**17号文件 §2 直接引用本节的目标 ACOS 倍数，用于问题类型判断。**

### 4.1 最终判定口径

```
目标 ACOS × 1.0  = 正常达标上限
目标 ACOS × 1.5  = 轻度回落上限
目标 ACOS × 2.0  = 中度回落上限
ACOS > 目标 ACOS × 2.0 = 严重回落候选
```

这是全知识库唯一的 ACOS 判定基准。禁止使用阶段加法百分点或目标 ACOS 加固定百分点替代上述倍数；除 ×1.5 和 ×2 外不得自行发明新的回落倍数。
经营模式不改变 ACOS 倍数；经营模式负责决定允许动作、预算倾向和审核权限。

### 4.1A 经营模式与 ACOS 判定的关系

经营模式权限表仍以 `09号§4` 为准：先由经营模式决定允许的动作集合，再由产品分层和 ACOS 倍数决定动作幅度。经营模式不得把目标 ACOS 倍数改写成另一套阈值。

### 4.2 产品阶段加值

| 产品阶段 | 加值 |
|---------|------|
| testing | +15% |
| **testing 且已满 60 天（超期）** | **+0%**（v3.4.0 新增，C-17） |
| pushing | +10% |
| harvesting | +5% |
| maintaining | +0% |
| liquidating | +20% |

> **testing 超期归零的理由（C-17）**：`03号§2` 规定 testing「最多测 60 天」，但 v3.3.0 对
> 超期没有任何规则。一个卡在 testing 不动的产品会永久享受三项优待：最高的 ACOS 容忍加值
> （+15%，五阶段之最）、`17号§5.2` 的 ×0.5 幅度抑制、以及 `21号§2` 的免淘汰评估。
> 目标 25% 时，轻度回落边界为 37.5%，中度回落边界为 50%；经营模式不改变这两个边界。
> 超期后：容忍加值归零 + 冻结增长型动作 + 输出 MANUAL_REVIEW 要求运营确认阶段。
> Agent **不得**自行改产品阶段标签（`02号§2` 权限为「仅建议」）。

### 4.3 计算示例

| 场景 | 计算过程 | 判定 |
|------|---------|-----------|
| 任意经营模式，目标25% | 25% × 1.5 | **37.5%：轻度回落上限** |
| 任意经营模式，目标25% | 25% × 2.0 | **50%：中度回落上限** |
| 任意经营模式，目标30% | 30% × 2.0 | **60%：中度回落上限** |

> ACOS ≤ 目标 ACOS：达标；目标 ACOS < ACOS ≤ 目标 ACOS×1.5：轻度回落；目标 ACOS×1.5 < ACOS ≤ 目标 ACOS×2：中度回落；ACOS > 目标 ACOS×2：严重回落候选。

## 5. 目标 CPA 与无单花费门槛（v3.4.0 新增，C-09）

### 5.1 目标 CPA

```
目标 CPA = 平均订单金额 × 目标 ACOS
```

- 平均订单金额 = 近 7 天广告销售额 ÷ 近 7 天广告订单数（无广告订单时退化为近 14 天）
- 术语定义见 `14号§20`；具体门槛取值见 `03号§7.3`

### 5.2 五个门槛的取值

全部取值在 `03号§7.3`，本节只说明用途与调用点：

| 门槛 | 用途 | 调用点 |
|------|------|--------|
| 样本不足门槛 | 低于此花费视为样本不足，不做大幅调整 | `17号§1.2` `SAMPLE_INSUFFICIENT` |
| 无单花费门槛 | 进入降 Bid 观察（相关词）或否词判断（不相关词） | `31号§4` 档 2、`19号§8` 预警档 |
| 强优化花费门槛 | 进入大降 + 人工复评 | `31号§4` 档 3、`19号§8` 强优化档 |
| 否词花费门槛 | 高花费低相关的否词准入 | `05号§3` |
| 淘汰花费门槛 | 淘汰/转低价捡漏组准入 | `21号§1`、`32号§2.4` |

### 5.3 为什么必须动态

女装客单价跨度大（$18 T恤 到 $79 外套）。用同一个裸美元无单门槛：

- 对 $18 客单（目标 CPA ≈ $5.4）：$15 的门槛意味着容忍近 3 个 CPA 的亏损才动手
- 对 $79 客单（目标 CPA ≈ $23.7）：$15 的门槛意味着还没跑到一个正常 CPA 就被判无效

两个方向的错都在真实发生。v3.3.0 全库门槛都是裸美元（$5/$10/$15/$20），
且淘汰门槛在 `05号` 是 $10、在 `21号`/`18号` 是 $15（同一门槛两个值）。

**降级**：平均订单金额不可用时取 `03号§7.3` 的裸美元兜底值，标 `DATA_MISSING`，升一级审核等级。

## 6. 约束值速查卡

Agent 生成提案时，必须在输出中引用本文的约束值：

```yaml
constraint_values_applied:
  bid_formula: "CPC $0.75 × long_tail 0.8 × pushing 1.2 = 初始Bid $0.72"
  bid_adjustment: "19号大涨+10% × pushing1.2 × 旺季1.2 = +14%"
  bid_hard_limit: "上限$3.00，下限$0.20"
  budget_range: "P1 × pushing = $40–80 × 旺季1.5 = $60–120/天，当前$50略低于范围下限"
  placement: "ranking + pushing → TOS主投，初始+10%"
  acos_tolerance: "目标25% + pushing+10%×模式系数1 + ranking+10% + 旺季+10% = 55%"
  mode_coefficient: "active_promotion → 1（阶段加值正常生效，09号§3.2）"
  target_cpa: "平均订单金额$42 × 目标ACOS 25% = $10.5；无单花费门槛 max($15, $10.5) = $15"
  bid_floor_note: "全站下限$0.02；低价捡漏组固定 min(current_bid, 0.20)"
  kb_ref: "15-策略约束值规则.md"
```
