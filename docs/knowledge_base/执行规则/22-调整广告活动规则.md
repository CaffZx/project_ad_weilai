# 调整广告活动规则（adjust_campaign_rules.yaml）

定义 Agent 如何对存量广告活动进行 Budget / Bid / Placement / Search Term 四个维度的调整建议，以及必须输出的字段。

---

## 0. 核心原则

- **必须先判断广告活动类型**，再决定可调整哪些维度（见 §1）
- 精准广告拆成三层：Budget → Bid → Placement
- 广泛/词组广告拆成三层：Budget → Bid → Search Term（否词/提词）
- 广泛/词组/自动广告**禁止输出 Placement 调整**，placement 字段填写 `N/A`；`product_targeting` **允许**（PP 优先）
- AI 不能直接从「ACOS 高」跳到「降 Bid」或「淘汰」，必须先走分层诊断

---

## 1. 广告活动类型判定（调整前必判）

| 投放方式/活动类型 | 归类 | 允许调整项 | 禁止调整项 |
|-----------|------|----------|-----------|
| EXACT | 精准广告 | Budget + Target Bid + Placement（头部/其他/商品，上限按 `03号§6.2` 定位分档）+ `eliminate_to_low_bid_pool` + 关闭 Target | **禁止否词**（`ONT-015`；阻断时须给 `recommended_next_step`）；不能盲目扩泛词 |
| BROAD | 广泛广告 | Budget + Bid + Search Term（否词/提词）+ `stop_campaign` | Placement 调整，填 `N/A`；**不得进低价捡漏组** |
| PHRASE | 广泛广告（按广泛策略处理） | 同 BROAD | 同 BROAD |
| AUTO | 广泛广告（按测词逻辑） | 同 BROAD，但 AUTO Target Bid 在契约完成前被阻断（`ONT-009`、`31号§8`） | 同 BROAD |
| PRODUCT_TARGETING | 商品定投广告（v3.4.0 新增） | Budget + Target Bid + Placement（**PP 优先**，`ONT-010`）+ `stop_campaign` | 不做否词（无搜索词）；不套三日验证；**不得进低价捡漏组** |

## 2. 精准广告调整规则

### 2.1 Budget（预算）调整

| 场景 | 建议动作 | 审核等级 |
|------|---------|---------|
| 预算利用率 ≥ 70% + ACOS ≤ 目标 ACOS + 库存天数 ≥ `03号§5` 健康线 | `campaign_budget_increase`（增加预算） | 默认 MANUAL_REVIEW；增幅 > 30% 升 HIGH_RISK_REVIEW |
| 3天 ACOS > **有效容忍上限**（`15号§4`） | `campaign_budget_decrease`（降低预算） | 默认 AUTO_APPROVED；主力精准活动需 MANUAL_REVIEW |

### 2.2 Bid（基础竞价）调整

| 场景 | 建议动作 | 审核等级 |
|------|---------|---------|
| `ranking_opportunity` 触发（自然位上升 + ACOS 可控 + CVR 不下降） | `bid_up_for_ranking`（提价冲排名） | 提价 ≤ 10% 可 AUTO_APPROVED；> 20% 需 HIGH_RISK_REVIEW |
| 3天 Keyword ACOS > **有效容忍上限**（`15号§4`）且 7天订单 = 0 或订单不足 | `bid_down_for_acos`（降价控 ACOS） | 核心词必须 MANUAL_REVIEW；非核心词 AUTO_APPROVED |

> **Ranking 保护**：如果关键词承担冲排名任务，即使 ACOS 短期偏高，也**禁止降 Bid**。

### 2.3 Placement（广告位）调整

**仅 `exact_keyword` 与 `product_targeting` 适用**，广泛/词组/自动此节跳过。
TOS 加价上限按 `03号§6.2` 的产品定位四档（P0/P1 30%、P2 15%、P3 10%）。

按三个广告位分别评估，每个位置独立输出建议：

| 数据情况 | 判断逻辑 | 建议动作 |
|---------|---------|---------|
| 有花费 + 有有效广告位 | 对比头部/商品/其他三个广告位的 ACOS、订单、CVR；哪个位置 ACOS 更低、转化更好，优先加该位置比例 | 提高表现最好广告位的加价比例 |
| 有花费 + 无有效广告位 | 广告位有消耗但无订单，或 ACOS > **有效容忍上限**，该位置无有效转化 | 降低对应广告位比例 |
| 无花费 | 当前广告位无消耗，无法判断好坏 | 可试探其他（RoS）和头部（TOS）；优先测其他再测头部 |

广告位最终有效出价按 `07-广告位规则.md` 计算：`placement_effective_bid = base_bid × (1 + placement_pct / 100)`。若基础 Bid 与广告位比例同轮变化，必须先确定 `proposed_base_bid`，再用各广告位 `proposed_pct` 计算对应广告位的理论有效出价。

**广告位调整阻断条件：**

| 阻断场景 | 影响 | 处理 |
|---------|------|------|
| 缺少广告位数据 | 阻断全部 Placement 调整 | 状态 BLOCKED，原因码 `PLACEMENT_DATA_MISSING` |
| 库存不足（< 15天） | 阻断头部（TOS）和商品（PP）加价 | BLOCKED |
| 高退货率（≥ 30%） | 阻断头部（TOS）加价 | BLOCKED |
| 低评分（< 3.8） | 阻断头部（TOS）加价 | BLOCKED |
| TOS/PP 花费高但无单 | 先降广告位加价；不降基础 Bid；不直接淘汰活动 | 降 Placement % |

**广告位输出格式（三个位置必须全部输出）：**

```yaml
placement_adjustments:
  - placement: "头部"
    current_pct: 20
    proposed_pct: 30
    action: "上调"
    evidence: "头部7天ACOS=18%，目标25%，7天订单4单"
  - placement: "其他"
    current_pct: 0
    proposed_pct: 0
    action: "维持"
    evidence: "无花费，暂不调整"
  - placement: "商品"
    current_pct: 10
    proposed_pct: 0
    action: "下调"
    evidence: "商品页7天花费$6，点击8次，0订单，ACOS=MAX"
```

### 2.4 精准活动出现高花费无关搜索词怎么办（v3.4.2 新增，替代「后台否词」）

**前提：本账户的精准活动一律 1 关键词 = 1 活动（SKAG）。** 多关键词精准活动
被 `ROUTE-002` 直接迁入低价捡漏组，是要被消除的异常结构，不是常规形态。

**在 SKAG 结构下，否词这个动作本身不成立：**

精准活动的搜索词只可能是该关键词本身及亚马逊的近似变体（复数、拼写错误、词序）。
所以：

- 若否定词与唯一关键词**不匹配** → 什么都不会发生，动作是空转；
- 若否定词与唯一关键词**匹配** → 等于把整个活动打死，那不如直接暂停 Target，
  后者可逆、可审计、状态清晰。

因此 v3.4.0/v3.4.1 里「阻断后建议人工去后台加活动级否定」的写法，
在本账户结构下**既无意义也有害**（它还引导人工绕开系统做不可见的变更，
破坏 `10号§1.11` 的对账前提）。v3.4.2 予以删除。

**正确替代路径（按顺序尝试）：**

| # | 动作 | 适用 | 依据 |
| --- | --- | --- | --- |
| 1 | 降 Bid 观察 | 高相关但暂未转化（R1/R2） | `19号§2`、`31号§4` 相关性优先 |
| 2 | 降预算 | 花费失控但词本身值得保留 | `19号§4` |
| 3 | 暂停该 Target | 词本身不值得投，但活动结构要保留 | `30号§1` `pause_target` |
| 4 | 迁入低价捡漏组 | 词已确认无效，走淘汰通道 | `21号§4`、`32号§2` |
| 5 | `stop_campaign` | 整个活动不再需要（SKAG 下等价于词退出） | `30号§2`、`10号§1.6` |

近似变体确实跑偏（如单复数导致语义漂移）时，亚马逊 SP 无法关闭近似匹配，
所以唯一杠杆仍是上表第 3–5 项，**不是否词**。

> 广泛/词组/自动活动的否词规则不受本节影响，见 §3.3。

## 3. 广泛广告/词组广告调整规则

### 3.1 Budget（预算）调整

| 场景 | 建议动作 | 审核等级 |
|------|---------|---------|
| 预算花不出去，曝光/点击不足 | **按 `19号§4.1` 三步**：① 瓶颈判断（`23号§4.3`，组合层瓶颈则不动活动层）② `28号§5` 四档填补（回流有效词 → 提现有词 → 提词升组 → 才扩新词）③ 四档走完仍无法消化才降预算 | 不可因预算低直接开广告位加价 |
| 预算花完但 ACOS 高、搜索词质量差 | 降低预算，或把预算转移给有效词/精准承接 | 非主力广泛 AUTO_APPROVED；主力广泛 MANUAL_REVIEW |

### 3.2 Bid（基础竞价）调整

| 场景 | 建议动作 | 审核等级 |
|------|---------|---------|
| 曝光不足但词高度相关 | 小幅提高 Bid，观察1–3天 | 提 Bid 幅度建议 ≤ 15% |
| 点击多无单 或 搜索词质量差 | 按 `31号§4` 四档分支：先判相关性 → R3/R4 否词，R1/R2 降 Bid 观察；需要退出时 `stop_campaign`（**不得转低价捡漏组**，`ONT-016`） | 降 Bid **前必须先判相关性、检查是否应先否词** |

### 3.3 Search Term（搜索词）治理

广泛/词组广告**每轮调整必须读取搜索词报告**，无效/不相关/高点击无单的搜索词必须进入否词判断。

| 场景 | 建议动作 | 审核等级 |
|------|---------|---------|
| 明显不相关词（R3/R4 或 `24号§2.2` 语义冲突） | `add_negative_search_term` | 广泛/词组/自动必须执行；**无花费门槛，相关性判定即可触发** |
| 高点击无单词（点击 ≥ 10 次无单） | 按 `31号§4` 四档：R3/R4 → 否词；R1/R2 → 降 Bid 观察；核心词或 `ONT-RUNTIME-004` 四类保护词 → **禁止否词**，仅降 Bid/预算 | 点击 ≥10 预警；≥20 强优化（与 `19号§8` 一致） |
| 有订单 + 有 CVR + 有词根价值 | 提取为 Exact 精准广告或 Long-tail 承接 | 提词后原广泛保留测词功能 |

### 3.4 Placement（广告位）— 广泛广告禁区

| 规则 | 执行 |
|------|------|
| 任何广泛/词组/自动广告场景，禁止输出广告位调整建议 | placement 字段填写 `N/A` |

## 4. 调整广告活动必须输出的字段

| 字段 | 中文说明 | 精准广告填写要求 | 广泛/词组广告填写要求 |
|------|---------|--------------|-------------------|
| `action_code` / `physical_action_code` | 动作码 | 按 `30号§1` 成对输出 | 按 `30号§1` 成对输出 |
| `bottleneck_layer` | 瓶颈层级 | 预算类动作必填（`23号§4.3`） | 预算类动作必填 |
| `relevance_tier` | 相关性档位 | — | 否词/提词必填（`28号§2`） |
| `proposal_type` | 建议类型 | 固定：**调整广告活动** | 固定：**调整广告活动** |
| `object_class` | 对象类型 | `Campaign` / `KeywordTarget` / `Placement` | `Campaign` / `SearchTerm` |
| `campaign_type` | 广告活动类型 | `exact_keyword` / `product_targeting` | `broad_keyword` / `phrase_keyword` / `auto_discovery` |
| `campaign_name` | 被调整的活动名称 | 必须明确 | 必须明确 |
| `current_budget` | 当前日预算 | 必须读取 | 必须读取 |
| `proposed_budget` | 建议日预算 | 必须给具体金额 | 必须给具体金额 |
| `current_base_bid` | 当前基础竞价 | 必须读取 | 必须读取 |
| `proposed_base_bid` | 建议基础竞价 | 必须给具体数值 | 必须给具体数值 |
| `current_tos` / `proposed_tos` | 头部广告位当前值/建议值 | 必须读取；缺数据则阻断 | **N/A，禁止输出** |
| `current_pp` / `proposed_pp` | 商品页广告位当前值/建议值 | 必须读取；缺数据则阻断 | **N/A，禁止输出** |
| `current_ros` / `proposed_ros` | 其他位置广告位当前值/建议值 | 可读取并输出维持/调整 | **N/A，禁止输出** |
| `negative_search_terms` | 否词建议列表 | **禁止输出**（`ONT-015` hard_block）。若检测到高花费无关搜索词，输出 BLOCKED + `recommended_next_step`（降 Bid 观察 / 暂停该 Target / 迁入低价捡漏组，见 §2.4） | **必须读取搜索词报告并给出否词判断** |
| `extract_to_exact` | 提取为精准的词 | 可用于补充精准承接 | 跑出有效词时必须判断是否提取 |
| `evidence` | 证据链 | 花费、订单、ACOS、CVR、自然位、广告位数据 | 花费、订单、ACOS、CVR、搜索词质量、否词依据 |
| `source_report_refs` | 证据来源 | targeting_report / placement_report / organic_rank_signal | search_term_report / targeting_report |
| `ontology_validation_status` | ontology 校验状态 | passed / blocked / downgraded / review_required | passed / blocked / downgraded / review_required |
| `expected_impact` | 预期影响 | 说明订单、ACOS、自然排名、预算影响 | 说明词池质量、无效点击下降、有效词沉淀 |
| `adjustment_decision_path` | 决策路径说明 | 说明走了哪个判断分支 | 说明走了哪个判断分支 |
| `review_level` | 审核等级 | 按风险和护栏输出 | 按风险和护栏输出 |

## 5. 输出示例

### 精准广告调整示例

```yaml
proposal_type: 调整广告活动
object_class: Campaign
campaign_type: exact_keyword
campaign_name: "floral_dress_exact_B0XXXXXXXX"
current_budget: 20.0
proposed_budget: 20.0              # 预算利用率72%，未达70%+连续3天，维持
current_base_bid: 0.85
proposed_base_bid: 0.98            # ranking_opportunity触发，提价+15%
placement_adjustments:
  - placement: "头部"
    current_pct: 10
    proposed_pct: 20
    action: "上调"
    evidence: "头部7天ACOS=18%，目标25%，7天订单4单，自然位32连续上升"
  - placement: "其他"
    current_pct: 0
    proposed_pct: 0
    action: "维持"
    evidence: "无花费，无信号"
  - placement: "商品"
    current_pct: 0
    proposed_pct: 0
    action: "维持"
    evidence: "无花费，无信号"
negative_search_terms: []
extract_to_exact: []
evidence:
  - "7天花费$14.2，订单6单，ACOS=22%（目标25%）"
  - "自然排名：32位，7天上升4位"
  - "CVR=5.8%，高于品类均值"
source_report_refs:
  - targeting_report
  - placement_report
  - organic_rank_signal
ontology_validation_status: passed
expected_impact:
  orders: "预计自然排名继续上升，带动自然单增加"
  acos: "短期ACOS可能小幅上升，在目标容忍范围内"
  organic_rank: "预计排名进入Top25"
  budget: "预算无变化"
adjustment_decision_path: "精准广告→Bid：ranking_opportunity触发→提价+15%；Placement：头部有效→上调+10%"
review_level: MANUAL_REVIEW
```

### 广泛广告调整示例

```yaml
proposal_type: 调整广告活动
object_class: Campaign
campaign_type: broad_keyword
campaign_name: "casual_dress_broad_B0XXXXXXXX"
current_budget: 15.0

current_base_bid: 0.70
proposed_base_bid: 0.63            # 点击多无单，降Bid（先确认已否词）
placement_adjustments: N/A         # 广泛广告禁止输出广告位调整
negative_search_terms:
  - keyword: "wedding dress"
    reason: "明显不相关，7天点击12次，0订单"
    match_type: "精确否定"
  - keyword: "plus size evening gown"
    reason: "品类差异过大，7天点击8次，0订单"
    match_type: "精确否定"
extract_to_exact:
  - keyword: "floral casual summer dress"
    reason: "7天花费$8，3单，CVR=4.2%，有词根价值"
    suggested_action: "新增精准承接活动"
evidence:
  - "7天花费$13.8，3单，ACOS=38%（目标25%）"
  - "搜索词报告：20个搜索词，有效词3个，不相关词5个，高点击无单词4个"
  - "否词执行后预计无效点击下降30%"
source_report_refs:
  - search_term_report
  - targeting_report
ontology_validation_status: passed
expected_impact:
  orders: "否词后流量质量提升，CVR预计小幅改善"
  acos: "ACOS预计降至目标范围内"
  organic_rank: "不涉及"
  budget: "降预算$2，控制无效花费"
adjustment_decision_path: "广泛广告→否词：5个不相关词否定；Bid：点击多无单→降Bid-10%；Budget：ACOS高→降预算$2"
review_level: MANUAL_REVIEW
```
