# 样本窗口与生命周期状态规则

定义广告 Agent 如何判断“样本不足”“样本充足”“数据缺失”“拿量失败”和“到期需诊断”，避免护栏长期把无数据词或无数据活动判为白名单。

---

## 0. 核心结论

样本不足是临时保护状态，不是健康状态，也不是永久白名单。

- 样本不足只能阻断危险动作，不能阻断诊断。
- 每次输出样本不足，必须说明缺少什么样本、当前观察了多久、下一次什么时候复评。
- 达到观察窗口后仍无曝光、无点击、无花费，不能继续简单判定为样本不足，必须转入“拿量失败诊断”。
- 数据缺失、真实 0、样本不足必须区分；缺失数据不得用 0 代替。
- 若短期记忆系统未上线，必须用轻量生命周期状态字段替代，记录首次出现时间、连续观察次数和下一次复评时间。

> 本文优先级：当 `17-问题诊断与动作优先级.md` 中 `SAMPLE_INSUFFICIENT` 仅按“上线<3天 / 7天花费<$5 / 7天点击<10”判断时，必须叠加本文的观察窗口与生命周期状态，不得无限期保持样本不足。

---

## 1. 三类状态必须分开

| 状态 | 定义 | 允许结论 |
| --- | --- | --- |
| 数据缺失 `DATA_MISSING` | 应该有数据但未获取到，或数据源失败/延迟/不可确认 | 阻断依赖该数据的动作，输出数据缺失原因 |
| 真实 0 `ZERO_CONFIRMED` | 数据源正常返回，确认曝光/点击/花费/订单为 0 | 可进入拿量失败诊断，不等同于样本不足 |
| 样本不足 `SAMPLE_INSUFFICIENT` | 数据可用但观察期或点击/花费样本未达到判断门槛 | 临时保护危险动作，同时设置复评 |

禁止把 `DATA_MISSING` 当成 0；也禁止把确认真实 0 的长期活动一直归为样本不足。

---

## 2. 生命周期状态

每个可观察对象必须有生命周期状态。对象包括 Campaign、KeywordTarget、SearchTerm、AutoTarget、新增测试词。

```text
created
→ observing
→ diagnosable
→ action_required / continue_observe / blocked
→ reviewed
```

| 状态 | 含义 | Agent 处理 |
| --- | --- | --- |
| `created` | 新建或首次被 Agent 识别 | 记录首次出现时间，不做危险动作 |
| `observing` | 仍在基础观察窗口内 | 可做拿量诊断，不做否词、淘汰、大幅降预算 |
| `diagnosable` | 达到观察窗口或样本门槛 | 必须输出明确诊断，不得只写样本不足 |
| `action_required` | 已达到动作判断条件 | 输出调整、否词、预算/Bid、低价捡漏或人工审核建议 |
| `continue_observe` | 有合理继续观察原因 | 必须给出下次复评时间和继续观察原因 |
| `blocked` | 数据缺失、库存异常、规则冲突 | 输出阻断原因，不伪装为 KEEP |
| `reviewed` | 已人工审核或已执行动作 | 进入执行后复盘 |

---

## 3. 观察窗口

| 对象/场景 | 基础观察窗口 | 到期后处理 |
| --- | ---: | --- |
| 新建 Campaign | 3 天 | 未达 3 天禁止危险动作；满 3 天后进入拿量诊断 |
| 新增测试词 Campaign | 7 天看拿量，14 天看转化 | 7 天无曝光/点击要诊断 Bid、词搜索量、Listing；14 天仍无有效数据进入测试词处置 |
| 广泛广告 Search Term | 7 天为基础窗口，必要时补看 14 天 | 点击/花费达到门槛后进入否词或观察判断 |
| 低价捡漏活动 | 14 天 | 按低价捡漏复评规则判断恢复、继续捡漏或停投候选 |
| P3 长尾、淡季、季节性长尾 | 21 天 | 延长观察，但必须记录市场需求或季节证据 |
| Listing 优化中 | 7 天 | 观察期内不做强否词和淘汰；到期后重新诊断 |

观察窗口到期后，系统必须改变状态；不得连续多轮继续输出同一句“样本不足”。

---

## 4. 样本充足定义

### 4.1 Campaign 层

Campaign 满足以下任一条件，视为可诊断：

- 上线 ≥ 7 天，且近 7 天点击 ≥ 10；
- 上线 ≥ 7 天，且近 7 天花费 ≥ $5；
- 上线 ≥ 7 天，且近 7 天订单 ≥ 1；
- 上线 ≥ 14 天，即使点击/花费不足，也必须进入拿量失败诊断。

Campaign 满足以下条件，才可进入高风险动作评估：

- 上线 ≥ 14 天；
- 数据状态正常；
- 已完成 Bid、预算、搜索量、Listing、库存、Buy Box 或广告状态诊断；
- 若涉及淘汰，必须满足淘汰规则的独立门槛。

### 4.2 KeywordTarget 层

KeywordTarget 满足以下任一条件，视为可诊断：

- 近 7 天点击 ≥ 10；
- 近 7 天花费 ≥ $5；
- 近 7 天订单 ≥ 1；
- 上线 ≥ 14 天且仍无曝光/点击/花费。

若上线 ≥ 14 天仍无曝光或无花费，应转入 `TRAFFIC_ACQUISITION_FAILED`，检查 Bid、关键词搜索量、相关性、广告活动状态和预算限制。

### 4.3 Search Term 层

Search Term 满足以下任一条件，视为可诊断：

- 近 7 天点击 ≥ 10；
- 近 7 天花费达到低花费阈值；
- 近 14 天重复出现且累计点击 ≥ 10；
- 近 14 天已有订单。

Search Term 样本不足时，只能输出观察或数据原因；不得否词。

### 4.4 新增测试词

新增测试词必须按批次进入测试生命周期：

| 时间点 | 检查重点 | 允许动作 |
| --- | --- | --- |
| 第 3 天 | 是否开始拿曝光、点击、花费 | 只诊断拿量，不淘汰、不否词 |
| 第 7 天 | 是否拿到基本流量，搜索词是否相关 | 可调 Bid、预算；广泛词可进入搜索词治理 |
| 第 14 天 | 是否有订单、ACOS、有效搜索词或自然位信号 | 毕业、继续观察、降级、低价捡漏候选 |

## 5. 样本不足不是白名单

以下情况不得继续简单输出 `SAMPLE_INSUFFICIENT`：

| 场景 | 正确状态 | 必须诊断 |
| --- | --- | --- |
| 连续 2 次运行均样本不足 | `RECHECK_REQUIRED` | 下一次复评时间、缺失样本类型 |
| 上线 ≥ 7 天仍 0 曝光 | `TRAFFIC_ACQUISITION_FAILED` | Bid 是否过低、词搜索量、Listing 相关性、广告状态 |
| 上线 ≥ 7 天有曝光无点击 | `CTR_OR_RELEVANCE_WEAK` | 主图、价格、标题相关性、词意图 |
| 上线 ≥ 14 天仍无花费 | `TRAFFIC_ACQUISITION_FAILED` | Bid、预算、活动状态、搜索量、投放对象 |
| 上线 ≥ 14 天点击不足但花费存在 | `LOW_SAMPLE_BUT_DIAGNOSABLE` | CPC、点击质量、搜索词相关性 |
| 数据源连续缺失 | `DATA_PIPELINE_ISSUE` | MCP/ERP 数据链路，不做广告动作 |

样本不足保护期满后，Agent 必须输出“下一步处理”，不能只输出 KEEP。

---

## 6. 允许动作与禁止动作

| 状态 | 允许动作 | 禁止动作 |
| --- | --- | --- |
| `created` | 记录、观察 | 降 Bid、降预算、否词、淘汰 |
| `observing` | 小幅提 Bid、检查预算/状态、设置复评 | 否词、淘汰、大幅降预算 |
| `SAMPLE_INSUFFICIENT` | 继续观察、拿量诊断、设置复评 | 否词、淘汰、危险降价 |
| `TRAFFIC_ACQUISITION_FAILED` | 检查 Bid/搜索量/Listing/状态，必要时小幅提 Bid | 直接淘汰 |
| `diagnosable` | 按对应规则输出 Bid/预算/否词/提词/淘汰候选 | 伪装为健康 KEEP |
| `DATA_MISSING` | 阻断依赖数据动作、提示数据问题 | 用 0 代替缺失数据 |

---

## 7. 轻量生命周期字段

在短期记忆系统未上线前，代码必须为每个对象保存以下轻量状态字段：

```yaml
sample_lifecycle:
  object_type: Campaign | KeywordTarget | SearchTerm | AutoTarget
  object_id: string
  first_seen_at: datetime
  last_seen_at: datetime
  age_days: number
  run_count: number
  consecutive_sample_insufficient_count: number
  sample_state: created | observing | sample_insufficient | diagnosable | traffic_acquisition_failed | action_required | blocked
  data_state: NORMAL | DATA_MISSING | DATA_DELAYED | ZERO_CONFIRMED
  last_sample_reason: string
  next_review_at: datetime
  last_action_taken: string
```

没有这些字段时，Agent 每轮都会把对象当成首次判断，容易形成永久样本不足。

---

## 8. 输出要求

当 Agent 输出样本不足时，必须包含：

```yaml
sample_status:
  sample_state: SAMPLE_INSUFFICIENT
  object_age_days: number
  data_window: 3d | 7d | 14d | 21d
  missing_sample_type: impressions | clicks | spend | orders | search_term_report
  current_impressions: number | null
  current_clicks: number | null
  current_spend: number | null
  current_orders: number | null
  next_review_at: datetime
  next_diagnosis: string
  blocked_actions:
    - add_negative_search_term
    - eliminate_to_low_bid_pool
```

禁止只输出“样本不足，保持”。

---

## 9. 与否词、淘汰、新增词的关系

| 场景 | 关系 |
| --- | --- |
| 广泛广告否词 | 必须先通过本文样本充足判断，再进入 `30-广泛广告否词与搜索词治理规则.md` |
| 自动广告否词 | 必须先通过本文样本充足判断，再进入自动广告专项规则 |
| 淘汰 | 样本不足不得淘汰；观察窗口到期后仍低效，才进入 `21-淘汰广告活动规则.md` |
| 新增测试词 | 必须有 3/7/14 天复盘状态，不能无限期停留在测试中 |
| 核心词保护 | 核心词可保护危险动作，但不免除样本到期诊断 |

## 10. 原因码

| 原因码 | 含义 |
| --- | --- |
| `SAMPLE_NEW_OBJECT_OBSERVING` | 新对象仍在基础观察期 |
| `SAMPLE_CLICK_INSUFFICIENT` | 点击样本不足 |
| `SAMPLE_SPEND_INSUFFICIENT` | 花费样本不足 |
| `SAMPLE_SEARCH_TERM_MISSING` | 搜索词报告缺失 |
| `SAMPLE_NOT_WHITELIST_RECHECK` | 样本不足不是白名单，需复评 |
| `SAMPLE_TRAFFIC_ACQUISITION_FAILED` | 观察期满仍拿不到流量 |
| `SAMPLE_ZERO_CONFIRMED` | 数据源确认真实 0 |
| `SAMPLE_DATA_MISSING_BLOCKED` | 数据缺失导致动作阻断 |
| `SAMPLE_LIFECYCLE_STATE_REQUIRED` | 缺少生命周期状态，需代码补字段 |

---

## 11. 代码适配要求

研发实现必须满足：

- 区分 `DATA_MISSING`、`ZERO_CONFIRMED`、`SAMPLE_INSUFFICIENT`；
- 样本不足必须记录连续次数和下一次复评时间；
- 达到 7/14/21 天观察窗口后，不能继续输出同一类样本不足；
- `keep` 不能覆盖样本到期诊断；
- 前端必须展示样本状态、观察天数、缺失样本类型和下一次复评；
- 护栏不得把所有低点击/低花费对象永久保护为白名单；
- 没有短期记忆系统时，必须先落地本文 §7 的轻量生命周期字段。
