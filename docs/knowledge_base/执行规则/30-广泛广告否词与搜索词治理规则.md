# 广泛广告否词与搜索词治理规则

定义广告 Agent 在广泛广告中如何使用搜索词报告进行否词治理，明确否词动作的适用对象、样本标准、否定精准/否定词组选择、人工审核边界和输出字段。

---
---

## 2. 必需数据

广泛广告否词必须读取搜索词报告，至少包含：

- `campaign_id`
- `campaign_name`
- `search_term`
- `match_type` 或来源投放类型
- 近 7 天曝光、点击、花费、订单、销售额、ACOS
- 近 14 天点击、花费、订单、销售额、ACOS（用于样本补充和复核）
- 搜索词与产品的语义相关性判断
- 是否已存在否定词
- 是否已被精准活动承接
- 数据窗口、更新时间、数据状态

若搜索词报告缺失、延迟、为空且无法确认真实无数据，则否词动作必须 `BLOCKED`，不得把缺失数据当作 0。

---

## 3. 搜索词相关性分层

| 相关性等级 | 定义 | 否词原则 |
| --- | --- | --- |
| R1 高度相关 | 搜索词直接表达产品品类、款式、功能、结构、真实变体属性、人群或场景 | 不因短期 ACOS 高直接否词；先控 Bid、预算或继续观察 |
| R2 中度相关 | 搜索词与产品存在合理关联，但意图更宽或属性不完整 | 可观察；无转化且样本充分时优先否定精准 |
| R3 弱相关 | 搜索词只和大类相关，和本品款式/功能/人群不够匹配 | 样本充分且低效时可否定精准 |
| RX 明显不相关 | 品类、款式、性别、人群、场景、功能或价格意图明显不匹配 | 有点击/花费证据即可进入否定精准；同词根多次出现可进入否定词组评估 |

相关性判断依据：产品标题、五点、变体属性、产品定位标签、核心词规则、女装类目语义规则。

---

## 4. 样本窗口与样本充足定义

广泛广告否词默认使用 7 天窗口；当 7 天数据不足但该词持续出现时，补看 14 天窗口。

| 数据状态 | 定义 | 允许动作 |
| --- | --- | --- |
| 样本不足 | 点击 < 10 且花费未达到低花费阈值，或搜索词报告缺失/延迟 | 不否词；输出观察或数据缺失原因 |
| 可诊断 | 点击 ≥ 10，或花费达到低花费阈值，且数据状态正常 | 可进入相关性和转化判断 |
| 强诊断 | 点击 ≥ 20 且 0 订单，或花费达到高花费阈值且 0 订单 | 必须给出否词、降 Bid、预算收缩或继续观察的明确结论 |
| 已验证有效 | 订单 ≥ 1，或 CVR/ACOS 在当前阶段可接受范围内 | 不否词；可考虑提取精准或保留观察 |

样本不足不是白名单。连续 2 次运行仍为样本不足时，必须输出下一步诊断方向：检查 Bid、搜索量、词根、Listing 相关性、预算限制或数据链路。

## 5. 否词准入规则

只有满足以下全部基础条件，才允许输出否词建议：

1. 广告类型为 BROAD，或被业务明确归入广泛治理的 PHRASE；
2. 搜索词报告可用，且该 search_term 数据状态正常；
3. 搜索词尚未被否定；
4. 已完成搜索词与产品的语义相关性判断；
5. 已检查该词是否为核心词、季节机会词、已出单词、已精准承接词；
6. 输出具体证据：点击、花费、订单、ACOS、相关性等级、数据窗口。

以下任一情况禁止否词：

- 精准广告；
- 搜索词报告缺失或数据状态不可信；
- 样本不足；
- 核心词；
- 已出单且 ACOS 未超过当前阶段有效容忍上限；
- 高度相关但短期无单，且仍在观察窗口内；
- Listing 优化中、价格调整中或产品承接状态异常；
- 无法判断搜索词是否已被精准活动承接。

## 6. 否定精准与否定词组选择

### 6.1 默认优先否定精准 `NEGATIVE_EXACT`

广泛广告否词默认使用否定精准，避免误伤相近有效搜索词。

适用场景：

| 场景 | 动作 | 审核 |
| --- | --- | --- |
| 单个搜索词明显不相关，且有点击或花费证据 | `NEGATIVE_EXACT` | `MANUAL_REVIEW` |
| 单个搜索词点击 ≥ 10 且 0 订单，相关性 R3/RX | `NEGATIVE_EXACT` | `MANUAL_REVIEW` |
| 单个搜索词 ACOS 明显高于有效容忍上限，且非核心、非季节、非已出单价值词 | `NEGATIVE_EXACT` | `MANUAL_REVIEW` |
| 单个搜索词已被更精准活动稳定承接，原广泛中持续浪费花费 | `NEGATIVE_EXACT` | `MANUAL_REVIEW` |

### 6.2 谨慎使用否定词组 `NEGATIVE_PHRASE`

否定词组影响范围大，只有在“词根级无效”被确认时才允许建议。

适用场景：

| 场景 | 动作 | 审核 |
| --- | --- | --- |
| 同一不相关词根连续产生多个无效搜索词 | `NEGATIVE_PHRASE` | `HIGH_RISK_REVIEW` |
| 同一错误属性词根与本品事实冲突，且持续消耗 | `NEGATIVE_PHRASE` | `HIGH_RISK_REVIEW` |
| 同一非目标人群/非目标场景词根持续出现，且 14 天无订单 | `NEGATIVE_PHRASE` | `HIGH_RISK_REVIEW` |

否定词组最低样本要求：

- 至少 3 个不同 Search Term 命中同一无效词根；
- 合计点击 ≥ 20；
- 合计订单 = 0；
- 合计花费达到低花费阈值；
- 该词根不属于核心词、产品真实属性、季节机会词或已出单词根。

## 7. 否词前后的动作顺序

广泛广告搜索词质量差时，不能直接跳到淘汰。

```text
读取 Search Term Report
→ 判断数据状态与样本是否充足
→ 判断搜索词相关性
→ 判断是否已出单/核心/季节/精准承接
→ 单词无效：优先 NEGATIVE_EXACT
→ 词根级无效：评估 NEGATIVE_PHRASE，高级人工审核
→ 否词后观察 7 天
→ 仍无改善：再评估降 Bid / 降预算
→ 仍无改善：进入低价捡漏诊断
```

否词、降 Bid、降预算、转低价捡漏是独立动作，必须分别输出证据和审核状态。

---

## 8. 审核规则

| 动作 | 审核等级 |
| --- | --- |
| 不否词，仅观察 | `AUTO_APPROVED` |
| `NEGATIVE_EXACT` | `MANUAL_REVIEW` |
| `NEGATIVE_PHRASE` | `HIGH_RISK_REVIEW` |
| 品牌词、竞品词、多语言词、价格词、促销词 | 最低 `MANUAL_REVIEW` |
| 搜索词报告缺失时输出否词 | `BLOCKED` |
| 精准广告输出否词 | `BLOCKED` |
| 自动广告复用本文广泛否词规则 | `BLOCKED`；应转入自动广告专项规则 |

Agent 执行人员不得只看活动卡片直接同意否词；必须展示 search_term、match_type、点击、花费、订单、ACOS、相关性、审核等级和否词影响范围。

---

## 9. 输出字段要求

`negative_keywords` 子项必须包含：

```yaml
negative_keywords:
  - search_term: string
    negative_match_type: NEGATIVE_EXACT | NEGATIVE_PHRASE
    clicks_7d: number
    spend_7d: number
    orders_7d: number
    acos_7d: number | MAX | null
    relevance_level: R1 | R2 | R3 | RX
    reason: string
    data_window: 7d
    data_state: NORMAL | DATA_MISSING | DATA_DELAYED | SAMPLE_INSUFFICIENT
    existing_negative_check: boolean
    exact_campaign_coverage: none | exists_unstable | exists_stable
    review_level: MANUAL_REVIEW | HIGH_RISK_REVIEW | BLOCKED
```

禁止继续使用仅包含 `{keyword, clicks_7d, orders_7d, reason}` 的否词结构作为最终执行契约。

---

## 10. 代码适配要求

研发实现必须满足：

- `negative_keywords` 必须保留 `negative_match_type`，不得在落库或执行层丢失；
- 新增否词不得要求 search_term 已存在 `keyword_id`；
- `keep` 不得清空叠加型否词建议；
- `NEGATIVE_EXACT` 必须下发为亚马逊精准否定；
- `NEGATIVE_PHRASE` 必须下发为亚马逊词组否定；
- 否词 pending、MCP 提交、执行终态必须可对账；
- 同一 search_term 同一 campaign 同一 match_type 必须幂等，避免重复否词；
- 搜索词报告必须按 `campaign_id` 映射，不能只按 `campaign_name` 映射。

## 11. 复盘规则

否词执行成功后，必须创建 7 天复盘任务：

| 复盘项 | 判断 |
| --- | --- |
| 被否搜索词是否继续产生花费 | 若继续产生花费，检查否词是否执行失败或匹配类型错误 |
| 广泛广告无效点击是否下降 | 若未下降，继续分析其他无效 search_term |
| 有效词占比是否提升 | 若没有提升，说明词池质量仍差 |
| 订单是否受损 | 若订单下降明显，检查是否误否相关词 |
| ACOS 是否改善 | 若未改善，进入 Bid/预算诊断 |

误否词必须支持人工撤销，并记录误否原因码，用于后续知识库复盘。

---

## 12. 原因码

| 原因码 | 含义 |
| --- | --- |
| `NEG_EXACT_IRRELEVANT_TERM` | 单个搜索词明显不相关，建议否定精准 |
| `NEG_EXACT_HIGH_CLICK_NO_ORDER` | 单个搜索词高点击无单，建议否定精准 |
| `NEG_EXACT_HIGH_ACOS` | 单个搜索词 ACOS 明显偏高，建议否定精准 |
| `NEG_PHRASE_INVALID_ROOT` | 同一无效词根持续消耗，建议否定词组 |
| `NEG_BLOCK_EXACT_CAMPAIGN` | 精准广告禁止否词 |
| `NEG_BLOCK_AUTO_CAMPAIGN` | 自动广告不适用本文广泛否词规则，必须转入自动广告专项否词规则 |
| `NEG_BLOCK_SEARCH_TERM_MISSING` | 搜索词报告缺失，否词阻断 |
| `NEG_BLOCK_SAMPLE_INSUFFICIENT` | 样本不足，否词阻断 |
| `NEG_BLOCK_CORE_KEYWORD` | 核心词保护，否词阻断 |
| `NEG_BLOCK_RELEVANT_OBSERVING` | 高相关词仍在观察期，不否词 |
| `NEG_REVIEW_BRAND_COMPETITOR` | 品牌/竞品词需人工审核 |
