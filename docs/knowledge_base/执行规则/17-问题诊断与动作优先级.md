# 问题诊断与动作优先级（diagnosis_action_priority.yaml）

定义 Agent 如何将完整策略标签栈 + 数据诊断结论 + 记忆上下文，转化为有序的 Campaign 执行动作建议。

> **在决策链中的位置**
> `18-广告执行调整流程.md` Step 7（分层诊断）完成后，**立即进入本文**。
> 本文 §1~§7 输出有序动作列表，再交由 `15-策略约束值规则.md` 取具体约束值，生成提案。
> **提案完成后，必须进入本文 §8 执行组合预算回算与二次分配**（来源：[23-广告组合与预算分配规则.md](23-广告组合与预算分配规则.md)）。

## 0. 完整输入结构

Agent 执行本文逻辑前，必须已读取以下所有输入：

```
主输入（决定做什么）：
  ① 广告方向   push_natural_rank / expand_keywords / optimize_acos / balance_maintain
  ② 广告目的   traffic / conversion / ranking / profit
  ③ 问题类型   见 §1（由本轮数据诊断得出）

策略修正（决定幅度和保护规则）：
  ③b 经营模式  immediate_exit / controlled_clearance / limited_repair /
                stable_operation / active_promotion / profit_harvest
                （决定方向与权限，裁决优先级第 5 级，见 09号§1）
  ④ 产品定位   P0 / P1 / P2 / P3
  ⑤ 产品阶段   testing / pushing / harvesting / maintaining / liquidating
                （决定幅度；与经营模式的职责分离见 09号§3）
  ⑥ 淡旺季     淡季 / 旺季前期 / 旺季 / 旺季末期
  ⑦ 目标ACOS  定义"达标"基准线，所有 ACOS 高低判断均对比此值
  ⑧ 目标预算  定义"花够/花不够"的基准线

记忆修正（决定是否调整方向或强度）：
  ⑨ cooldown_active             该 Campaign 是否在冷却期
  ⑩ recent_effectiveness_status 上次同类动作的复盘结论
  ⑪ reverse_action_risk         本次建议是否与上次方向相反
```

## 1. 问题类型定义

### 1.1 判断顺序（命中即止）

```
① 特殊场景已激活（02号§7）→ 直接走特殊场景逻辑，跳出本文
② BLOCKED 类（数据/库存阻断）
②b 经营模式硬路径（immediate_exit）→ 确定性动作，不进入 LLM 判断（18号§0）
③ STAGE_EXPIRED_TESTING（测试期超期）
④ SAMPLE_INSUFFICIENT（样本不足）
④ CVR_WEAK（页面转化问题）
⑤ ACOS 类问题
⑥ 预算类问题
⑦ 排名类问题
⑧ 词池 / 广告位类问题
⑨ ALL_HEALTHY
```

### 1.2 问题类型表

**注意：所有 ACOS 类问题的判断阈值，必须先用 `15-策略约束值规则.md §4` 计算当前有效容忍上限，不得使用硬编码倍数。**

| 问题类型代码 | 判断条件 | 描述 |
|------------|---------|------|
| `BLOCKED_INVENTORY` | 库存天数 < 7天 | 库存不足，阻断所有增长动作 |
| `BLOCKED_DATA_MISSING` | 必需数据缺失（排名/广告位/库存） | 数据缺失，无法决策 |
| `STAGE_EXPIRED_TESTING` | `product_stage = testing` 且距阶段设置日已满 `03号§2` 的最长测试天数 | 测试期超期。冻结增长型动作 + 阶段 ACOS 加值归零（`15号§4.2`）+ 输出 MANUAL_REVIEW 要求运营确认阶段。Agent 不得自行改阶段标签 |
| `SAMPLE_INSUFFICIENT` | 活动上线 < 3天 OR 7天花费 < `03号§7.3` 样本不足门槛 OR 7天点击 < 10次 | 样本不足 |
| `CVR_WEAK` | 3天曝光 > 1500 且 CVR < 品类均值×30% | 曝光够但转化差，Listing 问题 |
| `HIGH_ACOS_NO_ORDER` | 3天ACOS > 当前有效容忍上限 且 7天订单 = 0 | 花钱无产出 |
| `HIGH_ACOS_LOW_ORDER` | 3天ACOS > 当前有效容忍上限 且 7天订单 < 目标80% | 超标且出单不足 |
| `HIGH_ACOS_WITH_ORDER` | 3天ACOS > 目标ACOS 但 ≤ 有效容忍上限，有订单 | ACOS偏高但未超容忍，有出单 |
| `BUDGET_NO_SPEND` | 7天花费 = $0 | 完全无花费 |
| `BUDGET_CANT_SPEND` | 预算利用率 < 50% 且 有花费 | 花不出去 |
| `BUDGET_EXHAUSTED` | 预算利用率 = 100% 且 ACOS ≤ 目标 ACOS | 预算不够用且效果好 |
| `RANK_OPPORTUNITY` | 自然位 ≤ 48 且 7天排名上升 ≥ 2位 且 ACOS ≤ 有效容忍上限 | 排名上升机会 |
| `RANK_DROPPING` | 自然排名连续7天下滑 ≥ 3位 | 排名在跌 |
| `KEYWORD_POOL_DIRTY` | 广泛广告：高点击无单词 > 5个 OR 不相关词 > 30% | 词池质量差（仅广泛广告） |
| `KEYWORD_POOL_EXHAUSTED` | 精准广告有效词 ≤ 3个 且 7天花费 < $10 | 精准词池枯竭 |
| `PLACEMENT_INEFFICIENT` | 精准广告某广告位：花费 > $5 且 点击 > 7次 且 订单 = 0 | 某广告位高消耗无单 |
| `ALL_HEALTHY` | 以上均不命中 | 全部正常 |

## 2. 有效容忍上限计算（使用前必算）

在判断任何 ACOS 类问题前，先按以下公式从 `15-策略约束值规则.md §4` 得出当前有效容忍上限：

```
有效容忍上限 = 目标ACOS
             + 阶段容忍加值（15号§4.2）× 经营模式系数（15号§4.1A / 09号§3.2）
             + 广告目的=ranking 时额外加值
             + 淡旺季=旺季前期/旺季 时额外加值
             + 特殊场景=promotion 时额外加值
             − 女装毛利退货修正（24号 PRC-005 命中时 −5pp）
```

> 经营模式系数：`immediate_exit` / `profit_harvest` / `limited_repair` → 0（阶段正加值归零）；
> `controlled_clearance` → 0，但 `liquidating` 阶段取 1；
> `stable_operation` / `active_promotion` → 1。

> 示例：目标ACOS=25%，pushing阶段+10%，ranking目的+10%，旺季+10%
> 有效容忍上限 = 25% + 10% + 10% + 10% = **55%**
> 当前ACOS=38% < 55%，**不触发 ACOS 类问题**，不降Bid。

## 3. 核心动作矩阵：广告方向 × 问题类型 → 有序动作

### 3.1 广告方向 = `push_natural_rank`（推自然排名）

| 问题类型 | 有序动作列表 |
|---------|------------|
| `ALL_HEALTHY` / `RANK_OPPORTUNITY` | ① 提主推词Bid ② TOS加价 ③ 确认预算不断供 |
| `HIGH_ACOS_WITH_ORDER` | ① 确认ACOS在容忍上限内（不降主推词）② 降非排名词Bid ③ 维持预算 |
| `HIGH_ACOS_LOW_ORDER` | ① 查15号§4确认容忍上限 → 容忍内：降非排名词Bid，不动主推词；超容忍：进入§4冲突裁决 |
| `HIGH_ACOS_NO_ORDER` | ① 进入§4冲突裁决（Ranking目的 vs 无出单） |
| `RANK_DROPPING` | ① 检查是否预算断供；仅当预算利用率≥90%且ACOS达标时加预算 ② 否则优先提主推词Bid ③ 必要时TOS加价恢复 |
| `BUDGET_CANT_SPEND` | ① **先执行 `19号§4.1` Step 1 瓶颈判断**（组合层瓶颈则不动活动层）② 提主推词 Bid（排名词花不出去是严重信号）③ 检查词量/曝光入口 ④ 走 `28号§5` 四档填补 ⑤ 暂不加预算，也**不降预算** |
| `BUDGET_NO_SPEND` | ① 大幅提Bid ② 确认广告位加价比例初始值（见19号）③ 检查活动状态 |
| `BUDGET_EXHAUSTED` | ① 加预算（排名任务不能断供）② 提Bid ③ TOS加价 |
| `KEYWORD_POOL_DIRTY` | ① 先否词净化 ② 否词后重新评估是否继续push_natural_rank |
| `CVR_WEAK` | ① 阻断push动作 ② 建议运营诊断Listing ③ 维持现状 |
| `SAMPLE_INSUFFICIENT` | ① 观察，不做Bid/预算大动作 |

## 4. 冲突裁决规则

当 广告方向 指向增长/推排名，但 数据问题 显示效果不佳时，用 **广告目的** 裁决。

| 广告方向 | 问题类型 | 广告目的 | 裁决结果 |
|---------|---------|---------|---------|
| push_natural_rank | HIGH_ACOS_LOW_ORDER | ranking | ACOS在容忍上限内 → 继续推排名；超上限 → 降非排名词，观察7天 |
| push_natural_rank | HIGH_ACOS_LOW_ORDER | conversion / profit | 停止执行 push_natural_rank，切换执行 optimize_acos 逻辑 → MANUAL_REVIEW |
| push_natural_rank | HIGH_ACOS_NO_ORDER | ranking | 保护主推词；降非排名词和预算；7天无改善进入淘汰评估 |
| push_natural_rank | HIGH_ACOS_NO_ORDER | conversion / profit | 停止push；执行 optimize_acos；建议目的切换 → HIGH_RISK_REVIEW |
| expand_keywords | HIGH_ACOS_NO_ORDER | traffic | 否词净化后继续扩，控制词质量 |
| expand_keywords | HIGH_ACOS_NO_ORDER | conversion / profit | 停止扩词；先治理ACOS；ACOS达标后再扩 |
| push_natural_rank | BLOCKED_INVENTORY | 任何 | BLOCKED，停止所有增长动作 |
| expand_keywords | CVR_WEAK | 任何 | BLOCKED，停止扩词，优先Listing诊断 |
| optimize_acos | RANK_OPPORTUNITY | ranking | 冲突：建议运营确认是否切换方向 → MANUAL_REVIEW |
| balance_maintain | RANK_DROPPING | 任何 | 冲突：建议运营升级为 push_natural_rank → MANUAL_REVIEW |

## 5. 策略修正：定位 + 阶段 + 淡旺季

§3和§4得出初步动作列表后，按以下规则修正幅度和保护规则。

### 5.1 产品定位修正

| 定位 | 附加约束 |
|-----|---------|
| P0 | 核心词Bid每次降幅 ≤ 5%；主力活动禁止自动淘汰；淡季保留Conversion承接和balance_maintain执行方向 |
| P1 | 正常执行，无额外约束 |
| P2 | 预算上限收紧至 `15号§2.1` 的 P2 列；TOS 加价上限按 `03号§6.2`（P2 = 15%）；超标持续7天才进淘汰评估 |
| P3 | 禁止追大词排名；TOS 加价上限按 `03号§6.2`（P3 = 10%）；目标ACOS 按 `03号§1` P3 列 |

### 5.2 产品阶段：动作幅度系数

| 产品阶段 | Bid幅度系数 | 预算幅度系数 | 特殊约束 |
|---------|-----------|-----------|---------|
| testing | ×0.5 | ×0.5 | 禁止淘汰（<14天）；禁止TOS加价；禁止大幅扩词 |
| pushing | ×1.2 | ×1.2 | 允许TOS加价；允许大幅加预算；ACOS容忍度最高 |
| harvesting | ×1.0 | ×1.0 | 标准执行；不新增大预算活动 |
| maintaining | ×0.7 | ×0.7 | 只做微调；不做策略性大动作 |
| liquidating | ×0.8 | 上限$80 | 只允许PP加价；禁止TOS加价；禁止扩词 |

### 5.3 淡旺季：幅度系数叠加

| 淡旺季 | Bid系数 | 预算系数 |
|-------|--------|--------|
| 淡季 | ×0.8 | ×0.8 |
| 旺季前期 | ×1.1 | ×1.2 |
| 旺季 | ×1.2 | ×1.5 |
| 旺季末期 | ×0.9 | ×0.9 |

> **最终幅度 = 19号基础幅度 × 阶段系数 × 淡旺季系数**
> 示例：19号大涨=+10%，pushing×1.2，旺季×1.2 → 实际幅度=+14.4%，取整+14%
>
> **口径统一（v3.4.0，C-24）**：本节系数与 `03号§3`、`15号§2.2` **共用同一套值**。
> v3.3.0 的两套系数（幅度 淡季0.7/旺季末期0.85 vs 范围 淡季0.8/旺季末期1.0）差距过小
> （0.05–0.15），不足以支撑「有意设计」的解释，更像两次编辑未同步——原文自己也标了待确认。已统一。
>
> 用途区分仍然保留：本节系数修正**本次调整幅度**，`15号§2.2` 同一套系数用于判断**预算合理区间**。

## 6. 记忆修正

§3~§5 得出最终动作列表后，检查记忆信号，按以下规则修正输出。

| 记忆信号 | 修正规则 |
|---------|---------|

## 7. 淘汰前诊断路径（不可跳过）

§3中任何"评估淘汰"动作，必须先按以下路径执行，不得跳过直接淘汰：

```
精准广告：
  广告位花费高无单？→ 先降广告位加价，观察3天
    仍无改善？→ 降基础Bid
      仍无改善？→ 评估淘汰（按21号执行）

广泛/词组/自动广告：
  高点击无单？→ 先判相关性（31号§4）→ R3/R4 执行否词
    否词后仍无改善？→ 降Bid / 降预算
      仍无改善？→ 评估 stop_campaign（30号§2；不得进低价捡漏组，ONT-016）

商品定投广告（v3.4.0）：
  广告位花费高无单？→ 先降该广告位加价（PP 优先，ONT-010）
    仍无改善？→ 降 Target Bid
      仍无改善？→ 评估 stop_campaign（不做否词，无搜索词；不进低价捡漏组）
```

> 参见 `21-淘汰广告活动规则.md §3`

## 8. 组合预算回算与二次分配

> **优先级：** Campaign 动作提案生成后、最终输出前，**必须执行本节**。
> 来源：[23-广告组合与预算分配规则.md](23-广告组合与预算分配规则.md) §5~§7；
> 结构化定义：[ontology/budget_groups.yaml](../ontology/budget_groups.yaml)。

组合预算回算是 Campaign 动作与父 ASIN 总预算之间的连接层。一个父 ASIN 下可能有数十个 Campaign，如果只在 Campaign 层调预算，可能出现每个活动单独看都合理但整体超父 ASIN 目标的情况。

### 8.1 预算归类（先归类，后回算）

在本轮所有 Campaign 调整动作确定后，先将每个涉及的 Campaign 归入其所属组合：

| 判定条件 | 归属组合 |
| --- | --- |
| campaign_type ∈ [broad_keyword, phrase_keyword, auto_discovery] | auto_broad_group |
| campaign_type = exact_keyword 且为多关键词活动 | low_bid_retention_group |
| 单关键词 exact 命中 `eliminate_to_low_bid_pool` | low_bid_retention_group |
| 单关键词 exact 连续3个完整站点自然日每日花费均大于配置门槛，且3日汇总ACOS低于目标ACOS | exact_core_group |
| 单关键词 exact 未通过上述验证 | exact_testing_group |

> 归类优先级：广泛流硬路由 > 多关键词精准低价捡漏 > 单关键词精准退出 > 单关键词精准三日验证。预算金额不决定组合身份。

### 8.2 计算组合预算变化

**Step 1 — Campaign 层：**

```
campaign_budget_delta = proposed_daily_budget - current_daily_budget
```

**Step 2 — 组合层（排除低价捡漏组）：**

```
group_requested_delta = sum(campaign_budget_delta of campaigns in group,
                            exclude campaigns moved_to low_bid_retention_group)
```

**Step 3 — 淘汰释放（活动层）：**

```
eliminated_campaign_release = sum(current_daily_budget - 1
                                  for campaigns moved_to low_bid_retention_group)
```

> 释放预算来自 Campaign 活动层（活动预算从原值降到 $1），不以 low_bid_retention_group 组合预算作为释放来源（GROUP-BUDGET-003）。

**Step 4 — 父 ASIN 层净变化：**

```
requested_increase = sum(positive group_requested_delta)
released_budget = eliminated_campaign_release + other_campaign_budget_decrease
net_required_increase = requested_increase - released_budget
```

> `other_campaign_budget_decrease` 仅包含仍留在原组合内的降预算活动，不包含本轮转入 low_bid_retention_group 的活动（避免重复计算）。

### 8.3 二次分配

**先判断是否充足：**

```
available_reallocation_budget = released_budget + parent_allowed_net_increase

if available_reallocation_budget >= requested_increase:
  → 预算充足，各组合按 requested_delta 全额执行，不压缩
```

**预算不足时：**

当 `available_reallocation_budget < requested_increase` 时，按以下场景选择分配方式：

| 场景 | 分配方式 | 说明 |
| --- | --- | --- |
| 普通重分配 | 按 `requested_delta` 占比分配 | 数据健康、无强护栏触发 |
| 存在明确推词、修复或推进优先级 | **按经营目标和真实消耗动态分配** | 禁止固定60/20/20；推词受人工 `max_exact_push_share` 上限约束 |

**动态分配三步：**

```
Step A: 根据经营模式、广告目标、ACOS和真实利用率生成组合优先级
Step B: actual_i 不超过 requested_delta_i，且总增量不超过 available
Step C: leftover 只在仍有真实消耗能力的未满足组合间再分配；不强制分完
```

**精准主力组保护：**

当父 ASIN 预算不够分配时，精准主力组不得被精准测试组或广泛自动组挤断供：

| 精准主力组状态 | 保护强度 |
| --- | --- |
| 精准主力组为空 或 7d 花费 = $0 | GROUP-BUDGET-004 暂不生效 |
| 精准主力组 7d 花费 > $0 且 < $5 | 轻度生效：精准主力组优先保障 |
| 精准主力组 7d 花费 ≥ $5 且有出单 | 完全生效：精准主力组不得断供，精准测试组优先压缩 |

### 8.4 瓶颈判断（每次回算前必执行）

```text
如果 组合利用率 = 100% 且 活动平均利用率 < 80%：
  → 瓶颈在组合层 → 应先提升组合预算，不调单个活动

如果 活动平均利用率 = 100% 且 组合利用率 < 80%：
  → 瓶颈在活动层 → 按正常逻辑调整

如果 组合利用率 = 100% 且 活动平均利用率 ≈ 100%：
  → 瓶颈在父 ASIN 层 → 应先提升父 ASIN 总预算
```
