# 输出规范（output_schema.yaml）

定义 Agent 输出给 ERP 的数据格式。

## 0. 经营单元外壳（C01）

所有面向在售经营的提案、批准结果、动作与回执，必须携带：

```text
contract_version = amazon_ops.v2
operating_unit_id
shop_id
site_code
parent_asin
parent_seller_sku（可空，仅映射）
```

不得用裸 `asin` 作为缓存键、锁、配置主键或执行目标。身份不完整时
`result_status=IDENTITY_REQUIRED`，只允许返回候选，不允许进入广告执行。
MySQL 状态通过经营单元注册表和 `state_key` 写入，Redis/LRU、Campaign cache、
running lock 与 analysis session 均使用 `operating_unit_id`。生产副本联调完成前
共享后端仍保持默认关闭；任何情况下都不得以性能为由恢复裸 ASIN 写入。

## 一、批处理结构

Agent 每次输出一个批处理提案，包含以下字段：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| batch_id | 字符串 | 批次ID |
| generated_at | 日期时间 | 生成时间 |
| kb_version | 字符串 | 知识库版本 |
| marketplace | 字符串 | 站点 |
| category | 字符串 | 品类 |
| total_asins | 整数 | ASIN总数 |
| review_level_counts | 对象 | 各审核等级的提<br>案数量统计 |
| estimated_budget_impact | 对象 | 预算影响预估（当前总预算/提议总预算/变化金额/变化比例） |
| proposals | 数组 | 每个ASIN的提案详情 |

## 二、ASIN提案结构

每个 ASIN 的提案包含：

| 字段 | 说明 |
| --- | --- |
| parent_asin | 父ASIN编码 |
| tag_snapshot | 当前标签快照 |
| strategy_summary | 策略摘要 |
| core_strategy_tags | 核心策略标签（必填，枚举值见下方） |
| original_core_strategy_tags | SOP或触发规则原始命中的核心策略标签 |
| final_core_strategy_tags | 经护栏和冲突裁决后的最终核心策略标签 |
| strategy_preservation_status | 策略保留状态：preserved / downgraded / hard_blocked / replaced |
| strategy_preservation_reason | 保留、降级、硬阻断或替换的原因 |
| data_quality | 数据质量说明 |
| campaign_type | 广告活动类型（exact_keyword / broad_keyword / phrase_keyword / auto_discovery / product_targeting） |
| proposed_actions | 提议的动作列表 |
| blocked_actions | 被阻断的动作列表 |
| portfolio_budget_summary | 组合预算回算摘要 |
| budget_groups | 广告组合预算明细 |
| memory_update_proposal | 记忆更新建议 |

### 标签快照

包含：产品定位、产品阶段、淡旺季、广告目的、广告方向、关键词类型、特殊场景。

### 关键词相关字段

关键词类别与匹配方式必须分开输出。

| 字段名 | 类型 | 中文含义 | 枚举 |
| --- | --- | --- | --- |
| target_keyword_strategy | list[str] | 已选关键词类别 | generic / long_tail / competitor / brand / custom |
| keyword_class | str | 识别的关键词类别 | generic / long_tail / competitor / brand / custom |
| match_type | str | 匹配方式 | EXACT / BROAD / PHRASE |

字段约束：

- `target_keyword_strategy` 和 `keyword_class` 使用小写业务枚举。
- `match_type` 使用匹配方式枚举，统一大写。
- 禁止新输出 `keyword_class=broad`。
- 历史数据中的 `broad` 仅在关键词类别字段中映射为 `generic`。

示例：

```yaml
target_keyword_strategy:
  - generic
  - long_tail

keyword_class: generic
match_type: BROAD
```

### 关键词类别兼容规则

历史版本中 `broad` 曾用于表示“大词/泛词”。新版统一改为 `generic`。

| 历史值 | 新值 | 说明 |
| --- | --- | --- |
| broad | generic | 仅限关键词类别字段，不适用于 `match_type` |

适用字段：

- `target_keyword_strategy`
- `keyword_class`

不适用字段：

- `match_type`

`match_type=BROAD` 仍表示广泛匹配，不做迁移。

### 策略摘要

包含：运营状态、库存态势、核心SKU态势、退货评价态势、市场竞争态势、推荐姿态、主要原因

### 核心策略标签

枚举值：Traffic / Conversion / Ranking / Profit。凡命中的核心策略必须逐项输出，禁止仅在自然语言中描述（如"保留高效词/控ACOS"）而不写对应策略标签。

注意：“维持”不是广告目的，也不是 core_strategy_tags 的合法枚举。若策略含义是“不做大动作/平衡维持”，应在 `ad_direction=balance_maintain` 或具体动作 `balance_maintain_no_action` 中表达，不得输出维持类策略标签。

#### core_strategy_tags 校验规则

| 规则 | 内容 |
| --- | --- |
| 原始策略保留 | final_core_strategy_tags 默认必须包含 original_core_strategy_tags |
| 降级表达 | 若风险护栏触发，仅可在 downgraded_actions 中说明预算、出价、扩词、广告位或Ranking强度降低 |
| 硬阻断表达 | 仅 hard_blocked 状态允许 final_core_strategy_tags 少于 original_core_strategy_tags |
| 禁止替代表达 | 不得用"控ACOS/保留高效词/利润风控"等自然语言替代 Conversion / Ranking / Profit 等合法策略标签；不得用 Profit 替代 Conversion；不得用 Profit 替代 Traffic |
| 必填场景 | 起步期Traffic、推进期Conversion/Ranking、旺季末期Conversion/Profit承接、退货风险降级场景均须输出 original_core_strategy_tags 与 final_core_strategy_tags |

### 数据质量

包含：完整度评分、缺失必需数据列表、陈旧数据源、降级数据源

## 三、单条动作结构

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| action_id | 字符串 | 动作ID |
| idempotency_key | 字符串 | 幂等键 |
| parent_asin | 字符串 | 父ASIN |
| object_class | 字符串 | 对象类型（ParentASIN/Campaign/AdGroup/KeywordTarget/ProductTarget/AutoTarget/SearchTerm/Placement） |
| campaign_type | 字符串 | 活动类型（exact_keyword/phrase_keyword/broad_keyword/auto_discovery/product_targeting） |
| object_id | 字符串 | 对象ID |
| action_code | 字符串 | **业务动作码。枚举以 `30-动作词表与映射.md§1` 为唯一权威，本文不重复列举** |
| physical_action_code | 字符串 | **物理动作码**，与 `action_code` 成对输出，映射见 `30号§1`。ERP 按此字段写入 |
| status | 字符串 | 生命周期状态，11 态，见 `30号§4`。**Agent 只能产出 `proposed` 或 `blocked`**；其余 9 态由校验器 / ERP / 系统写入 |
| bundle_id | 字符串 | 所属 ActionBundle。复合动作（`eliminate_to_low_bid_pool` / `demote_to_exact_testing`）展开的多条动作共享同一 bundle_id，必须同批成功或同批回滚（`30号§3`） |
| current_value | 数字或字符串 | 当前值 |
| proposed_value | 数字或字符串 | 建议值 |
| change_pct | 数字 | 变化百分比 |
| budget_group_type | 字符串 | 所属预算组类型。**四组**：`exact_core_group` / `exact_testing_group` / `auto_broad_group` / `low_bid_retention_group` |
| portfolio_subtype | 字符串 | 组合内逻辑子桶，当前仅 `product_targeting`。商品定投活动 `budget_group_type=auto_broad_group` + 本字段；广告位权限与压缩顺序按子桶判定 |
| target_low_bid_retention_group | 字符串 | 转低价捡漏时的目标组名 |
| kb_params_used | 对象 | 使用的知识库参数 |
| evidence | 数组 | 证据链（指标/记忆引用/竞品引用） |
| ontology_validation_status | 字符串 | ontology 校验结果（passed/blocked/downgraded/review_required） |
| ontology_rule_refs | 数组 | 命中的 ontology 规则 |
| source_report_refs | 数组 | 使用的数据源列表 |
| portfolio_budget_summary_ref | 字符串 | 引用的组合预算回算摘要ID |
| expected_impact | 对象 | 预期影响（订单/ACOS/自然排名/预算） |
| risk_reasons | 数组 | 风险原因 |
| confidence | 数字 | 置信度（0-1） |
| risk_score | 数字 | 风险评分（0-1） |
| review_level | 字符串 | 审核等级（AUTO_APPROVED/MANUAL_REVIEW/HIGH_RISK_REVIEW/BLOCKED） |
| lookback_window | 字符串 | 本次判定使用的数据窗口：`1天` / `3天` / `7天` / `14天`（`18号§3`） |
| search_term_action | 字符串 | 仅搜索词类动作：`否词` / `观察` / `提词` / `精准测试候选`（`31号§15`） |
| relevance_tier | 字符串 | 相关性档位 `R1`/`R2`/`R3`/`R4`（`28号§2`）。否词动作必填判定依据 |
| bottleneck_layer | 字符串 | 预算类动作必填：`组合层` / `活动层` / `父ASIN层`（`23号§4.3`、`GROUP-BUDGET-007`） |
| threshold_statuses_used | 数组 | 本次用到的阈值状态。含 `needs_review` 时审核等级自动升一级（`01号`） |
| apparel_rule_refs | 数组 | 命中的女装专项条件码（`24号§7`，如 `VAR-001` / `PRC-004`） |
| ontology_validation_status | 字符串 | `passed` / `blocked` / `review_required`。**由 `OntologyValidator` 代码写入**；LLM 不自述 |
| ontology_rule_refs | 数组 | 命中的 `ONT-*` / `GROUP-*` 规则编号，供审核溯源 |
| ontology_warn_only | 数组 | 分级放行期间只记录不阻断的 finding，格式 `规则号:原因码` |
| physical_action_code | 数组 | 本条动作实际执行的物理操作（30号§1 右列）。与 `action_code` 成对输出；复合动作各子动作只带自己那一个 |
| data_min_age_days | 整数 | 决策窗口最新数据的龄期（天）。不可逆动作受 ONT-022 成熟度门约束 |
| data_maturity | 数值 | 窗口平均归因成熟度 0–1（`attribution_maturity.corrected_window`） |
| acos_corrected | 数值 | 归因校正后 ACOS。**与 acos_raw 并排输出**，判定一律用 corrected；0 销售未成熟时为 null =「证据不足」 |
| decision_log_id | 字符串 | 决策日志行 ID（`ad_decision_log.decision_id`，全部动作必填，BLOCKED 动作也记） |

### 字段分层规则

以下字段属**提案级**（写在 §二 ASIN 提案结构的 `tag_snapshot` 里），**不重复写进单条动作**：

| 提案级字段 | 说明 |
| --- | --- |
| `product_position` | 产品定位 P0/P1/P2/P3 |
| `product_stage` | 产品阶段 |
| `operating_mode` | 经营模式（`02号§13`） |
| `season_stage` | 淡旺季阶段 |
| `target_acos` / `parent_target_daily_budget` | 人工录入的经营参数 |
| `target_cpa` | 目标 CPA（`14号§20`），由平均订单金额 × 目标 ACOS 计算 |

混层会让 ERP 侧字段映射出错（同一值在提案级与动作级各存一份，更新时必然漂移）。

## 四、阻断动作结构

| 字段 | 说明 |
| --- | --- |
| parent_asin | 父ASIN |
| blocked_action_type | 被阻断的动作类型 |
| reason_code | 原因码。常用：`ACTION_NOT_REGISTERED` / `ACTION_CODE_MISMATCH` / `ACTION_SCOPE_INVALID`（`30号§7`）、`KEYWORD_NOT_IN_INPUT` / `WORD_ROOT_FABRICATED`（`25号§4.2`）、`LIQUIDATING_NO_EXPANSION`（`25号§6`）、`PLACEMENT_DATA_MISSING`、`RELEVANCE_TOO_LOW`、`SHRINK_ROOT_CAUSE_NOT_KEYWORD` |
| evidence | 证据 |
| recommended_next_step | 建议下一步操作。**所有 BLOCKED 动作必填**——硬阻断只 block 不给替代路径时，运营看到空动作无从处理 |
| ontology_rule_refs | 命中的 ontology 规则编号（`ONT-*` / `GROUP-*`），由 `OntologyValidator` 写入 |

## 六、Ontology 补充引用

> 本文件的输出字段要求与 [20-亚马逊广告ontology补充](20-亚马逊广告ontology补充.md) 对齐：
> - **§3 Sponsored Products 广告对象 Ontology**：定义了 `object_class` 的合法枚举（ParentASIN / Campaign / AdGroup / KeywordTarget / ProductTarget / AutoTarget / SearchTerm / Placement），输出时每条动作必须包含 `object_class`
> - **§7 动作合法性 Ontology**：定义了 `action_code` 与 `object_class` 的合法映射，输出时 `action_type` 必须与 `object_class` 匹配；同时输出须包含 `ontology_validation_status`、`ontology_rule_refs`、`source_report_refs`
>
> 详见 [20-亚马逊广告ontology补充 §11 建议新增输出字段](20-亚马逊广告ontology补充.md#11-建议新增输出字段)。
