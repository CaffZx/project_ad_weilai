# 冲突裁决规则（conflict_rules.yaml）

当多个规则或场景产生冲突时，按优先级裁决。

## 1. 裁决优先级顺序（高→低）

| 级 | 维度 | 说明 |
| :-: | --- | --- |
| 1 | 特殊场景 | `02号§7`：促销 / 库存不足 / 差评 / 页面优化 / 紧急清仓 |
| 2 | 硬安全护栏 | `10号§1`：不直接执行、缺必需数据、幅度绝对上限、禁止无限预算、对象级非法动作 |
| 3 | 库存与核心SKU | `03号§5`、`24号§3` |
| 4 | 退货与评价风险 | `03号§5`、`10号§7`、`24号§6` |
| **5** | **经营模式** | `02号§13`：六模式。决定**方向与权限** |
| 6 | 产品阶段 | `02号§2`：五阶段。决定**幅度** |
| 7 | 淡旺季 | `02号§3` |
| 8 | 广告目的 | `02号§4` |
| 9 | 市场竞争态势 | `02号§10`、`08号` |
| 10 | 广告方向 | `02号§6` |
| 11 | 产品定位 | `02号§1` |

### 1.1 为什么经营模式插在第 5 级，而不是置顶

**插在产品阶段之前**：经营模式是人工录入的经营**意图**，产品阶段是**客观状态**。
意图应能覆盖状态——「这个品阶段上还在 pushing，但我决定立即退出」必须能表达，
反过来（客观阶段覆盖老板的决定）没有意义。

**但不置顶**：若经营模式置顶，`controlled_clearance` 或 `active_promotion` 就能覆盖
第 2–4 级的硬安全护栏、库存阻断和退货评价风控——例如在库存仅剩 3 天时仍然加预算放量。
这是危险的。**安全永远优先于经营意图。**

`immediate_exit` 是唯一的例外，但它不依赖裁决链：其确定性硬路径在代码中前置执行
（`campaign.py` 的 `_build_immediate_exit_adjustments()`），且它需要的动作本来就是收缩，
不会与安全护栏产生冲突。

### 1.2 P0 定位临时优先级提升（保留）

当产品定位 = P0 且场景为淡季 / 旺季末期 / 核心词维护时，产品定位优先级临时上调至
**第 4.5 级**（退货与评价风险之后、经营模式之前），详见 §规则 8「P0定位优先例外」。
此时 P0 核心维护策略不得被普通风控规则删除，仅硬阻断场景例外。

## 2. 三种冲突处理类型

| 类型 | 含义 |
| --- | --- |
| hard_block（硬阻断） | 直接阻断动作，输出BLOCKED或移出可执行提案 |
| modifier（修正） | 允许动作但修正幅度、系数或审核等级 |
| review_escalation（审核升级） | 允许提案但提高审核等级 |

## 3. 经营模式与产品阶段的职责分离通则

> 这一节替代了「六模式 × 五阶段 = 30 格仲裁表」。30 格里有 29 格是可确定性推导的，
> 不需要枚举，也就不存在「规则未覆盖的长尾格」。

### 3.1 职责分离

| | 经营模式决定 | 产品阶段决定 |
| --- | --- | --- |
| 内容 | **方向与权限**：允许哪些动作、是否允许新建活动、预算优先给哪个组合 | **幅度**：Bid 幅度系数、预算幅度系数、ACOS 容忍加值 |
| 权威表 | 本文 §4 | `15号§1.2`（Bid 系数）、`15号§2`（预算区间）、`15号§4.2`（ACOS 阶段加值）、`17号§5.2`（幅度系数） |

两者不争夺同一个决定权，因此绝大多数组合可直接叠加：
**先按经营模式确定允许的动作集合，再按产品阶段确定这些动作的幅度。**

### 3.2 唯一真冲突：ACOS 容忍加值

冲突只发生在一处——**经营模式想收缩，而产品阶段给了正的 ACOS 容忍加值**。
消解规则按模式分四类：

| 经营模式 | 对 `15号§4.2` 阶段正加值的处理 | 理由 |
| --- | --- | --- |
| `immediate_exit` | **归零** | 要退出，不接受更差的 ACOS |
| `profit_harvest` | **归零** | 以利润为第一目标 |
| `limited_repair` | **归零** | `runtime_contract` 已定义其边界为 `human_target_acos_and_parent_budget`，即在目标 ACOS 内修复 |
| `controlled_clearance` | **仅保留 `liquidating` 阶段的正加值**，其他阶段的正加值归零 | 清货与 `liquidating` 方向一致（都是接受更差 ACOS 以回收库存），是唯一该保留的一格 |
| `stable_operation` | 正常生效 | 中性 |
| `active_promotion` | 正常生效 | 扩张 |

**实现形式**：`15号§4.1` 的有效容忍上限公式中，阶段加值前乘一个由经营模式决定的 0/1 系数。

```text
有效容忍上限 = 目标ACOS
             + 阶段加值 × mode_stage_coefficient   ← 本节决定这个系数
             + 广告目的加值（ranking 时）
             + 淡旺季加值（旺季前期/旺季时）
             + 特殊场景加值（promotion 时）
             − 女装毛利退货修正（24号 PRC-005 命中时 −5pp）
```

> 注意：只归零**正**加值。`15号§4.2` 中 `maintaining` 的加值本身是 `+0%`，不受影响。

## 4. 六个经营模式的权限表

| 经营模式 | 广告权限 | 允许动作 | 禁止动作 | 预算倾向 | 允许新建活动 |
| --- | --- | --- | --- | --- | :-: |
| `immediate_exit` | `STOP` | 精准 → `eliminate_to_low_bid_pool`；广泛/词组/自动/商品定投 → `stop_campaign` | 全部其他动作。不进入 LLM 判断 | 不分配 | ❌ |
| `controlled_clearance` | `CLEARANCE_ONLY` | 降 Bid、降预算、否词、`stop_campaign`、PP 加价（`15号§3.1` liquidating 行） | 加预算、提 Bid、TOS 加价、大规模扩词 | 优先保有订单的活动 | ❌ |
| `limited_repair` | `NORMAL` + 目标 ACOS 约束 | 否词、降 Bid、降预算、Listing 诊断、小幅调整 | 激进扩词、大规模新建、超目标 ACOS 的放量 | 在父 ASIN 预算与目标 ACOS 内 | ⚠️ 仅结构性空缺补位（`28号§3.4`） |
| `stable_operation` | `NORMAL` | 全部常规调整、低幅度扩词 | 大规模新增与扩量 | 维持现有结构比例 | ✅ 限量 |
| `active_promotion` | `NORMAL` | 全部动作，含扩词、加预算、提 Bid、提词升组 | 突破父 ASIN 预算 | 推词需求明显时优先精准主力组，受 `max_exact_push_share` 约束（`23号§7.2`） | ✅ |
| `profit_harvest` | `NORMAL` | 降本、保留高效词、否低效词、预算向精准高效词集中 | 积极扩词、探索型新建 | 优先精准主力组的高效活动 | ⚠️ 仅承接已验证词 |

**共同硬规则**：

- 经营模式由人工录入，**Agent 不得自行变更**（`02号§13`）。
- 未知经营模式值 → 输出 `flags` 并**强制 `MANUAL_REVIEW`**，不得静默降级为 `NORMAL`。
- 经营模式缺失（未录入）→ 视为 `stable_operation`，但所有预算类动作升 `MANUAL_REVIEW`。

## 5. 具体冲突规则

### 1. 库存不足 vs 增长动作（硬阻断）

| 项目 | 内容 |
| --- | --- |
| 触发 | 父ASIN库存天数<7天 且 非紧急清仓 |
| 阻断动作 | 提价、加预算、广告位加价、扩词 |
| 结果状态 | BLOCKED |

### 2. 核心SKU短缺 vs TOS加价（硬阻断）

| 项目 | 内容 |
| --- | --- |
| 触发 | 核心子SKU库存比例<70% |
| 阻断动作 | TOS加价、激进提价 |
| 回退动作 | 平衡维持、PP加价（如果适合） |

### 3. 紧急清仓 vs 库存不足（修正）

| 项目 | 内容 |
| --- | --- |
| 触发 | 同时存在 inventory_low 和 urgent_liquidation 标签 |
| 胜出方 | urgent_liquidation（紧急清仓覆盖库存不足） |
| 效果 | 暂停ACOS逻辑、需HIGH_RISK_REVIEW、禁止无限预算、Agent最大预算增幅30% |

### 4. 促销 vs 库存不足（硬阻断）

| 项目 | 内容 |
| --- | --- |
| 触发 | 同时存在 promotion 和 inventory_low |
| 胜出方 | inventory_low（库存不足覆盖促销） |
| 阻断动作 | 促销出价加成、促销预算增加 |

### 5. 冲排名 vs ACOS超标 + 排名上升（修正）

| 项目 | 内容 |
| --- | --- |
| 触发 | 广告目的=ranking + ACOS超标 + 7天排名上升≥2位 + 退货率≤20% |
| 效果 | 允许继续冲排名，但提价上限15%，审核等级=MANUAL_REVIEW，7天后跟进 |

### 6. 冲排名 vs ACOS超标 + 排名不动（修正）

| 项目 | 内容 |
| --- | --- |
| 触发 | 广告目的=ranking + ACOS超标 + 排名无变化或下降 |
| 效果 | 允许继续冲排名，建议优化ACOS，审核等级=MANUAL_REVIEW |

### 7. 页面优化中（修正）

| 项目 | 内容 |
| --- | --- |
| 触发 | listing_optimization 标签激活 |
| 效果 | 广告目的不新增“维持”枚举；强制执行方向=balance_maintain，最大出价调整5%，阻止新增否定词，观察期7天 |

### 8. P0定位优先例外（优先级例外）

| 项目 | 内容 |
| --- | --- |
| 触发 | 产品定位=P0 + 场景=淡季/旺季末期/核心词维护 |
| 效果 | 产品定位优先级临时上调至产品阶段之前（原第10级→第5级前）；风控规则可限制预算、出价、扩词比例，但不得删除P0核心维护策略 |
| 硬阻断例外 | 不可投放、库存断货、严重差评、广告资格异常场景下，按硬阻断规则裁决，不适用本例外 |

### 9. SOP核心策略保留规则（策略级裁决）

| 项目 | 内容 |
| --- | --- |
| 触发 | SOP标准答案或上游规则已命中 core_strategy_tags |
| 裁决原则 | 普通风险规则仅可限制动作强度，不得删除SOP核心策略标签 |
| 必须保留字段 | original_core_strategy_tags / final_core_strategy_tags / downgraded_actions / blocked_actions |
| 允许替换条件 | 仅 hard_block 可替换或删除核心策略，包括不可投放、库存断货、广告资格异常、严重差评 |
| 禁止行为 | 因ACOS偏高、亏损、滞销库存、退货率偏高而直接将Traffic改写为Profit，或将推进期Conversion/Ranking改写为Traffic/Profit；保守执行应用balance_maintain方向表达 |

### 10. 推进期旺季前期策略保留规则

| 项目 | 内容 |
| --- | --- |
| 触发 | 产品阶段=pushing + 淡旺季=旺季前期/旺季 + SOP命中Conversion或Ranking |
| 必须保留的核心策略 | Conversion / Ranking；若利润风险存在，同时附加Profit；若需要保守执行，附加执行方向balance_maintain |
| 风险修正方式 | Ranking可降级为"少数强词保守推进"或"核心自然位保护词"；Conversion必须保留 |
| 禁止行为 | Traffic不得成为唯一或主要策略；Profit不得覆盖Conversion/Ranking |
| 输出要求 | final_core_strategy_tags 必须包含 SOP 核心标签；若Ranking降级，须在 downgraded_actions 中说明 |

### 11. 退货风险不覆盖推进期核心策略

| 项目 | 内容 |
| --- | --- |
| 触发 | 退货率≥30% 或 评分<3.8，同时产品阶段=pushing |
| 裁决原则 | 退货风险仅阻断激进动作，不替换推进期主策略 |
| 阻断动作 | 增长型Traffic、TOS加价、激进提价、激进Ranking |
| 必须保留动作 | 高转化Long-tail、精准词承接、核心自然位保护词、Conversion、balance_maintain方向 |
| 输出要求 | 须写明"退货风险触发：增长型动作被阻断，推进期核心策略保留并降级执行" |
