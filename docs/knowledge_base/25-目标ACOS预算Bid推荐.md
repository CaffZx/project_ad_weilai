## 1. 目标 ACOS 推荐

### 1.1 目标 ACOS 的性质

目标 ACOS 是**人工录入或确认**的经营参数，Agent 只推荐、不自行改变（`02号§维度总览`：ACOS目标
维度的 Agent 权限为「仅建议」）。它是整套知识库所有 ACOS 判断的基准线 —— `15号§4` 的有效容忍
上限就是在它之上做加法。

**目标 ACOS ≠ 有效容忍上限。** 前者是经营目标，后者是「超过多少才触发动作」的判定线。

### 1.2 推荐公式

```text
推荐目标 ACOS = 毛利率 × 广告可承担比例
```

| 项 | 说明 |
| --- | --- |
| 毛利率 | ERP `margin` 字段（扣采购、头程、FBA 费、平台佣金，不扣广告费；见 `24号§5`） |
| 广告可承担比例 | 按产品定位与阶段取值，见 §1.3 |

**女装必须做的退货修正**（`24号§1`：女装退货率天然高，名义 ACOS 达标不代表实际盈利）：

```text
退货修正后目标 ACOS = 推荐目标 ACOS × (1 − 退货率)
```

退货率取近 30 天值（`03号§5`）。数据缺失时不做修正并标 `DATA_MISSING`。

### 1.3 广告可承担比例

| 产品定位 | 产品阶段 | 广告可承担比例 | 说明 |
| --- | --- | :-: | --- |
| P0 / P1 | testing | 0.9 | 测试期以拿数据为主，允许几乎全部毛利投入 |
| P0 / P1 | pushing | 0.8 | 放量期，接受薄利换排名 |
| P0 / P1 | harvesting | 0.5 | 效率优先 |
| P0 / P1 | maintaining | 0.4 | 稳定期 |
| P2 | testing | 0.7 | 常规品测试期不宜过度投入 |
| P2 | pushing | 0.6 | |
| P2 | harvesting / maintaining | 0.4 | |
| P3 | 任意（非清仓） | 0.3 | 长尾品以利润为主，不追排名（`17号§5.1`） |
| 任意 | liquidating | 见 §1.4 | 清仓期另有口径 |

> 推荐结果必须与 `03号§1` 的定位 ACOS 上限取**较小值**：
> `min(退货修正后目标 ACOS, 03号§1 对应定位的默认 ACOS 上限)`。
> 三个值均标 `needs_review`，运营可覆写；Agent 只给推荐值与计算过程，不自动生效。

### 1.4 清仓期（`liquidating`）的目标 ACOS

清仓期的目标不是利润而是回收现金，故不走 §1.2 公式：

- 目标 ACOS 上限按 `03号§2` 的 liquidating 行取值。
- 有效容忍上限的阶段加值按 `15号§4.2` 的 liquidating 行。
- **经营模式修正**：若同时 `operating_mode ∈ {profit_harvest, immediate_exit, limited_repair}`，
  阶段正加值归零（`09号§3` 职责分离通则）；若 `operating_mode = controlled_clearance`，
  liquidating 的正加值**保留**（清货与 liquidating 方向一致，是唯一保留的一格）。
- 禁止无限预算（`10号§1.7`），即使紧急清仓。

## 2. 幅度上限（跨文件共享口径）

> `28号§5` 第 2 档「提现有有效词的 bid/预算，幅度 ≤25号§2」引用本节。

本节不定义基础幅度（在 `19号§3/§4`），只定义**单轮与单日的上限封顶**。
基础幅度经 `15号§1.2/§2` 系数修正后，还必须过本节的封顶。

| 项 | 单次上限 | 每日累计上限 | 作用域 | 来源 |
| --- | --- | --- | --- | --- |
| Bid 变化 | 按 `03号§7` 单次最大出价变化 | 按 `03号§7` 每日出价总变化上限 | 每父 ASIN 每日 | `03号§7` |
| 预算变化 | 按 `03号§7` 单次最大预算变化 | 按 `03号§7` 每日预算总变化上限 | 每父 ASIN 每日 | `03号§7` |
| 广告位加价 | 按 `03号§6` 各位置单次最大调整 | — | 每活动每位置 | `03号§6` |
| 提现有有效词（`28号§5` 第 2 档） | 与普通调整同上限，**不额外放宽** | 同上 | 每父 ASIN 每日 | 本节 |

**超限处理**（`10号§1.4/§1.5`）：

- 超出阈值上限 → 升级 `HIGH_RISK_REVIEW`
- 超出 `03号§8` 的绝对上限 → `BLOCKED`

**Bid 硬上下限**（`03号§8`，三概念分离后的口径，见 C-10）：

| 概念 | 值 | 含义 |
| --- | --- | --- |
| 全站 Bid 硬上限 | `03号§8` 的出价绝对上限 | 任何动作不得突破 |
| 全站 Bid 硬下限 | 站点最低可执行值（US = `$0.02`） | 平台限制，不是业务选择 |
| 低价捡漏组固定 Bid | `min(current_bid, 0.20)` | **业务选择**，仅适用于 `low_bid_retention_group`，不是全站下限 |

## 3. 数量上限（跨文件共享口径）

> `28号§3` 的配额公式与「以每日新词额度 15 封顶」引用本节与 `03号§7`。

| 项 | 上限 | 作用域 |
| --- | --- | --- |
| 每日最大新词数 | 按 `03号§7` | **每父 ASIN 每日**（v3.4.0 明确作用域，见 C-16） |
| 每日最大否定词数 | 按 `03号§7` | 每父 ASIN 每日 |
| 每日淘汰活动数 | 按 `03号§7`（v3.4.0 从 1 放宽至 3） | 每父 ASIN 每日 |
| 首次接入的存量清理例外 | 见 `05号§7` 的批量清理条款 | 每父 ASIN 单批 |

**额度共享规则**（`28号§0` 已声明）：`expand_keywords`、`create_campaign`、`create_ad_group`
三个动作**共享**每日新词额度，不各自计数。

**单词最低验证预算**：按 `16号§2` 的首次创建默认日预算取值。
`28号§3` 的配额公式即 `floor(可分配扩词预算 ÷ 单词最低验证预算)`。

## 4. 词保真（跨文件共享口径）

> `28号§1` 的「所有候选词必须存在于本轮输入数据，禁止 LLM 生成输入外的词（25 号§4 词保真，
> 违反→BLOCKED）」引用本节。

### 4.1 规则

Agent 输出的任何关键词、搜索词、否定词、Target，**必须能在本轮输入数据中找到出处**。
禁止 LLM 生成输入数据之外的词。

| 词类型 | 合法出处 |
| --- | --- |
| 否定词候选 | 本轮 `search_term_report` 中出现的搜索词 |
| 提词候选 | 本轮 `search_term_report` 中出现的搜索词，或其词根 |
| 扩词候选 | `28号§1` 的六个来源码之一，且该词在对应数据源中实际存在 |
| 词根 | 必须能从至少 2 个实际出现的搜索词中提取 |

### 4.2 校验与失败语义

| 情况 | 处理 |
| --- | --- |
| 词不在本轮输入数据中 | `status = blocked`，`reason_code = KEYWORD_NOT_IN_INPUT` |
| 词根无法从实际搜索词提取 | `status = blocked`，`reason_code = WORD_ROOT_FABRICATED` |
| 缺 `search_term_report` | 全部搜索词类动作阻断；扩词降级为「仅人工提案」（`28号§1`） |

由 `OntologyValidator` 在 `ActionBundle` 输出前强制校验（`ONT-018`）。

### 4.3 必须输出的溯源字段

| 字段 | 要求 |
| --- | --- |
| `keyword_source` | 来源码（`28号§1`） |
| `source_report_refs` | 该词所在的数据源（`search_term_report` / `targeting_report` 等） |
| `word_root_evidence` | 词根类动作必填：提取该词根所依据的实际搜索词列表（≥2 个） |

## 5. 父 ASIN 日预算推荐

### 5.1 性质

父 ASIN 日预算与目标 ACOS 一样是**人工录入或确认**的参数，Agent 只推荐。
它是三层预算控制的顶层（`23号§4`：ParentASIN → AdBudgetGroup → Campaign）。

**数据缺失时 Agent 不得自行假设**（`10号§3`：父 ASIN 目标预算 `DATA_UNAVAILABLE` →
所有预算动作升级 `MANUAL_REVIEW`）。

### 5.2 推荐口径

```text
推荐父 ASIN 日预算 = 近 7 天日均实际广告花费 × 定位预算系数 × 淡旺季预算系数
```

- 定位预算系数：`03号§1` 的预算优先级系数
- 淡旺季预算系数：`03号§3`（v3.4.0 已统一为一套，见 C-24）
- 结果必须 ≤ `03号§8` 的 ASIN 总日预算上限

**下限保护**：推荐值不得低于「精准主力组 7 天实际花费日均值 × 1.1」——
否则会直接造成主力组断供（`GROUP-BUDGET-004`）。

### 5.3 与 3 日验证门槛的联动（重要）

`23号§3.5` 的精准主力组 3 日验证门槛当前为**固定 $5.00**（严格大于；
`03号§10`，v3.4.3 已撤回 C-08）。父 ASIN 日预算变化**不会改变升组门槛**。

| 场景 | 影响 | 处理 |
| --- | --- | --- |
| 父 ASIN 日预算上调 | 固定 $5 门槛不变 | 仅改变可承载的活动数量；已在主力组的活动仍按 `admission_only` 处理 |
| 父 ASIN 日预算下调 | 固定 $5 门槛不变 | 预算不足时按 `23号§7` 动态压缩，不得通过降低准入门槛批量升组 |

> `admission_only` 语义（`runtime_contract.exact_main_validation`）：三日验证**只在准入时判定**，
> 已在主力组的活动不因门槛变化被自动降级；降级只走 `32号§2` 的三级回落。

## 6. 清仓期禁扩词

> `28号§0.3` 矩阵的 `liquidating` 列与 `28号§3.2` 引用「25号§6」。

**`product_stage = liquidating` 时禁止扩词**，包括 `expand_keywords`、`create_campaign`、
`create_ad_group` 三个动作。

| 情况 | 处理 |
| --- | --- |
| 清仓期触发任何扩词场景 | `status = blocked`，`reason_code = LIQUIDATING_NO_EXPANSION` |
| **唯一例外**：节日款尾货承接 | 按 `24号§4.2` `SEA-001`：允许少量 R1 词，单轮 ≤2 个，强制 `HIGH_RISK_REVIEW`，需运营显式确认 |
| 清仓期已有活动 | 可调 Bid / 预算（只降不升）、可否词、可 `stop_campaign`；**仅精准广告**可 PP 加价（按 `15号§3.1` liquidating 行）；广泛/词组/自动/商品定投 Placement 统一 `N/A` |

**与经营模式的关系**：`liquidating` 是产品阶段（客观状态），`controlled_clearance` 是经营模式
（经营意图）。两者可同时为真，也可只有其一。禁扩词由**产品阶段**触发；
经营模式 `controlled_clearance` 的额外限制见 `09号§4` 与 `31号§3`。

## 7. 输出要求

| 字段 | 要求 |
| --- | --- |
| `target_acos_recommendation` | 推荐值 + 完整计算过程（毛利率 × 可承担比例 × (1−退货率)，以及与 `03号§1` 上限取小的结果） |
| `parent_budget_recommendation` | 推荐值 + 计算过程 + 下限保护是否触发 |
| `amplitude_capped` | 幅度是否被 §2 封顶；被封顶时写出封顶前后的值 |
| `quota_calc` | 数量类动作必填：`可分配预算 ÷ 单词最低验证预算 = N`，以及封顶值 |
| `keyword_source` / `source_report_refs` / `word_root_evidence` | 按 §4.3 |
| `threshold_statuses_used` | 用到的阈值状态（`confirmed_from_sop` / `needs_review` / …），含 `needs_review` 时审核等级升一级 |
