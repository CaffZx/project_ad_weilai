## Agent 行为边界

| 规则 | 值 |
| --- | --- |
| 是否可生成提案 | ✅ 是 |
| 是否可直接写入记忆 | ❌ 否 |
| 是否可直接执行广告 | ❌ 否 |
| 执行系统 | ERP |
| 允许 Agent 产出的状态 | `proposed`（已提议）、`blocked`（已阻断）。**仅此两态** |
| 动作生命周期 | 10 态，见 `30-动作词表与映射.md§4`；`validated` 之后由校验器/ERP/系统写入，Agent 不得自行写入 |
| 是否可注册新动作 | ❌ 否。新动作必须先在 `30号§1` 注册，未注册的 action_code 由 OntologyValidator 直接 BLOCKED |

## 阈值状态定义

| 状态 | 含义 |
| --- | --- |
| confirmed_from_sop | SOP明确给出或运营口径明确，可在Agent中使用 |
| needs_review | AI根据SOP推断，必须进入阈值确认表；使用时默认提高审核等级 |
| experimental | 可用于原型试跑和离线评估，不用于自动批量确认 |
| erp_or_operator_controlled | Agent只引用和提示，不做最终裁决 |

## 审核等级定义

| 等级 | 含义 |
| --- | --- |
| AUTO_APPROVED | 低风险、小幅、证据充分，可在ERP中批量确认 |
| MANUAL_REVIEW | 需要运营人工确认 |
| HIGH_RISK_REVIEW | 高预算、高幅度、转低价捡漏、广告位大幅加价、清仓等高影响动作 |
| BLOCKED | Agent自检或硬风控不通过，不生成可执行动作 |

## 数据策略

- 缺少必需数据时不得猜测

- 输出中必须包含数据质量说明

- 输出中必须包含使用的知识库参数（含 `threshold_statuses_used`）

- 输出中必须包含证据链

- 知识库文件缺失时 **fail-fast**：`kb_loader` 拒绝启动，不得在「零业务规则」状态下运行（v3.4.0 修正；v3.3.0 是 logger.error + 缓存空串，会静默无规则运行）

- 所有候选词必须存在于本轮输入数据，禁止生成输入外的词（词保真，见 `25号§4`）
