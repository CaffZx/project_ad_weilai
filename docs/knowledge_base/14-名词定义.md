# 名词定义（glossary.yaml）

确保 Agent 对高频术语的理解与运营一致，消除歧义。

## 0. 经营单元

| 项目 | 内容 |
| --- | --- |
| 定义 | Amazon 在售经营的最小执行单元：店铺 × 站点 × 父 ASIN |
| 唯一字段 | `shop_id + site_code + parent_asin` |
| 站点规范 | 使用 `AMAZON_US / AMAZON_UK / AMAZON_DE`；短码只作输入别名。**本期仅 `AMAZON_US` 投放**，其他站点由代码 fail-fast（`00号§6`） |
| 系统 ID | `operating_unit_id`，按 `amazon_ops.v2` 统一算法派生 |
| 子体关系 | 子 ASIN 仅作为缺货、滞销调价、特殊关键词等例外作用域，仍归属父级经营单元 |
| 禁止 | 裸 ASIN 跨店铺/跨站点复用配置、缓存、override 或动作 |

## 3. 核心词

| 项目 | 内容 |
| --- | --- |
| 定义 | **见 `执行规则/29-核心词定义规则.md`（唯一权威）**。判定式：`is_core_keyword = no_semantic_conflict AND (semantic_core OR data_core)`，其中 `data_core` 需**至少命中 2 项**数据信号 |
| 字段 | `is_core_keyword`（boolean）、`core_keyword_basis`、`semantic_evidence`、`data_evidence`、`semantic_conflict_check` |
| 最大数量 | 每父 ASIN 30 个（`29号§8`） |
| 更新频率 | 每周重算；产品定位、Listing、变体可售状态或关键词数据重大变化时可提前重算（`29号§8`） |
| 注意 | 不是花费最高的词，不是订单最多的词，不是运营标注的词，也不等于 EXACT 投放方式 |

> 核心词判定以 `29号` 为唯一权威；`29号§4` 的 `data_core` 至少命中 2 项，
> 避免仅凭「花费前 30%」这一条就获得降幅保护（高花费恰恰可能是需要优化的词）。

## 15. 页面承接排查

当曝光/点击充足但CVR异常低时触发。检查项：

- 主图是否展示多场景穿搭（女装重点）

- 尺码表是否清晰（退货率关联）

- 颜色选项是否完整

- 价格/Coupon是否有竞争力

- 评价是否有尺码/面料负面反馈

- A+内容是否充分（多场景/卖点完整）
- 类目节点是否正确

- 链接是否有购物车

## 16. 低价捡漏组

| 项目 | 内容 |
| --- | --- |
| 定义 | 父 ASIN 下仅承接退出后精准活动的低预算保活组；广泛、词组、自动退出时关闭，不进入本组 |
| 固定值 | 组合预算固定 $1；Target 基础 Bid = **`min(current_bid, 0.20)`**（`current_bid` 已低于 $0.20 时保持不变，不得抬高。见 `03号§8`、`ONT-014`） |
| 注意 | 不是暂停，不是关停，不参与新增预算分配 |

## 20. 目标 CPA

| 项目 | 内容 |
| --- | --- |
| 定义 | `目标 CPA = 平均订单金额 × 目标 ACOS`。即「按当前经营目标，获取一个订单最多允许花多少广告费」 |
| 用途 | 全部「无单花费门槛」的动态基准（见 `03号§7`、`15号§5`） |
| 数据来源 | 平均订单金额 = 近 7 天广告销售额 ÷ 近 7 天广告订单数（无广告订单时退化为近 14 天）；目标 ACOS 为人工录入值 |
| 降级方案 | 平均订单金额不可用 → 标 `DATA_MISSING`，退化为 `03号§7` 的裸美元兜底值，并升一级审核等级 |
| 为什么需要 | 女装客单价跨度大（$18 T恤 到 $79 外套）。同一个裸美元无单门槛，对低客单意味着容忍近 3 个 CPA 的亏损，对高客单意味着还没跑到一个正常 CPA 就被判无效——两个方向的错都在真实发生 |

## 21. 有效容忍上限

| 项目 | 内容 |
| --- | --- |
| 定义 | 「ACOS 超过多少才触发降 Bid / 降预算 / 淘汰判断」的判定线。**不是**目标 ACOS，也**不是**目标 ACOS 的倍数 |
| 计算 | **见 `执行规则/15-策略约束值规则.md§4`（唯一权威）**：目标 ACOS + 阶段加值 + 广告目的加值 + 淡旺季加值 + 特殊场景加值，全部为**百分点加法** |
| 经营模式修正 | 收缩类模式会把阶段正加值归零，见 `09号§3` 职责分离通则 |
| 硬规则 | 全知识库禁止使用「目标 ACOS × 倍数」形式判断 ACOS 高低（`17号§1.2`） |

## 22. 精准测试组 / 精准主力组的关系

| 项目 | 内容 |
| --- | --- |
| 关键区分 | **精准测试组不是精准主力组的低预算版本，而是独立的验证阶段** |
| 身份规则 | 组合身份由验证状态决定，不由预算金额决定。加预算不能替代验证（`budget_groups.identity_rule`） |
| 降级语义 | **降级不等于淘汰**。从主力组回落到测试组是「重新验证」，不是「放弃」；恢复需重新满足 `23号§3.5` 的连续三日验证，不能用恢复预算代替 |
| 详细规则 | `执行规则/32-精准组合升降级规则.md` |

## 23. 保护型精准测试

| 项目 | 内容 |
| --- | --- |
| 定义 | `exact_testing_group` 上的一个**时限保护状态**，不是独立组合。字段：`protected_testing`（boolean）+ `protection_expires_at`（date）+ `protection_basis` |
| 适用 | P0/P1 的战略核心词，相关性达 R1 或 `semantic_core = true`，有最低数据证据，但尚未达到主力组准入条件 |
| 保护范围 | 保护期内不自动否词、不进淘汰评估、不进降级判定 |
| 保护边界 | **不豁免降 Bid / 降预算**；到期强制回归常规评估，不可由 Agent 自行续期 |
| 详细规则 | `执行规则/31-广泛自动词组调整规则.md§11` |

## 24. 瓶颈层级

| 项目 | 内容 |
| --- | --- |
| 定义 | 预算花不出去时，真正的约束在哪一层：组合层 / 活动层 / 父 ASIN 层 |
| 为什么必判 | 组合预算是当天总花费上限，一旦触达组内所有活动当日全部停止。此时单个活动可能只花了预算的 33% 就被关停，Agent 若直接看活动利用率会误判「花不出去」并去提 Bid 或扩词——而真实原因是组合预算不足 |
| 判定 | **见 `执行规则/23-广告组合与预算分配规则.md§4.3`**。每次预算类调整前必须执行 |
| 硬规则 | 组合利用率 = 100% 且活动平均利用率 < 80% 时，**不得**调整单个活动预算或 Bid，应先提升组合预算（`GROUP-BUDGET-007`） |
