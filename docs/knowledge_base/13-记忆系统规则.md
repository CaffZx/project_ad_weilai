## 0. 核心边界（必读）

| 模块 | 负责什么 | 不负责什么 |
|------|---------|-----------|
| 数仓 | 存储所有事实数据：花费、点击、ACOS、订单、排名、竞品、库存、退货 | 不存 Agent 调整目的 |
| 知识库 | 定义看到什么数据该怎么调、调整目的是什么、怎么复盘 | 不存单个 ASIN 执行历史 |
| 短期记忆 | 记录调整目的、成功标准、复盘结论 | **不记 Bid 值、预算值等数字**（数仓有） |
| ASIN 背景记忆 | 记录竞品态势、女装风险指标等持久背景信息 | 不记调整目的和复盘结论 |
| 长期记忆 | 沉淀同类场景的稳定经验及细分市场规律 | 不替代知识库规则，不直接触发执行 |
| Agent | 读取数仓 + 知识库 + 记忆，生成提案 | 不直接执行广告，不直接写记忆 |
| ERP | 审核、执行提案，写回记忆 | 不直接修改知识库 |

## 1. 完整闭环流程（12 步）

```
Step 1   ERP 从亚马逊 API 拉取昨日数据 → 写入数仓
Step 2   ERP 数据新鲜度校验通过后，触发 Agent
Step 3   Agent 从数仓读取 1天/3天/7天 事实数据
Step 4   Agent 读取知识库规则（触发规则、动作规则、阈值、护栏）
Step 5   Agent 读取短期记忆（该 ASIN 过去 7 天内所有 validity=valid 的记录）
Step 6   Agent 按需读取 ASIN 背景记忆 和 长期记忆（见 §6）
Step 7   Agent 先执行复盘（处理所有已到复盘窗口的 pending 记录）
Step 8   Agent 结合复盘结论生成新提案（含调整目的、成功标准、复盘窗口）
Step 9   Agent 输出：提案 + 记忆写入建议（memory_update_proposal）
Step 10  ERP 人工审核：approved / modified / rejected
Step 11  ERP 执行通过的提案，并将 memory_update_proposal 写入短期记忆
Step 12  到期复盘日（day_1 / day_3 / day_7），ERP 触发 Agent 复盘任务
         → 复盘结论写回短期记忆
         → day_7 达成 → 生成长期记忆候选
         → day_7 未达成 → 该条记忆标记 INVALID
```

## 2. 存储结构总览

所有记忆统一存储在 **ASIN 级文件**中，一个 ASIN 一个文件：

```
memory/asins/{parent_asin}.json
```

文件内部结构：

```json
{
  "parent_asin": "B0XXXXXXXX",
  "short_term_memory": [
    { "memory_id": "...", "campaign_id": "...", "keyword": "...", ... },
    { "memory_id": "...", "campaign_id": "...", "keyword": "...", ... }
  ],
  "asin_background": {
    "competitor_memory": { ... },
    "risk_memory": { ... }
  }
}
```

**关键说明：**
- 文件路径是 ASIN 级（一个 ASIN 一个文件）
- 文件内的每条短期记忆记录按 Campaign 区分（一词一活动，一条记录对应一个关键词的调整）
- 每条记录**不存储** Bid 值、预算值等数字，这些从数仓读取
- ASIN 背景记忆（竞品、风险）也存在同一文件内，随 ASIN 持久保存

## 3. 短期记忆

### 3.1 定义

短期记忆记录每次广告调整的**目的、成功标准、复盘进度和复盘结论**，供 Agent 下次决策前判断上次目标是否达成。

- 时间窗口：**7 天**（超过 7 天且复盘完成的记录自动归档）
- 存储位置：`memory/asins/{parent_asin}.json` → `short_term_memory[]` 数组
- 每条记录对应一个 Campaign 的一次调整，按 campaign_id 区分
- 不存储：Bid 值、预算值、花费数字（从数仓取）

### 3.2 核心作用

| 作用 | 说明 |
|------|------|
| 防止重复调整 | 同一 Campaign 7 天内已调过，不重复触发同方向动作 |
| 防止反向误调 | 上次刚提价且目的未复盘，本次要降价前必须先复盘 |
| 承接复盘任务 | 到 day_1 / day_3 / day_7 后对比数仓数据，判断目的是否达成 |
| 支持目的切换 | 7 天内不切换广告目的；反向切换需等 14 天 |
| 支持风险评分 | 连续未达成、人工驳回记录影响 risk_score |

### 3.3 存储字段

| 字段 | 说明 | 示例 |
|------|------|------|
| `memory_id` | 记忆唯一 ID | `mem_20260601_B0XXX_camp_001` |
| `created_date` | 创建日期 | `2026-06-01` |
| `expire_date` | 过期日期（创建日 + 7 天） | `2026-06-08` |
| `campaign_id` | 广告活动 ID | `camp_001` |
| `keyword` | 关键词 | `floral summer dress` |
| `product_stage` | 产品阶段 | `pushing` |
| `strategy_tag` | 广告目的 | `Ranking` |
| `adjustment_intent` | **调整目的**（核心字段） | `推动自然排名从第35位进入前20` |
| `intent_reason` | 为什么这样调，引用规则和数据 | `自然位32连续上升，ACOS在目标内，ranking_opportunity触发` |
| `action_type` | 动作类型，见 §3.3.1（不记具体数值） | `bid_up_for_ranking` |
| `kb_rule_ref` | 引用的知识库规则路径 | `04-触发规则/ranking_opportunity` |
| `success_criteria` | 成功标准（必须能用数仓复盘） | 见 §3.4 |
| `review_windows` | 复盘窗口列表 | `[day_1, day_3, day_7]` |
| `review_status` | 各窗口复盘状态 | 见 §3.5 |
| `effectiveness_status` | 最终复盘结论 | `pending / achieved / partially_achieved / not_achieved / inconclusive` |
| `fallback_plan` | 未达成时的下一步 | `回调 Bid，转 Conversion 目的` |
| `erp_review_result` | ERP 审核结果 | `approved / modified / rejected` |
| `human_override_note` | 人工修改说明 | `运营将目标排名调整为前25` |
| `validity` | 记忆是否有效 | `valid / invalid` |

#### 3.3.1 action_type 枚举值

对应 `05-动作规则.md` 定义的动作类型，`action_type` 只能取以下值：

| action_type | 说明 |
|------------|------|
| `bid_up_for_ranking` | 提价冲排名 |
| `bid_down_for_acos` | 降价控 ACOS |
| `add_negative_search_term` | 加否定词 |
| `expand_keywords` | 扩词 |
| `campaign_budget_increase` | 增加预算 |
| `campaign_budget_decrease` | 降低预算 |
| `eliminate_to_low_bid_pool` | 转低价捡漏组（不使用 pause） |
| `balance_maintain_no_action` | 维持现状，不操作 |

### 3.4 成功标准模板（按调整目的）

| 调整目的 | day_1 成功标准 | day_3 成功标准 | day_7 成功标准 |
|---------|-------------|-------------|-------------|
| Traffic 花钱起量 | 曝光 > 500，花费 > $1 | 预算利用率 ≥ 50%，有点击 | 形成有效搜索词或有初步订单 |
| Conversion 转化 | 有点击、有曝光 | CVR 不低于调前，ACOS ≤ 有效容忍上限 | 7天订单达成率 ≥ 80%，ACOS ≤ 目标 ACOS |
| Ranking 推自然位 | 预算利用率 ≥ 50%，花费和点击不下降 | ACOS ≤ 有效容忍上限，点击不下降 | 自然排名提升 ≥ 2位，或自然单占比提升 |
| Profit 控 ACOS | 花费小幅收缩或持平 | ACOS 下降，订单未大幅受损 | ACOS ≤ 目标，订单波动 ≤ 20% |
| balance_maintain 平衡维持 | 无异常波动 | 高效词稳定，预算正常消耗 | 自然位和订单稳定，无明显退化 |
| 否词优化 | 否词生效，对应搜索词消失 | 无效点击减少，CTR 改善 | ACOS 改善，有效词占比提升 |
| 转低价捡漏组 | 花费大幅收缩 | 订单未明显受损 | 流量被替代活动承接，整体订单稳定 |

### 3.5 复盘状态定义

| 状态 | 含义 |
|------|------|
| `pending` | 尚未到复盘窗口，或已到窗口但尚未复盘 |
| `achieved` | 达成全部成功标准 |
| `partially_achieved` | 部分达成，核心指标改善但未全部达标 |
| `not_achieved` | 未达成，核心指标无改善或恶化 |
| `inconclusive` | 数仓数据不足或被外部干扰（如断货、大促），无法判断 |

### 3.6 记忆有效性规则

| 情况 | validity 状态 | 说明 |
|------|-------------|------|
| 创建后未到 day_7 | `valid` | 正常有效，每日决策前必须读取 |
| day_7 结论 = `achieved` 或 `partially_achieved` | `valid → 转长期记忆候选` | 复盘完成后归档，可生成长期记忆候选 |
| day_7 结论 = `not_achieved` | `invalid` | 立即失效，执行 fallback_plan |
| day_7 结论 = `inconclusive` | `valid，延长至 day_14` | 等待额外 7 天数据再判断 |
| 超过 expire_date 未完成复盘 | `invalid` | 自动失效，ERP 日志记录 |

## 4. 复盘机制

### 4.1 复盘触发方式

复盘不依赖 Agent 自主判断，由 **ERP 定时触发**：

```
ERP 每日启动时：
  → 读取该 ASIN 文件中所有 validity=valid 的短期记忆记录
  → 找出 created_date + 1天 = 今天（day_1 到期）
  → 找出 created_date + 3天 = 今天（day_3 到期）
  → 找出 created_date + 7天 = 今天（day_7 到期）
  → 将这些记录打包成"复盘任务列表"，传给 Agent
```

### 4.2 复盘三步流程

Agent 收到复盘任务后，按以下三步执行：

```
第一步：从短期记忆读取"调整目的"和"成功标准"
        → 知道当时希望达成什么

第二步：从数仓读取对应时间段的实际数据
        → 知道实际发生了什么

第三步：对比"成功标准"和"实际数据"，得出复盘结论
        → 输出 effectiveness_status 和复盘说明
        → 更新 validity 状态
        → 如 not_achieved，触发 fallback_plan
        → fallback 动作本身也会生成新的短期记忆记录
```

### 4.3 复盘结论对下次决策的影响

| 复盘结论 | Agent 下次决策处理方式 |
|---------|-------------------|
| `achieved` | 可继续加码、转承接或进入维持阶段 |
| `partially_achieved` | 小幅微调，不做激进动作 |
| `not_achieved` | 执行 fallback_plan，不重复同方向动作 |
| `inconclusive` | 输出时提高审核等级至 MANUAL_REVIEW |
| `pending`（未到期） | 维持观察，不做反向动作 |

## 5. ASIN 背景记忆

### 5.1 定义

ASIN 背景记忆是 ASIN 维度的**持久背景信息**，存储于同一 ASIN 文件的 `asin_background` 节点下，由 ERP 定期更新，不参与复盘流程。

### 5.2 竞品记忆字段

| 字段 | 说明 |
|------|------|
| `competitor_asin_pool` | 竞品 ASIN 池 |
| `relative_price_position` | 相对价格定位（我方更贵 / 更便宜 / 持平） |
| `competition_intensity` | 竞争强度（低 / 中 / 高） |
| `traffic_opportunity` | 流量机会（弱 / 中 / 强） |
| `promo_gap` | 竞品促销差距 |
| `last_competitor_driven_actions` | 上次竞品驱动的动作 |

### 5.3 女装风险记忆字段

| 字段 | 说明 |
|------|------|
| `return_rate_history` | 退货率历史 |
| `rating_history` | 评分历史 |
| `complaint_tags` | 投诉标签 |
| `core_child_sku_stock_history` | 核心子 SKU 库存历史 |

### 5.4 调取时机

| 场景 | 需要读取 |
|------|---------|
| 竞品弱势期判断 / 竞品截流决策 | 竞品记忆 |
| 护栏检查（高退货率 / 低评分 / 核心 SKU 短缺） | 女装风险记忆 |
| 广告位加价决策（TOS / PP 阻断判断） | 女装风险记忆 |
| 新品参考同类竞品初始出价 | 竞品记忆 |

## 6. 长期记忆

### 6.1 定义

长期记忆包含两个维度：

| 维度 | 内容 | 来源 |
|------|------|------|
| **动作经验**（Campaign 级别沉淀） | 从多次短期记忆复盘结论中沉淀出的有效 / 无效动作模式 | 短期记忆复盘达标后自动候选 |
| **细分市场规律**（市场级别） | 竞争强度趋势、价格中位数趋势、促销压力时段、季节性窗口、有效广告位策略 | ERP 定期汇总更新 |

长期记忆不记录单次操作流水，不直接触发自动执行。

### 6.2 沉淀门槛（动作经验维度）

| 产品类型 | 最小复盘次数 | 达成率要求 | 置信度 |
|---------|-----------|---------|-------|
| 长周期稳定款 | 5 次 | achieved + partially ≥ 70% | 高（0.8） |
| 季节性 / 短生命周期款 | 3 次 | achieved + partially ≥ 70% | 低（0.6，标注为季节性经验） |
| 稳定无效模式 | 3 次 | not_achieved ≥ 60%（排除断货、Listing 异常、数据缺失） | 高（0.8） |

### 6.3 必须调用长期记忆的场景

| 场景 | 需要读取的维度 |
|------|-------------|
| 同类动作连续 2 次 not_achieved | 动作经验：查失败模式 |
| 新品无历史数据 | 动作经验：同类目、同价格带、同词型经验 |
| 知识库规则无法覆盖当前场景 | 动作经验，输出 MANUAL_REVIEW |
| 竞品明显变化 | 动作经验：竞品截流、价格带经验 |
| 旺季 / 大促节点决策 | 细分市场规律：季节性窗口、促销压力时段 |
| 生成风险评分 | 动作经验：历史失败率纳入 risk_score |

### 6.4 动作经验存储字段

| 字段 | 说明 |
|------|------|
| `pattern_id` | 长期经验唯一 ID |
| `scope` | 适用范围（产品阶段 / 关键词类型 / 广告位 / 细分市场） |
| `scenario_description` | 场景描述 |
| `effective_actions` | 稳定有效的动作类型 |
| `ineffective_actions` | 稳定无效或高风险的动作类型 |
| `sample_count` | 样本复盘次数 |
| `achieved_ratio` | 达成比例 |
| `confidence` | 置信度（0–1） |
| `parameter_recommendation` | 建议修改的知识库参数 |
| `rule_change_candidate` | 是否建议修改知识库（true / false） |
| `human_confirmed` | 运营是否确认（true / false） |
| `last_reviewed_at` | 最近复核日期 |

### 6.5 重点沉淀模式

| 模式 | 沉淀内容 |
|------|---------|
| 新品测试模式 | 哪些词型最快跑出曝光和订单 |
| 竞品截流模式 | 哪类竞品词适合截流，哪类长期 ACOS 失控 |
| 价格带模式 | 比竞品便宜多少时适合放量，价格无优势时哪些动作容易失败 |
| 季节趋势模式 | 旺季前期哪些动作有效，旺季末期哪些应收缩 |
| 关键词承接模式 | Broad 跑出词后多久转 Exact 成功率最高 |
| 广告位模式 | TOS / PP / RoS 在不同阶段的有效性规律 |
| 淘汰模式 | 多久无转化、经历哪些诊断步骤后转低价捡漏组最合适 |

### 6.6 长期记忆人工确认流程

```
Agent 识别到长期记忆候选
  → 输出 long_term_memory_candidate（rule_change_candidate=true）
  → ERP 在"知识库修正队列"中展示给运营
  → 运营确认：同意 / 修改后同意 / 驳回
  → 同意后：ERP 将 human_confirmed 置为 true
  → 知识库管理员修改对应知识库文件，更新 kb_version
```

## 7. Agent 决策前必须调取的内容

### 7.1 每次决策前固定调取（必须）

```
① 数仓：
   - 该 Campaign 近 1天 / 3天 / 7天 数据
   - ACOS、花费、订单、CVR、预算利用率、自然排名

② 知识库（广告调整SOP知识库—修改）：
   - 标签快照：product_stage、strategy_tag（参见 02-标签维度定义.md）
   - 触发规则和动作规则（参见 04-触发规则.md、05-动作规则.md）
   - 安全护栏和阈值参数（参见 10-安全护栏.md、03-阈值参数.md）

③ 短期记忆（memory/asins/{parent_asin}.json）：
   - 该 ASIN 下所有 validity=valid 的记录
   - 按 campaign_id 筛选当前 Campaign 的记录
   - 重点看：adjustment_intent、effectiveness_status、cooldown 状态
```

### 7.2 按条件调取（满足条件时）

| 条件 | 需要额外调取 |
|------|-----------|
| 护栏检查（退货率 / 评分 / 核心 SKU） | ASIN 背景记忆：女装风险记忆 |
| 竞品截流 / 竞品弱势期判断 | ASIN 背景记忆：竞品记忆 |
| 有 pending 复盘任务到期 | 先完成复盘，再生成新提案 |
| 准备做反向动作（上次涨现在要降） | 上次短期记忆的 effectiveness_status |
| 同类动作连续 2 次 not_achieved | 长期记忆：动作经验，查失败模式 |
| 新品上线 < 14 天 | 长期记忆：同类目动作经验 |
| 旺季 / 大促节点决策 | 长期记忆：细分市场规律 |
| 知识库规则无法覆盖 | 长期记忆：动作经验，输出 MANUAL_REVIEW |

### 7.3 决策前判断顺序

```
Step A：是否有 pending 复盘到期？
  → 有：先复盘，更新 effectiveness_status，再往下走
  → 无：直接往下走

Step B：该 Campaign 是否处于冷却期？
  （7 天内刚做过同方向动作，且复盘仍为 pending）
  → 是：维持观察，不生成新提案
  → 否：往下走

Step C：上次目的是否达成？
  → achieved：可加码或转下一阶段
  → partially_achieved：小幅微调
  → not_achieved：执行 fallback，不重复同方向
  → inconclusive：生成提案但审核等级提升至 MANUAL_REVIEW
  → 无历史记忆（新词/新活动）：正常按知识库规则决策

Step D：生成新提案，附带 memory_update_proposal
```

## 9. ERP 写回规范

ERP 是闭环中最关键的写回节点，每个状态对应必须写回的内容：

| ERP 状态 | 必须写入短期记忆 |
|---------|--------------|
| `approved` | 完整写入 memory_update_proposal 所有字段，创建待复盘任务 |
| `modified` | 写入修改后的 adjustment_intent 和 action_type，记录 human_override_note |
| `rejected` | 记录驳回原因，写入 erp_review_result=rejected，不创建复盘任务 |
| `executed` | 记录实际执行时间，execution_status=executed |
| `failed` | 记录失败原因（API 失败 / 对象不存在 / 超限），不创建复盘任务 |

## 10. 记忆对风险评分的影响

参见 `11-风险评分.md`，记忆系统对风险评分的附加影响如下：

| 记忆信号 | 对 risk_score 和 review_level 的影响 |
|---------|-----------------------------------|
| 同类动作连续 2 次 not_achieved | confidence -0.10 |
| 同类动作连续 3 次 not_achieved | 审核等级最低 MANUAL_REVIEW |
| 14 天内类似提案被 ERP 驳回 | risk_score +0.25 |
| 上次目的尚在 pending，准备做反向动作 | 审核等级最低 MANUAL_REVIEW |
| 长期记忆显示高失败率 | risk_score +0.15 |
| 长期记忆显示稳定有效（human_confirmed=true） | confidence +0.05，不突破护栏上限 |
| 新品样本不足（上线 < 3 天） | 禁止淘汰、强否词、激进降预算 |
