# 决策批次驱动的前置/执行层分离 — 改造方案

> 版本: v1.0 · 日期: 2026-06-12
> 配套: [ERP数据库改造方案.md](ERP数据库改造方案.md) · handover §8 (团队共识:前置缓存 + 执行层 T+1 落库)

## 概述

把整个看板改造成「决策批次」驱动的状态机。日常看"最新一次分析"(前置只读快照 + 执行层可改可执行)，仅在需要改配置时显式"新建分析事件"进入实时分析。

## 领域模型

**分析事件 = 决策批次 = 一行 `t_advert_agent_decision`(decision_id)**，冻结一份前置 1-4 快照 + 一份执行层结果。

### 新增加列 (t_advert_agent_decision)

| 列 | 取值 | 含义 |
|---|---|---|
| `decision_status` | `DRAFT` / `COMPLETED` / `ARCHIVED` | 进行中/已完成/失效 |
| `analysis_mode` | `REALTIME` / `SCHEDULED` | 手动/定时 |
| `is_latest` | 0/1 | 该 ASIN 最新**已完成**批次 |

### 执行权 (派生)

```
executable(batch) = batch.is_latest AND NOT exists(该 ASIN 的 DRAFT 事件)
```

### 生命周期

```
新建分析事件 → INSERT DRAFT(REALTIME) → 实时编辑写 state DB
→ 执行层跑完 write_full → DRAFT 翻 COMPLETED + is_latest=1
→ cancel-event → 删 DRAFT,旧批次执行权自动恢复
→ 定时跑 → INSERT(SCHEDULED),继承上一 COMPLETED 全份 1-4,只重算执行层
```

### 页面三态

| 场景 | 条件 | 左侧 1-4 | tab5 |
|---|---|---|---|
| A 首访/未配置 | `has_config=false` | 可编辑 | 锁定 |
| B 已配置·无 DRAFT | `in_progress=null` | 只读快照 | 可交互·可执行 |
| C 有 DRAFT | `in_progress≠null` | 可编辑 | 全锁 |

## 已定决策

1. 放弃实时事件 = 冻结可恢复: DRAFT 期间旧批次执行权暂停; cancel-event 后恢复
2. 新建事件预填 = 只继承 1-2: 战略+策略从 state DB 继承; 3-4(目标ACOS/预算+广告方向)清空重跑
3. 定时跑 = 完全冻结整份 1-4, 只重算执行层
4. 历史批次下拉 = 全部保留·标注来源: [手动]/[定时]+日期, 最新可执行置顶高亮
